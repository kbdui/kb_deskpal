# V0.1 开发计划与验收

本次用户需求优先于 `doc/` 中的长期路线图。当前只交付 Windows 可运行的 Python 3.11+ Agent 后端，不包含 Live2D、Qt、情绪与高级自主行为。

## 阶段与门槛

1. Phase 1：架构、Python src 包结构、配置、模块接口、执行日志。主 Agent 审查接口后冻结契约。
2. Phase 2：严格依次实现 LLM Adapter → Tool Framework → Task Manager → Memory Manager → Agent Core。每项通过审查及针对性验证后才能开始下一项。
3. Phase 3：Planner、应用装配、CLI 及端到端工具流程整合。
4. Phase 4：单元、接口、集成、错误路径与权限测试，最终架构复核和交付文档。

## 子 Agent 分工

| 角色 | 所有权 | 交付 |
| --- | --- | --- |
| Agent 1 架构 | 包结构、配置、接口、日志基础设施 | ARCHITECTURE.md、接口契约、架构复核 |
| Agent 6 LLM | llm 具体实现 | API Provider、离线 Demo Provider、协议映射 |
| Agent 5 工具 | tools、sandbox 具体实现 | 注册发现、参数校验、权限策略、基础工具 |
| Agent 3 任务 | tasks 具体实现 | 七种状态、合法转换、创建查询取消 |
| Agent 4 记忆 | memory 具体实现 | SQLite Memory Object 保存查询删除 |
| Agent 2 核心 | agent、planner、application、CLI | 生命周期及 Observe/Think/Plan/Act/Reflect 请求流程 |
| Agent 7 测试 | tests、测试报告 | 单元、接口、集成与失败路径测试 |

所有角色使用用户授权的 gpt-6.1-sol / high。受并发槽位限制分批调度，架构审查与测试准备可并行，核心模块实现保持上述顺序。每次交付必须报告修改文件、设计、接口、验证结果及潜在问题。共享工作区按模块所有权整合，不允许子 Agent 擅自提交或覆盖其他模块。

## 架构决策

- 包名 `deskpal`，通过 Protocol 和明确数据对象注入依赖；应用层装配具体实现。
- 同步有限步骤执行适合 V0.1，未来异步/后台调度通过接口扩展。
- 默认提供明确标识的离线演示，不声称其具有真实模型理解能力；API 模式从环境变量读取密钥，模型可配置。
- 记忆采用本地 SQLite；任务 V0.1 可先使用进程内存储。日志采用本地 JSONL。
- 工具至少提供 echo、时间查询及限定工作区的文本读取/写入。写入需要按本次请求指定工具授权。
- V0.1 Sandbox 仅为可信内置工具提供路径与权限策略；完整进程隔离、资源限制与不可信插件留待后续版本。
- 任一步缺少授权时任务返回 Waiting，并提供重新提交请求的说明；不伪装未实现的自动恢复。
- 不记录模型内部推理；密钥及敏感字段不进入日志或仓库。

## 最终验收

- 请求“帮我执行一个任务”能创建任务、规划、调用基础工具、返回结果。
- 普通回复、工具回复、非法参数、未知工具、权限不足、路径越界、API 异常都有可验证结果。
- SQLite 数据关闭后重新打开仍可查询；任务状态不能非法跳转。
- 离线完整流程无需 API 密钥与外网；API 网络协议用模拟响应验证，无密钥时不能宣称真实服务验证通过。
- 测试通过、模块无循环依赖、安装与运行方式可复现、文档说明扩展与已知限制。
- 主 Agent 审查最终差异后决定是否提交及推送；保留已有交接文档与用户数据。
