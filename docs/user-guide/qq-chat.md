# QQ 文字私聊与群聊

更新：2026-11-15。首版代码已接入；已完成核心契约及群聊节流的合成自动化验证，未做真实模型、NapCat 收发或窗口交互验证。启动方式仍是 `python -m deskpal.gui`，入口为“工具与插件 → 插件 → QQ 聊天 → 打开插件页面”。

## 何时触发思考

NapCat 向本机事件地址上报消息。签名、当前账号、授权会话、文字内容和暂停状态符合要求后，DeskPal 先保存并去重，再将工作放入现有唯一 Dispatcher，由 AgentCore 处理；HTTP 接收线程不调用模型。

- 私聊：授权范围内的新文字来信可以触发。
- 群聊：默认被 @ 或引用回复角色已记录的消息时触发；也可明确选择“全部文字消息交给模型”。未触发的同群文字可以作为后续上下文，不因此逐条调用模型。
- 自己发出的消息、重复上报、未授权会话、纯非文字消息及暂停期间的新消息不触发模型。
- 同一批积压来信会有界合并；触发只表示提供判断机会，模型可以安静结束，不必回复。

同一会话同时只安排一项处理工作。处理期间的新来信，只有实际交给下一次规划判断后才归入当前工作；若在最后一次判断后到达，则保留给后续工作，收尾查看或摘要整理不会把它误记为已处理。

群聊按群独立节流：普通消息从首条开始合并 10 秒，连续来信不反复延长；同群后续处理还要满足“普通群聊思考间隔”，可选 30 秒、1 分钟或 3 分钟，默认 1 分钟。被 @ 或引用回复角色时，先合并 2 秒，可突破普通冷却；“同群直接呼叫限频”默认开启，直接呼叫之间至少间隔 10 秒，关闭后仍保留 2 秒合并。两种群聊响应模式都遵守直接呼叫设置；私聊不套用群聊等待。

间隔限制新任务的启动，不是 API 调用次数上限；同一任务内部仍可多轮判断、调用工具及按模型决定整理。实际开始首次规划便记录冷却，即使保持安静也不退回；重启保留计时。没有新消息就不因这个间隔自动调用模型。已登记的内部复查和主动跟进仍走各自机会与授权，不由来信间隔触发。

群聊繁忙或恢复连接时，优先给模型最新一批消息和直接呼叫，不逐批补答全部旧积压。未选中的旧消息保留原文，撤下独立唤醒资格；只有实际交给规划/整理的消息才分别记录已看/已整理，不把撤下唤醒当作已经理解。尚未开始的 QQ 任务排在本机新请求之后，已经运行的任务不被强行打断。

另有两种后台机会：待确认认知到期后的内部复查，以及模型明确登记的后续跟进。轻量周期检查只入队，模型仍由 Dispatcher / AgentCore 调用。内部复查禁止发送；若希望角色主动跟进已有私聊或群聊，需在本机连接设置中开启“允许角色主动跟进已授权会话”。模型可以安排未来六天内的跟进或取消当前会话跟进，机会到达后也可以选择不发言。不会随机选择陌生人开聊、自动添加好友或入群。

同一记忆修订反复没有进展时，检查重试从 15 分钟逐步延长到 1 小时、4 小时、16 小时；这只是避免重复调用的操作退避，不删除记忆、不伪装复查已完成。仍不确定的认知由模型重新安排复查。暂停不会在恢复时批量补发旧主动跟进。失败跟进若已有发送组，不自动换任务重放；无发送时最多三次尝试。

## 何时真正发送

模型需要回复时调用 `qq_send`。工具先调用一次插件表达模型，按语义形成 1–6 条有序文字，短回复可以只有一条；每条正文最多 1,500 UTF-8 字节，整组最多 6,000 字节。不是每句话再调用一次模型。

每条实际 API 发送前重新核对账号、当前会话、预授权和暂停状态，并读取 NapCat 实际登录账号，避免协议端自行换号后继续以错误账号发送。只发给这项工作对应的私聊或群，不由模型换到其他收件人。NapCat 确认并返回消息编号后才记录为已确认，不代表对方已读。正文始终作为纯文本，不执行其中的 CQ 字符串；单独校验后可以在消息组第一条附带原生 @ 或引用回复，只允许当前群已知发言者、当前会话已记录消息，不支持 @ 全体。

已确认的前几条不会因后续失败而撤销或重发。后续发送前若发现新来信，则停止未发部分，交回模型结合实际记录继续判断。连接中断、异步结果、回执缺失，以及协议端已响应但本机落库失败，都可能进入未知状态；未知条目停止重发，需在 QQ 客户端自行核对，首版没有自动解决未知结果的页面操作。

模型直接输出普通正文不等于已发 QQ 消息；发送必须经上述工具。QQ 处理不会在桌面日常聊天再生成一条最终回复。

## NapCat 与连接配置

NapCat 继续安装和运行在项目外。本机位置是 `F:\NapCat`；本轮只读查看过目录、包信息及 HTTP 签名实现片段，没有读取账号配置、Token、聊天记录，也没有运行或修改 NapCat。包文件中的 `0.0.1` 不是本轮确认的协议端发行版本，实际兼容版本仍待联调核对。

在 NapCat 中登录专属 QQ 后，配置两个方向：

1. **HTTP 服务器**：例如监听 `127.0.0.1:3000`，启用。其 Token 对应 DeskPal 页面里的 **OneBot Token**。首版只允许本机 HTTP API，不经代理、不跟随重定向。
2. **HTTP 客户端 / Webhook 上报**：URL 填 DeskPal 页面显示的回调地址，默认 `http://127.0.0.1:8780/onebot/events`。消息格式选 `array`。你安装的 NapCat 用这里的 **Token** 生成 `X-Signature: sha1=…`，因此它应与 DeskPal 的 **事件签名密钥**相同，至少 16 个字符。它与上一步 API Token 是两项独立配置，均不是 WebUI 登录密码。

DeskPal 页面填写 API 地址、两个凭据、回调端口，以及私聊 QQ 号和群号授权范围。号码用逗号分隔；空白表示该类会话不开放，`*` 表示你明确允许该类全部来信。群聊响应方式单独选择。首次可不填绑定 QQ 号，保存启用时会读取实际登录账号和昵称；若填写了号码，必须与协议端账号一致。

点击“保存并应用”才启用；未启用时不会启动回调服务或调用 QQ 模型。页面“事件接收已开启（账号已核对）”表示启动时账号核对成功且本机接收器已开启，不是持续在线探测结果。若真实模型尚未就绪或当前为离线演示，来信保留，暂不触发模型处理。

插件自己发送的文字按 API 回执保存，不依赖自身消息上报。你直接登录账号手动发送的内容，是否进入插件记录取决于 NapCat 是否启用了自身消息上报；首版不拉取账号全部历史。更换绑定账号时也要重新核对授权范围。

## 凭据、暂停与数据

Windows 界面写入的 Token 和签名密钥保存到系统凭据库，页面不回显、不写入 QQ 数据库或备份。其他环境可通过 `DESKPAL_QQ_TOKEN`、`DESKPAL_QQ_EVENT_SECRET` 提供；已有环境变量时，界面不能覆盖为不同值。恢复备份需要重新填写凭据。请不要把 NapCat 安装目录、账号状态、实际配置或凭据提交到 Git。

暂停后不再处理新的来信或开始后续发送，原文仍可保留；已发消息不能撤销，已开始的网络请求也不保证取消。恢复不批量补发暂停期间消息。禁用连接会关闭本机接收器。切换角色会关闭旧后台和连接，插件数据跟随角色档案隔离。

实际 QQ 记录、人物与社交账号、当前会话摘要、长期认知/约定、处理工作、逐条发送回执、跟进、节流状态及经历投递账本放在档案内 `plugin_qq.sqlite3`。当前插件结构版本 3，旧版本 1/2 打开时事务升级，保留原文和回执；升级前未认领的旧群消息不自动批量补答，也不标记为已看或已整理。本轮没有实际打开或升级你的数据库。宿主另保存受管任务、执行账本、模型诊断及已接收经历。它们不伪装为桌面聊天。第 3 版备份包含插件库，仍可读取旧第 1/2 版归档；恢复到新路径后重新核对账号、授权和凭据，旧工作不自动续发。

## 同一角色的记忆与多人认知

QQ 使用主体角色卡、已学习人格、当前情绪和相关私人记忆，规划和插件表达阶段都能看到这些资料。模型可按需补查主体记忆、QQ 认知和当前会话旧原文，不逐轮拼入全部桌面记录。主体针对本机用户的理解仍属于 local:user，不冒充 QQ 联系人的资料或约定；资料是否适合透露，由模型结合当前人物、来源和群聊可见范围判断。读取主体记忆不授予修改角色卡、文件、终端或截图的权限。

QQ 人物认知与长期相处约定留在插件：同一个实际 QQ 号在私聊和群聊中关联同一人物，同名账号不合并。A 介绍或评价 B 时，同时保留实际来源、被提及对象和观点持有人。未知 B 只有名称时不猜账号。模型自行处理不同人的约定在群聊中的适用与冲突；没有好感度分数或机械优先级。

最后一次规划的 `organize_memory` 决定是否整理。一次 QQ 整理可以同时更新工作摘要、长期认知/约定，并选择分享重要经历；不是每句话再分别启动人物画像或主体模型。待确认内容有下次复查时间，可确认、更新或归档；归档提炼不删除聊天。只有实际纳入并成功提交的消息才标记已整理，旧轮暂缓材料仍可进入后续批次。格式错误有限纠错，临时模型故障有限重试，永久错误及存储故障不盲目重复模型调用。

分享采用角色第一人称，例如“我和小明一起讨论了画作，我发现自己很喜欢共同推敲创作”。原始 QQ 记录留在插件，只将必要的经历概括和真实来源交给主体。插件先同事务保存本地整理和发件箱，再经宿主接收并保存回执；失败后可重投，同一编号不产生多份材料。主体通过原有学习/复查流程决定形成经历、理解、成长缓冲或情绪，不提前宣称永久采用。页面的“已交给主体”只表示接收，不等于学习已完成。

主体遗忘经历不会删除 QQ 原消息或插件认知，插件归档理解也不级联删除主体记忆。已接收和已整理账本仍保留，避免因为遗忘自动重建同一份记忆。未来明确的新事件可以提供新的材料。

匿名消息只按单次匿名事件标识，不据此认定真实账号或同一个人物。全局暂停学习时，QQ 的摘要、认知整理和自动认知复查也暂停；正常聊天、原文与真实发送回执仍保留。图片、语音和文件只作非文字占位，不声称已理解媒体。
