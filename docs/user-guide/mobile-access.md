# 手机访问

2026-11-09 首版。手机浏览器可查看和切换会话、新建专项会话、发送消息、查看任务状态和执行记录，以及追加要求、补充信息、确认工具权限、暂停、继续或取消任务。手机与桌面使用同一个后台和当前角色的数据；不会另外启动 Agent 或复制一套数据库。设置、角色管理、模型密钥及图片管理继续在电脑操作。

## 在同一 Wi-Fi 下连接

1. 仍按原方式启动：`python -m deskpal.gui --config config.toml`，完成模型连接配置。
2. 打开「设置 → 手机访问」，连接范围选择「局域网」，保留默认端口 `8765`，公网地址留空，点击「开启 / 应用配置」。
3. 在手机浏览器打开页面显示的电脑局域网地址，例如 `http://192.168.1.10:8765`。`127.0.0.1` 只能供电脑自己访问。
4. 在电脑点击「生成配对码」，将八位数字填入手机页面。配对码五分钟有效，只能使用一次；连续输错五次需要重新生成。

Windows 防火墙若询问是否允许访问，只对需要使用的网络放行该端口。不同 Wi-Fi、访客网络的设备隔离或电脑睡眠都可能影响连接。局域网 HTTP 仅适合可信网络；通过互联网使用时应配置 HTTPS。

## 通过 Sakura FRP 连接

电脑自行安装并运行 Sakura FRP，Deskpal 不负责下载、登录或管理穿透客户端。

1. Deskpal 的连接范围选择「仅本机 / FRP」，端口例如 `8765`。
2. 在 Sakura 创建 TCP 隧道，本地地址填写 `127.0.0.1`，本地端口填写 `8765`（与 Deskpal 一致）。Deskpal 本地提供 HTTP，开启 Sakura 的「自动 HTTPS」后重启隧道，由 FRP 提供外部 HTTPS；外部访问应有有效证书。
3. 在 Deskpal 的「公网 HTTPS 地址」填写实际访问来源，例如 `https://chat.example.com:40333`，再点击「开启 / 应用配置」。用 Sakura 提供的实际完整域名和外部端口替换示例，不能带路径、账号密码、查询串或片段。本地端口 `8765` 与外部端口 `40333` 可以不同；该设置用于允许实际访问来源，不会申请域名或开启 HTTPS。
4. 在手机浏览器打开该地址，再用电脑生成的配对码登录。手机不需要安装 FRP 客户端。

若出现 Sakura 返回的「501 Not Implemented #83」，表示 HTTP 访问被穿透服务拦截。检查「自动 HTTPS」是否开启且已重启隧道，并使用 `https://完整域名:外部端口` 访问；只给网址加上 `https://` 不会自动启用 HTTPS。上述自动 HTTPS 配置已由用户实机验证可行。

代理必须保留浏览器访问的 Host。Deskpal 明确检查配置的公网 Host 和 Origin，不依据任意客户端传入的 `X-Forwarded-*` 头放宽限制。出现「访问地址未被允许」或「请求来源不匹配」时，检查公网地址、外部端口及代理 Host 设置；不要为了解决连接问题关闭身份验证。节点和域名条件以 [Sakura FRP 官方 Web 指南](https://doc.natfrp.com/app/http.html)为准，自动 HTTPS 见[官方说明](https://doc.natfrp.com/frpc/auto-https.html)。

## 聊天和任务

当前会话有进行中的工作时，输入区域会显示追加要求的目标。可以选择「新消息」发起独立请求，也可以给具体任务补充要求。任务已经收尾时，追加不会被假装采纳，输入会保留，可改发新消息。Enter 发送，Shift + Enter 换行，中文输入法选词不会触发发送。

工具权限仍使用原有计划、版本和授权检查。高风险操作需要勾选对应许可；任务计划变化后原勾选失效。暂停在后台安全边界生效，不能保证立刻停止正在执行的工具。取消也不会撤销已经完成的操作。

页面断网或刷新后会重新读取真实记录。尚未收到明确回执的操作会显示「查询 / 重试原操作」；重试沿用原命令编号，不额外创建同一条消息。放弃本地重试不会取消后台已经受理的任务。后台重启或切换角色后不会自动重发旧请求，应查看原会话确认结果，再决定是否重新提出要求。

## 设备和数据

设备登录最长保留三十天，退出登录会同时撤销当前设备凭据。电脑「手机访问」可单独撤销设备，或关闭整个入口。访问设置会保存，下次正常打开角色时恢复开启；切换角色、维护和退出过程中旧监听器关闭、旧实例请求失效。重新打开页面后连接当前角色。

设备授权存放在 Qt 提供的应用本地数据目录中的 `mobile/access.sqlite3`，与四个角色数据库分离，不包含在角色导出备份中。数据库只保存登录凭据摘要；原凭据通过 HttpOnly Cookie 保存在浏览器。手机页还会在本标签页的 sessionStorage 保存草稿和未确认命令，退出登录时清除，不把模型 API 密钥交给手机。

电脑上的 Deskpal 与 FRP 客户端需要保持运行。手机页面关闭不等于取消后台任务，重新打开后可查看结果。首版未实现手机系统推送、PWA 安装包、离线聊天或独立无桌面后台。

## 最小实机检查

- 同 Wi-Fi 配对，发送一条消息；桌面和手机都只出现一次，并能看到最终回复。
- 处理过程中追加要求，分别检查暂停、继续、确认工具权限和取消。
- 发送后切到其他手机应用，再回到页面；检查记录、输入和滚动位置。
- 在电脑撤销设备，手机随后无法继续操作；重新配对可恢复。
- 配置 FRP HTTPS 后改用移动网络，检查登录、发送与重连。

自动化仅验证合成数据下的回环 HTTP、Qt 浏览器和后台行为。具体手机浏览器、软键盘、Windows 防火墙和真实 FRP 链路需要上述实机检查。
