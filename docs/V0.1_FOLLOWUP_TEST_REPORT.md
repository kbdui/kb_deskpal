两项真实场景共最多三次请求：普通文本chat；实际模型提出echo调用→公开ToolManager验证/执行→独立`[REFLECT]`普通文本结果请求。按主Agent核对的官方Responses协议，注入传输将每次`max_output_tokens`限制为128并设`reasoning={"effort":"none"}`，不追加其他协议的thinking字段。工具请求固定只有echo且`tool_choice`指定echo；此项验证真实协议/解析/执行，不认证模型自主选择工具或一般自然语言理解。传输拒绝重定向，不复放native工具历史。

缺少门槛变量时明确skip/not run。显式启用后的HTTP错误（含401/402）、网络错误、超时、响应解析或工具调用不符合要求都fail，不用skip隐藏。pytest失败输出仅显示安全分类，`pytrace=False`省略真实响应正文、密钥和原始异常信息；不记录或打印模型推理。

同时有七项无网络策略验证：默认门槛不会读取密钥/网络；启用但缺key不联网；401/402/network/timeout模拟明确失败且错误中不出现假凭据或响应敏感标记；传输确实限制输出token、禁推理并指定唯一echo。

## dotenv配置阶段

用户改用项目`.env`后，主Agent添加python-dotenv依赖及加载规则：未指定environ时读取配置文件同目录`.env`，无配置路径则读取cwd；进程环境优先于.env，继而TOML和默认值。显式environ保持隔离；文件UTF-8解析、禁变量插值、忽略None，不修改进程环境。

测试Agent新增11项针对性配置回归，全部使用tmp_path及仅注入给config模块的fake process环境，不读取真实项目文件：

- cwd及配置父目录定位，进程>.env>TOML>默认值优先级及相对路径。
- 注入process mapping与真实全局环境中的测试标记均不被更改，不新增全局dotenv变量。
- `${TEST_SOURCE_VALUE}`在假密钥中保持字面值，不从文件或进程插值。
