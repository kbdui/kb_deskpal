# 页面与状态细则

设计日期：2026-10-25。本文为页面细则；D1–D5 实际范围见[开发记录](development-status.md)，T1 自动化结果与实机未验证边界见[测试记录](test-report.md)。设计条目本身不代表验收通过。

本文件补齐[产品设计](product-design.md)中的页面内容和恢复路径；后端契约见[技术方案](technical-plan.md)，模型、凭据、图片和工具的专用通道见[专项方案](settings-assets-and-tools.md)。

## 1. 页面布局与返回规则

主窗口保留同一套一级导航、主题和状态反馈，不用弹出多个技术管理窗口完成普通操作。导航条按“聊天 / 安排 / 记忆 / 工具插件 / 设置”排列，设置位于底部。标题栏不放模型、人格、记忆模式等配置控件。

| 页面 | 内容结构 | 进入与返回时的行为 |
| --- | --- | --- |
| 聊天 | 会话列表、当前消息、任务卡、固定输入区 | 恢复本窗口选中的会话、阅读位置和当前进程草稿 |
| 安排 | 待确认/提醒与日程/进行中/历史，目标与建议为次级区域 | 保留筛选；从任务返回聊天时定位原卡片，不创建新会话 |
| 记忆 | 搜索与筛选、记忆条目、候选审核、来源和影响详情 | 保留阅读位置；更正/遗忘后按版本刷新受影响条目 |
| 工具插件 | 搜索/分类、能力列表、说明与权限详情 | 只查询目录，不自动测试或启用任何能力 |
| 设置 | 分类索引、当前分区表单、固定保存反馈 | 返回原分区；未保存的普通表单保留为当前进程草稿 |

非聊天页隐藏会话栏并回收其布局列；窄屏同样不得保留聊天会话选择器。主窗口和小窗分别保留导航位置，共享会话、消息和任务事实。后台完成事件只更新数据、角标和提示，不强制跳页。

“返回聊天”是定位业务内容的动作；“调整人格”“换模型”“修改头像”“设置通知”是配置动作，只能由设置导航进入。错误提示可以写明设置分类名称，不在聊天中新增配置按钮。

## 2. 聊天页：普通消息优先

角色姓名与小头像位于顶部，模拟情绪最多显示简短只读状态，不使用关系分数或人格参数面板。首次空会话显示一句可编辑文案所形成的角色问候和输入提示，不自动发起模型调用；开始聊天后收起大欢迎区。

**普通聊天只显示用户消息与角色回复。** 后端为处理请求建立 Task 是内部事实，不要求把每句问候都包装为任务卡。排队或生成阶段在消息位置轻量显示状态；普通成功回复后收起过程提示。发生失败时，在对应消息处给出原因和可执行恢复动作。

任务卡用于需要审批的计划、用户要追踪的工具操作、提醒结果，以及必须说明的部分成功或不确定结果。无审批的纯查询可将可靠结果并入回复，详细步骤按需展开；涉及副作用的操作仍须保留可追溯卡片，不能被情绪化回复掩盖。所有投影关联同一后端任务，不因展示方式不同重复提交。

会话列表显示可理解的标题、最后活动时间和未读/待确认标记，不显示内部 ID。专项会话的行菜单可重命名、归档、恢复、删除；删除是内容管理，必须显示影响范围。日常聊天不提供归档和删除入口，后端也拒绝；清空记录统一放在“设置 → 记忆与隐私”，和清理范围一起展示。

历史记录分页读取，当前输入始终可见。查看早期记录时新回复不强行滚到底部；显示“有新消息”，点击后定位最新。跳转某条任务卡时可补加载其前后消息，不需一次加载整段历史。

草稿在当前进程按会话保存，两窗编辑同一会话时共享版本；发送后只清除已受理的草稿修订，不擦除后来输入。退出应用尚有草稿时说明草稿不跨重启保存，并允许返回编辑；不能把“关闭到托盘”误当作退出并清空草稿。隐私清理应清除其范围内的草稿和消息缓存。

## 3. 安排与授权

“安排”负责整理和追溯，不是用户完成聊天授权的必经页面。列表首要信息为名称、当前状态、下一次时间或最近活动、所属会话；内部编码和原始 JSON 只在技术详情。

| 区域 | 主要内容与操作 |
| --- | --- |
| 待我确认 | 原计划的完整步骤、影响对象、缺失授权；允许/取消与聊天使用同一组件 |
| 提醒与日程 | 名称、实际时刻、时区、当前状态、关联会话；到期项标记已读 |
| 进行中 | 排队、理解、执行进度；取消按钮说明只能停止尚未发生的后续工作 |
| 历史 | 完成、失败、取消、结果待核实，展示可靠结果和已产生的效果 |
| 目标与建议 | 目标名称、进度、分步计划、来源绑定；建议接受不等于执行授权 |

提醒的“已读”仅改变收件箱；修改时间、取消计时器等修改真实资源的操作仍生成可审核计划，或走既有等价授权服务。不能把关闭卡片当作取消提醒。

当审批包含长文件内容或多步骤，小窗提供“展开审核”定位主窗口原卡片并保留选择。高风险授权不预选；无法完整取得原计划时禁止确认并提供重新读取。技术失败与用户拒绝区别显示。

确认已受理后，卡片立即进入等待执行状态；轮询结果尚未更新为 Running 时也不得重新显示有效复选框。只有查询到当前进程确实仍缺授权，或明确重审，才重新建立审核控件。回执超时先核查原命令，不能将“未收到回复”当作“未执行”。

## 4. 记忆页与人格设置的分界

记忆条目展示内容、类型、来源概述、最近更新和当前可用范围，允许查看来源、更正、遗忘及审核候选。记录的“仅本地/允许云处理”在此为只读事实；用途策略、记忆模式与类别许可只能在设置中修改。

显式新增记忆的来源用途使用设置中新增输入的默认策略，创建表单仅显示该有效范围，不另放用途选择器；设置尚未读取时先等待就绪。更改默认策略不追溯改写已有记忆来源。

称呼、用户语言等画像事实沿用现有记忆领域；人格风格、回复详略、幽默等表达偏好归“设置 → 人格与表达”。不得在两页各提供一套覆盖同一字段的开关。需要持久保存的表达偏好候选只在设置审核；普通聊天中的“这次简短些”仍可作为本次意图，不能自动写成全局配置。

长期记忆共享不等于专项会话可以互读原始聊天。查看来源跨会话定位时只展示允许读取的记录；已清理来源显示“来源已清理”，不从旧缓存恢复文本。

遗忘前列出目标及实际关联影响；进行中显示“正在清理”，完成后展示已处理/保留范围。失败可继续现有清理工作单，不能用刷新页面冒充清理成功。空态分别说明“还没有记忆”“没有匹配结果”和“正在读取”，不混成同一句话。

## 5. 设置中心与首次启动

七个分区为人格与表达、桌宠与外观、通知与打扰、记忆与隐私、模型与连接、工具与插件、数据与高级。每个分区显示已生效值、修改状态和保存结果，按分区保存；不提供跨多个后端的虚假“全部保存成功”。

普通分区离开时保留内存中的未保存表单并标记；返回时可继续或放弃。秘密输入例外：离开密钥编辑流程或取消即清理，返回只显示已保存状态，不从草稿还原密钥。应用退出前对仍未保存的更改给出返回/放弃选项。保存成功后以后台返回的有效值为准。

首次启动分为两个状态：

1. **尚未配置可用连接**：进入设置中的模型与连接，云模式默认选中。可填写地址、模型名、密钥；允许暂不配置并浏览本地已有内容，发送不可用且说明原因。不能因缺密钥直接终止整个 GUI，也不能用离线示例冒充模型答复。
2. **已有可用配置**：正常进入聊天，保留已有模型选择、人格和用途许可。升级不会自动把旧 offline/本地连接迁为云，也不会自动把旧消息改为可出云。

新云配置的保存区域说明“新的聊天输入将由所配置的服务处理”，用户确认保存后应用于后续普通请求；历史、长期记忆和人格各自继续受类别/来源许可限制，不由一个云开关整体放开。

模型配置不要求用户部署本地服务；本地端点、代理处理、协议兼容等字段只在选择本地后出现。高级离线演示明确显示为示例答复模式。当前运行位置和有效凭据来源在设置内可查；聊天不重复展示模式选择或部署术语。

### 保存模型配置时的连续体验

配置校验、进入维护、写入、重新打开应在同一套设置视觉中呈现步骤，而不是让用户自己寻找另一个程序窗口。已有任务存在时先显示受影响状态，停止接收新请求并等待安全关闭；不为换密钥强制结束已经执行的同步副作用，也不宣称它已撤回。

用户可以在敏感载荷交给维护服务之前取消切换并返回原配置；开始保存后的取消语义是等待确定结果再恢复界面，不能同时报“已取消”和“新配置已生效”。超时或重新启动失败保留可恢复设置入口及已保存版本，不能退回无反馈的空白主窗口。原会话从持久目录重新读取，未发送草稿可在同进程维护切换中保留；真实退出不承诺恢复草稿。

维护恢复草稿仅限同一数据目录、会话仍有效且清理版本未变化；更换目录、恢复备份或隐私清理后不能把旧文本直接注入新会话。重新连接后重新读取任务和授权状态，不能同时恢复旧的授权勾选或进程内许可。

保存只是本地保存，连接测试是独立显式操作。状态文案区分“已保存，待生效”“已生效”“连接验证成功”和具体失败原因；连接验证失败不删除刚保存的值，用户可以修正。

## 6. 图片与工具页的完成定义

图片编辑只在设置进行，顺序为选择文件、校验、预览、应用。预览不更换主窗口和桌宠的当前图；后台成功后同步相关槽位。导入失败显示原因并保留原图；连续选择两张图片时，迟到的第一张不能覆盖第二张。用户头像、角色聊天头像、桌宠主形象及差分独立保存。

图片选择器说明文件格式与限制，PNG 透明图适合桌宠，JPEG 不自动去背景。首期提供保持比例的显示区域调整和头像圆形/方形预览，不承诺图像生成、抠图或动画制作。重置按槽位执行；如果差分未指定，回退当前主形象。

工具插件页按真实能力分组，展示中文名称、用途、来源、版本、所需权限和可用原因。选择一个条目只展开详情，不试运行、不联网、不授予权限。无中文元数据的扩展使用可信通用字段显示；不能为了美观隐藏实际未知参数。

内置工具分组与插件提供方是不同概念，不能将 19 项工具写成“安装了 19 个插件”。后续配置、安装、连接、启停能力仅在设置中按后端 capability 显示；当前不支持时不给可点击的假操作。空目录、读取失败和能力不可用各有独立说明。

## 7. 统一反馈与异常恢复

| 事件 | 用户应看到什么 | 允许的下一步 |
| --- | --- | --- |
| 发送尚未确定受理 | 消息处“正在核查发送结果”，保留原文 | 查询原命令；查明未受理后复用同键重试 |
| 任务失败或部分完成 | 对应卡片给出事实、已完成步骤与失败原因 | 查看结果；需要再做时形成新请求，不重放旧副作用 |
| 模型连接不可用 | 原消息的失败说明，指出设置中的对应分区 | 保留草稿/记录，用户自行进入设置修正 |
| 设置版本冲突 | 显示当前保存值与本次改动，保留非秘密草稿 | 重新载入或确认合并后再提交，不自动覆盖 |
| 图片损坏或超限 | 就地说明支持格式/上限，当前图片不变 | 重新选择或取消 |
| 历史读取失败 | 保留已有消息并显示加载失败 | 重试该页，不清空整个会话目录 |
| 来源/权限失效 | 旧审核卡不可操作，解释需重新审阅 | 获取当前计划；旧勾选不能沿用 |
| 清理尚未结束 | 原范围遮蔽，显示清理中及工作单状态 | 查看进度或继续恢复，不提前显示完成 |
| 退出期间提醒到期 | 重开后在安排/原会话显示错过的提醒 | 标记已读；不伪造已经准时发送系统通知 |

错误文本默认不用堆栈、原始 JSON、hash 或内部 ID，技术详情按需展开且脱敏。成功提示不能单靠短暂 toast：已完成的任务状态、有效设置和已导入素材都应在原位置持续可见。
