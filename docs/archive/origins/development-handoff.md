# Personal AI Agent Desktop Companion

# Codex 开发交接文档

版本：V1.0 Draft

------------------------------------------------------------------------

# 1. 文档目的

本文档用于向 Codex 交接 Personal AI Agent Desktop Companion
项目的完整背景、设计目标、技术约束和开发要求。

Codex 应根据本文档进行项目初始化、架构设计和代码实现。

本项目不是普通聊天机器人，而是一个长期运行的个人智能 Agent。

------------------------------------------------------------------------

# 2. 项目定位

## 2.1 核心目标

开发一个 Windows 平台个人智能 Agent。

核心形式：

-   Live2D 桌宠作为常驻交互入口；
-   可展开完整主窗口；
-   基于大语言模型进行理解和规划；
-   通过工具系统执行实际任务；
-   通过长期记忆形成用户模型；
-   通过人格和情绪系统模拟持续性人格。

最终目标：

成为用户长期使用的个人数字助手。

------------------------------------------------------------------------

# 3. 核心能力要求

系统必须支持：

## 3.1 Agent能力

-   自然语言理解；
-   抽象目标理解；
-   任务拆解；
-   任务规划；
-   工具调用；
-   执行反馈；
-   长期记忆。

## 3.2 自主等级

采用 C 级自主能力：

Agent 可以：

-   根据用户数据提出建议；
-   根据长期目标规划任务；
-   在授权范围内自动执行。

默认模式：

半自主模式。

授权后：

高度自主模式。

# 6. Agent核心设计

采用：

Observe → Think → Plan → Act → Reflect → Memory

## Observe

负责：

-   用户输入；
-   授权环境信息；
-   当前任务状态；
-   相关记忆。

## Think

负责：

-   理解用户意图；
-   判断目标；
-   判断能力需求。

## Plan

负责：

-   任务拆解；
-   执行顺序；
-   工具选择；
-   风险判断。

## Act

负责：

-   工具调用；
-   本地执行。

## Reflect

负责：

-   判断结果；
-   生成执行总结。

## Memory

负责：

-   保存重要信息；
-   更新用户模型。

# 9. 记忆系统

采用混合存储：

SQLite + Vector Database。

## 记忆类型

### Working Memory

当前上下文。

### Episodic Memory

历史事件。

### Semantic Memory

用户事实。

### Goal Memory

长期目标。

### Relationship Memory

用户与 Agent 的关系模型。

------------------------------------------------------------------------

# 10. Memory Evaluator

记忆不能简单保存全部聊天。

需要由 LLM 判断：

-   是否重要；
-   是否长期有效；
-   是否未来有价值。

保存对象：

    Memory Object

    {
    content,
    importance,
    confidence,
    created_time,
    last_access_time,
    decay_rate
    }
