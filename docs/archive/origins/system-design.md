# 第一章 项目概述

## 1.1 项目背景

传统聊天机器人主要解决"问答"问题，而个人生产力场景需要的不只是回答问题的系统，而是能够长期存在、理解用户、规划任务并执行操作的智能实体。

本项目希望构建一种新型桌面智能助手：

-   长期运行于用户电脑；
-   以Live2D桌宠作为主要存在形式；
-   通过大语言模型获得理解和推理能力；
-   通过工具系统获得现实操作能力；
-   通过长期记忆形成用户画像；
-   通过人格和状态模型形成持续一致的交互体验。

其目标不是替代搜索工具，而是成为用户长期使用的个人Agent。

# 第二章 产品定位

## 2.1 核心定位

系统定位：

> 一个具备任务规划能力、长期记忆能力、自主行为能力、工具调用能力和行为拟人化能力的个人智能Agent。

区别于普通聊天机器人：

  普通聊天机器人   本系统
  ---------------- --------------
  被动回答         主动辅助
  单次上下文       长期记忆
  无执行能力       工具执行
  无目标管理       长期目标监督
  无人格连续性     人格模型
  网页入口         桌面实体

------------------------------------------------------------------------

## 2.2 用户定位

系统面向个人用户。

特点：

-   单用户；
-   深度定制；
-   数据私有；
-   长期使用。

# 第三章 Agent能力目标

## 3.1 自主等级

采用C级自主能力：

Agent可以：

-   根据用户数据提出建议；
-   根据长期目标规划任务；
-   在授权范围内自动执行。

但不追求无限自主。

------------------------------------------------------------------------

## 3.2 行为拟人化目标

采用：

Level 4行为拟人化Agent。

目标：

-   稳定人格；
-   长期关系；
-   情绪状态模拟；
-   主动交流；
-   根据用户反馈调整行为。

说明：

拟人化属于行为模拟，不代表真实意识。

# 第六章 Agent核心机制

## 6.1 Agent循环

采用：

Observe → Think → Plan → Act → Reflect → Memory

------------------------------------------------------------------------

## Observe

观察：

-   用户输入；
-   授权环境；
-   当前任务；
-   相关记忆。

------------------------------------------------------------------------

## Think

分析：

-   用户真实目标；
-   任务类型；
-   是否需要工具。

------------------------------------------------------------------------

## Plan

生成：

-   执行步骤；
-   工具选择；
-   风险评估。

------------------------------------------------------------------------

## Act

执行：

-   工具调用；
-   本地操作。

------------------------------------------------------------------------

## Reflect

分析：

-   是否完成目标；
-   是否产生新的信息。

------------------------------------------------------------------------

## Memory

更新：

-   用户模型；
-   长期记忆；
-   目标状态。

------------------------------------------------------------------------

# 第十章 记忆管理机制

## 10.1 自动记忆生成

由LLM判断：

-   是否重要；
-   是否长期有效；
-   是否未来有价值。

流程：

对话

↓

Memory Evaluator

↓

摘要

↓

存储

------------------------------------------------------------------------

## 10.2 存储方案

采用混合方案：

SQLite：

-   用户信息；
-   目标；
-   状态。

Vector Database：

-   对话摘要；
-   事件；
-   语义关联。

------------------------------------------------------------------------

## 10.3 遗忘机制

采用权重衰减。

记忆包含：

-   importance；
-   confidence；
-   created_time；
-   last_access_time；
-   decay_rate。

低权重进入候选删除区。
