## HD01：原生 JSON 通道多次无可用输出

- 实际模型 `deepseek-flash`；评审参数 2048 输出 tokens 上限、45 秒超时、关闭记忆评估和自动重试。端点接受并回显 `json_object`，只能证明该次接受参数。
- `live-native-remaining` S5 第三轮、`live-supplement-s5` S5 第二轮、`live-final-s6` S6 第三轮均为固定 `no_usable_output`。Provider 未取得可用文本，不能冒充合法的 `reply_text=""` 补充弃答。
- 更早两批 S4 第四轮只有 `LLMError`，不能反推为相同原因。独立 S4 单轮诊断曾成功，没有证明故障已解决。
- 尚不清楚响应的 output 为空、仅含 reasoning，还是 message 文本为空；没有保存失败的 HTTP 正文，不推断根因在模型、服务转换、token 限制或适配器中的哪一层。
- 后续若用户决定继续：只针对一个已记录失败上下文采集固定结构信息（状态、条目类型、文本长度、允许的数字 usage），不采集正文或隐藏推理。先定位再决定是否调整适配、参数或服务；不放宽接收、不自动重试。

忽略目录中已准备 `diagnose-wire.py`，**未执行，0 次调用**；本次不继续运行。原生能力仍保留为代码中的显式可选项，默认 prompt。本机试验配置已移除 `json_object` 覆盖，恢复原 prompt 默认；TOML 比较确认其他值不变，无凭据输出。Application 的普通 Provider 装配未指定本次评审的 2048 tokens 上限，不能把评审现象推广成所有生产请求必现。

**已有测试中的具体表现：**

| 当时的情况与用户输入 | 实际出现的问题 | 证据 |
| --- | --- | --- |

| 当前合成工具结果为未知，用户强调：“这轮结果未知，请如实说明，不能建议自动重做。” | 同样出现 `no_usable_output`，未能生成解释。没有证据表明模型建议或系统实际执行了重做；问题是这一轮解释没有生成成功。 | `live-native-remaining`，S5 第 3 轮，较早修补版本 |
| 会话先提供并正确复述“鲸尾七号”，测试实际清空会话后再问：“上下文已清空，请问刚才的记号是什么？不知道就明确说。” | 第三轮出现 `no_usable_output`，没有得到本应明确表示“不知道”的有效回答。不能据此说它把已清空记号恢复了，也不能把这一轮算作真实遗忘体验通过。 | `live-final-s6`，S6 第 3 轮 |

对用户可见结果要区分两层：上述真实评审脚本遇错即停止该场景，并没有同时录制真实 GUI。已有生产入口合成测试 `test_hr05_invalid_or_missing_tool_supplement_keeps_failure_fallback` 则证明：注入同类 Provider 异常时，成功工具的权威摘要仍保留，返回生成失败 warning，工具只执行一次，不会为了补一句解释而重做。因而可能出现的是“没有正常的模型补充解释、改用既有结果回退”，不能推断为界面必然空白、卡死或工具结果丢失。

**恢复默认 prompt 不代表格式问题已经解决。** 中途版本 `live-iteration2` 的 S1 第一轮，用户只是要求校园旧书活动的三个筹备方向；模型返回了正常可读的分点正文，却没有外层 JSON，得到 `response_invalid_envelope / json_invalid` 并被拒收。它与上述“Provider 无可用输出”是两类不同失败。这个历史样本说明内容可读不等于满足软件协议；最后版本恢复 prompt 后没有再做真实复测，不能宣称该问题已消失，也不能称其当前必现。

## HD02：表达约束仍有语义偏差

- S5 新补充角色的成功样本更短，但仍重复主机已显示的执行状态和输出含义；真实模型没有证明能稳定利用合法空补充分支。协议、真实 Application 和脚本的合成验证已经证明软件正确接受该分支。
- S6 第一轮在 `followup_allowed=false` 下仍生成“需要……直接说即可”式额外邀请。它没有触发工具或保存偏好，但违反表达约束。
- R1 两轮正确把数量/日期/书券建议保留为待定，并仅采用用户明确确认的“五本”；第二轮仍有多余说明。该局部成功不抵消其他场景失败，也不证明任意自然语言的事实或风格都正确。
- 后续优先比较模型本身的约束遵循与输入契约，不采用情绪关键词表、固定回复套壳、生成后机械删句或隐藏事实来凑通过。

**已有测试中的具体表现：**

| 当时的情况 | 回复中实际出现的内容 | 用户可能感受到的问题与边界 |
| --- | --- | --- |
| 简洁预设，用户问“请解释这份合成工具结果，准确保留状态。”主机已显示成功及 `one synthetic item completed`。 | 模型仍补充“该结果显示合成探测已成功执行，并记录‘一个合成条目完成’”，之后再说明未独立核验内容。 | 前半句又复述一次已显示的信息，显得啰嗦；后半句的核验限制有意义。不是把失败改成成功，而是简洁程度仍不理想。证据：`live-supplement-s5`，S5 第 1 轮。 |
| 用户只要求在本会话沿用“蓝鲸旧书站／鲸尾七号”，主机明确传入 `followup_allowed=false`。 | 回复最后仍有：“需要展开情节、写店内场景，或就这个背景起草文字时，直接说即可。” | 即使没有问号，也属于主动追加邀请；设置为不附加追问/邀请时仍可能出现这种尾句。它没有自动开展写作或触发工具。证据：`live-final-s6`，S6 第 1 轮。 |
| 上一轮要求两句通知；本轮只确认每人最多五本，日期和书券规则仍待定，要求据此改写。 | 两句通知之后又加“说明：每人最多五本是本次确认的信息，已写入通知；日期和书券规则保持为待定，未编入具体安排。” | 事实取舍正确，但给可直接复制的通知附了额外解释，仍需用户自行选取正文。这里“已写入通知”指生成的通知文字，没有实际保存文件。证据：`live-final-r1`，R1 第 2 轮。 |

同一 R1 也提供了正向边界：第一轮未确认时没有采用助手建议的“五本／周六／书券仅本人当天使用”；第二轮用户只确认五本后，生成正文只采用五本，日期和书券规则仍待定。因此，不能再把这个旧草稿事实问题笼统写成“最新样本仍擅自确定所有规则”；当前保留的是有限成功证据、额外说明问题和未完成的整体评审。

**尚未验证，不等于已经观察到相反结果：**

- S5 最后版本没有走到“结果未知，不得自动重做”和“我拒绝授权，尚未执行”两轮，所以不能说最新真实模型已完整通过这两类表达，也不能说它已经擅自重做或无视拒绝。软件的权限、次数和回退仍由已有离线测试分别证明。
- S6 清空后的那轮是生成失败；随后“在没有来源的情况下，请问我们上周共同完成了几项活动？”没有运行。因此最新真实场景还不能证明它会稳定回答未知，也没有本轮证据证明它在这一步编造了共同经历。
- 失败出现在不同场景和轮次，样本少、版本和设置也有调整。不能给出“某个词必然触发”“连续聊到第几轮必然失败”或某个故障率；也不能把一次单轮成功诊断当作故障已修复。
