# V0.7 父 Agent 架构与生命周期复核

日期：2026-10-21（Asia/Shanghai）。这是源码审查记录，不代替原生输入、安装与资源验收。最终结论以[test-report.md](test-report.md)为准。

## 执行与数据边界

DesktopHost继续通过既有ApplicationBridge和factory拥有唯一Application/Core。新增presentation是空参数只读操作，读取任务标识、状态、revision和持久audit序列，不读取任务请求、计划或结果正文。Facade沿用session/memory_epoch信封；GUI严格校验七字段DTO。表现模块没有Application/Core、数据库连接或工具管理器，也没有授权/确认入口。角色点击只调用Host.restore，显式打开主窗口。

任务投影在WorkflowStore既有事务锁内取得序列和候选元数据；追加索引在后台初始化事务一次建立，未变更schema版本、工具执行路径或V0.6策略。原排序与健康队列约束已有专门测试；有界返回不表示任意损坏数据库的扫描成本有硬上界。

## Qt与线程所有权

文件、QBuffer、QImageReader和源QImage只在一个受控Python工作线程中使用。工作线程交付预缩放的独立QImage后不再改动；QPixmap转换、原生命中区域、Widget、QPainter和销毁均留GUI线程。GUI不读取PNG、不join或等待工作线程。这里只使用可信固定包资源，未开放外部路径、manifest、URL或可执行角色文件。

PetAssetLoader取消/超时不丢弃线程引用，也不强杀线程；只合并一个最新请求。完成信号排队到GUI，确认线程实际结束后才清所有权。Controller用独立加载代际拒绝迟到结果，禁用清缓存并保留待销毁窗口至destroyed。Host等待bridge Closed、loader结束和窗口销毁后才退出Qt；等待时仍显示真实关闭状态。这些机制不能保证任意native崩溃后GUI存活，也不把长时间不退出伪装成成功。

## 展示与交互

状态查询最多一条在途，隐藏/禁用停专用轮询。新鲜度、宿主/隐私代际和顺序由Controller检查；首次显示或恢复建立基线，不补播历史成功。memory_epoch在同sequence前进时建立新基线并取消旧装饰，其余同序冲突仍拒绝。Waiting/Failed/Unknown和Closing抢占装饰，不更改后台任务状态或重试执行。

窗口固定逻辑尺寸，表情共享neutral命中区域，实际透明点击和整窗穿透分别验证。后台展示不调用activateWindow；显式点击导航允许主窗口激活。拖动达到Qt阈值后不导航。几何按逻辑坐标保存/夹回工作区，不修改系统缩放。真实混合DPI往返和切图边缘必须依据原生证据，不能从源码推定通过。

## 当前结论

父 Agent 已检查新增Controller、loader、窗口、Host关闭汇合、DTO、应用查询和状态SQL，未发现确定需要修改的新生产缺陷。双Python受影响回归、离线wheel/中文空格target资源一致及安装GUI短测已有证据；r7已补实际1x/2x往返及右屏禁用再启用位置恢复，用户确认右屏外观正常。最终30分钟资源复算与[内存简析](memory-review-2026-10-21.md)已完成；原helper exit1、两次预览identity未匹配和增长未完全归因均保留，不整体认证T08。

先前慢loader心跳p95=125ms超过100ms目标，首次记录保留。原始计时显示诊断工具在GUI线程调用资源采样约78–172ms；父审后只修改诊断，将Windows采样与一次初始化的ctypes绑定放到单个非Qt工作线程，并以最新槽交付结果、Qt退出后有界等待其结束。原50ms默认Coarse timer和100/500ms目标未变。修后安装GUI及独立慢loader短测均p95=63ms，支持原测量存在实质干扰，但不声称全部延迟只有一个原因。完整证据和方法差异见测试报告。

最终冻结probe为5f23b888c922e4aa4e67fad53581f259f9afb3f6e5c10bc27a36e94e64a9c988。长测须逐轮核对真实OS回稳、同一进程禁/启各300秒CPU窗口和完整运行中资源曲线；不能只用关闭末值，或扣除估算探针保留量后判通过。cycle_settled的单次2秒后记录不等于连续5秒OS稳定。原生拖动/穿透的受控记录可认证对应动作，不能延伸为未完成的混合DPI和位置恢复通过。

静态版不接入Live2D、不实现人格情绪；产品版本保持0.5.0rc1。V0.6阶段0、隔离能力与V0.5原有未结项均未由本审查认证。

用户最新要求不做时序诊断、仅简析内存与必要修复后先归档。现有探针的原始记录列表有确定的运行中增长机制，表现层计数回收与数值预算达标，但未取得完整分配归属，不能排除native泄漏。未定位到明确生产缺陷，未安排推测性修改或追加诊断运行。按[归档记录](delivery.md)结束本轮，未决项进入[后续测试清单](deferred-tests.md)，不修改原验收门槛或把未测写为通过。
