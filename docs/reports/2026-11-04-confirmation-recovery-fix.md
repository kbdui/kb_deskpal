# 2026-11-04 确认操作与任务恢复修复

只读检查当前角色的工作流数据库和执行日志后确认：问题任务先完成六个查询步骤，随后模型提出四个管理操作，合计十步，超过配置的八步上限。旧循环先保存超限计划，再把预算不足归入需要重新审阅；确认恢复时，Core 又因计划超过上限抛出异常，Dispatcher 因此停止执行线程。两次确认均未开始剩余四项操作；重复点击不是这次故障的根因。

本次在后续规划中加入剩余步骤预算，并在保存下一轮快照前检查总步数。步骤、轮数和时间预算用尽时，任务明确失败并保留已完成结果，不再呈现为可以靠确认解决的授权事项。已有超限计划在审核页说明总步数、已完成数和续办方法，移除不可执行的确认入口；服务层和执行线程再做同样的预算拦截，避免恢复此类旧记录时停止整个后台。

界面会采用较新的后台确认状态，更新“已受理”提示。操作返回错误且核查确定没有受理回执时，释放挂起操作并重新读取任务，不再困在原命令重试状态；没有明确受理字段的响应也不再直接视为成功。中断日志新增异常类型，用户界面的中断说明改为中文。

未修改真实用户数据库、代用户执行待确认操作或调用真实模型。按本轮沿用的约定未运行测试，仅做代码与差异静态检查。原问题任务需重启加载修复后查看，取消超限请求，再仅提出尚未完成的要求；已完成的六项查询不会重放。
