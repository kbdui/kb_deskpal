# 2026-11-09 上下文与逐条消息学习调整

本次修复近期聊天正文被来源元信息挤掉、角色的自我设想难以保留，以及角色最终回复被提前视为已整理的问题。数据库表结构保持不变，既有数据通过可选 JSON 字段和新格式回执兼容读取，不主动重写真实档案。

## 近期聊天上下文

近期窗口继续最多读取八轮。历史与规划预算按照模型可见的正文视图计算，后台的编号、修订和来源索引不再重复占用正文预算。每条历史只携带所属轮次的直接消息引用，原任务的完整执行依赖仍留在工作流中。读取已经发布的历史时检查聊天自身的归属、清空状态、消息存续与用途，不再因当时参考的某条记忆后来发生修订就隐藏整段原话。历史仍是当时的发言，不能作为当前事实或新的执行授权；长正文及工具结果仍受总预算限制，不承诺无条件送入八轮。

## 来源类别与发言者身份

`origin` 继续描述用户消息、角色输出、工具结果或导入资料等来源类别。`MemorySource` 的既有 JSON 内容增加可选的 `speaker_id`、`speaker_name`、`speaker_kind` 和 `channel`，分别保存稳定身份、显示称呼、参与者类型和渠道；`MemoryDraft.subject` 表示内容讨论的对象。旧数据缺少这些身份字段时保留为空，不猜测原发言者。

本机用户使用 `local:user`，当前角色使用 `character:<角色标识>`。未来插件可由受信适配器提供如 `qq:<账号标识>` 的身份，并使用既有导入资料或工具结果类别；渠道不作为身份，同名者不合并，也不把插件联系人当作当前用户。模型使用宿主提供的身份，不自行生成身份编号。学习去重同时考虑发言者与内容对象，检索视图保留身份信息。本次没有实现 QQ 插件或联系人接入。

## 角色自己的设想

学习提示词区分外部事实、角色的主观设想和用户的明确要求。已经发布的角色外貌、创作偏好等可以用 `assistant_output` 和 `hypothesis` 进入现有缓冲区，保留原话、发言者和内容对象。用户认可具体设想时，可关联双方消息继续复核采用；被采用仍表示角色的主观设定，不表示客观事实。存储校验仅允许有角色身份、内容对象为该角色本身的假设解除旧有的采用限制，一般助手猜测仍不能直接采用为事实。角色卡不会因此被自动覆盖。用户纠正和双方已讨论的细节应进入摘要，避免将新的话题对象误替换为旧话题。

## 最终回复的整理标记

沿用“同步学习，再提交任务并发布回复”的顺序，不增加每轮模型调用。用户消息可以在本轮完成学习；当前角色回复此时仍是草稿，不作为已经发布的记忆依据。角色最终发布的正文在下一轮进入未整理历史，处理后才写入自己的完成回执。停止聊天后，最后一条角色回复会保持未整理，等待后续聊天带入；不会为了补标记额外调用模型。

回执按消息来源标识和实际正文摘要分别保存到现有 `memory_learning_receipts`。同一轮用户消息已完成，不再意味着角色最终回复也完成；正文发生变化也不沿用旧完成标记。旧整轮回执仅兼容为用户消息已整理，不能证明当时尚未生成的最终回复已处理。补查返回的消息同样分别标注整理状态，只有真正交给学习模型并成功提交的消息才记录完成。

## 验证

使用合成临时档案检查最终回复与草稿的区别、下一轮学习与去重、角色设想保存和用户认可后的采用、插件同名参与者身份往返、来源元数据不挤掉八轮短聊天，以及记忆修订后原话仍可读取而撤销原消息后停止读取。另运行反馈学习、学习回执和模型视图的相关回归。没有调用真实云模型，没有重放或恢复真实聊天内容。

最终核心套件 60 项通过，包含新增的 5 项场景回归，JUnit 记录在 `build/message-learning-final-20261109.xml`；十份修改源码通过定向 mypy。会话连续性与持久层套件 21 项通过、1 项失败；记忆存储、检索及显式记忆套件 169 项通过、1 项失败，后者记录在 `build/message-memory-storage-20261109.xml`。各套件存在新增场景的重复执行，不将计数直接相加。
