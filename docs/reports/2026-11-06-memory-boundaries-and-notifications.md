# 2026-11-06 记忆操作边界、滚动摘要与通知修正

本次按用户确认的六项修复方案实施，并将记忆页改为只读。此文记录实现变化，不代表通过验收。按要求，本轮没有运行自动化测试、类型检查、实机交互或真实模型调用，也没有打开应用或手动修改现有用户数据库。

## 操作边界与记忆页面

遗忘仅删除指定记忆及其历史修订、索引、对应学习正文；共同来源、来源任务、其他记忆对它的引用都不再触发级联删除。聊天原文、同轮其他记忆、已形成的人格/习惯/情绪、执行记录和日程保留。撤销依赖旧记忆的未完成工作与删除历史记录分开处理。同步移除了 AgentCore 在确认旧计划、失效待执行计划和执行遗忘时擦除任务的入口，以及按任务来源批量删除角色学习状态的入口。相关理解是否需要调整由后续学习判断。

聊天工具内的遗忘在当前执行线程完成，只撤下本轮旧记忆依赖，再继续模型判断和最终表达；不再为了遗忘中断自身，返回一个长期悬挂的“已受理”。既有外部管理入口仍可使用持久清理回执恢复。程序不尝试推测恢复此前已被旧实现删除的聊天原文。

清空聊天保留会话名称，仅清除该会话消息、摘要与工作上下文，停止仍依赖这些内容的工作。已创建的日程与提醒只断开聊天归属，名称、时间和提醒功能继续有效；任务执行结果不再被擦除。日程列表、授权中的目标说明及提醒到期检查均以日程自身为依据。

记忆页保留分类、列表、详情、重新加载和学习记录，移除新建、更正、遗忘菜单及右侧编辑表单。需要改变记忆时由用户在聊天中提出，模型复用管理工具；现有危险操作授权边界继续有效。

## 滚动摘要与模型协议

摘要仍由同步学习生成，采用上一版摘要和新增交流；历史来源从每轮传递的数组迁入独立的 `conversation_summary_source` 关联表。当前摘要不再累计携带全部来源，384 条限制仅约束单次新增来源，累计聊天不会因旧来源过多而停止保存。读取摘要时在数据库校验来源；来源失效后的重建使用新的来源集合。

摘要投递写入记忆库 `learning_summary_outbox`，与本轮学习完成、已整理标记同事务提交。工作流库 `conversation_summary_delivery` 提供幂等回执。保存失败保留旧摘要及待投递内容，后台恢复重试存储，不重复请求模型或重做学习；会话已清空、来源失效或更新版本胜出时，将旧投递标为失效。已整理标记与摘要投递成功是两个不同状态。

反馈提示词明确四类摘要字段均为字符串数组，并给出短例子。单段非空文字可以无歧义转为单项数组；其它字段错误使用明确的 `summary.<字段>` 诊断请求模型修正。增加明确遗忘约束，要求模型不得从旧聊天/工具引文重新生成用户要求遗忘的理解或将其写回摘要。

## 主动复查与统一免打扰

到期的主动跟进读取最新记忆版本，让模型重新判断继续、调整或结束，不因一次更正就直接取消。已删除、归档或失效的来源不再使用；还有有效来源时继续复查，完全没有依据时结束。执行期间仍验证已冻结的版本，防止处理中的旧结果覆盖新状态。没有新增独立的主动行为模块。

免打扰时间持久保存在当前角色工作流库 `notification_settings`，前端只缓存后端返回值，普通主动聊天和系统通知共用该配置及角色配置时区。新增“定时提醒可突破免打扰”开关，默认关闭；开启仅允许定时提醒突破，不能突破用户明确暂停提醒或关闭系统通知的设置。首次建立后端设置使用已有后台配置时间；旧前端 QSettings 中独立的小时值不再作为生效配置，可在设置页重新调整。

未开启突破时，到期提醒保持可读，状态为“免打扰结束后通知”，并写入持久延后投递记录。结束免打扰后重新核对日程是否仍有效，再进入现有汇总通知流程；等待期间不因普通通知的两分钟有效期被丢弃。暂停提醒与免打扰不同，用户明确暂停的提醒不在恢复时逐条补弹。

## 数据库与待验收范围

工作流库升级至 schema 7：增加摘要来源、摘要投递回执、统一通知设置和延后提醒表；原摘要的来源迁到新关联表。记忆库升级至 schema 4：增加摘要投递表。备份/恢复识别同步支持新版本。升级由后续启动执行，本轮未运行迁移，也未修改真实数据库。

后续至少验证：同轮两条无关记忆遗忘其中一条时其余数据保留；聊天中的遗忘能完成自然语言回复；清空聊天后日程仍可查看、编辑并到期提醒；超过旧来源上限的连续摘要仍更新；摘要投递失败和重启恢复不重复学习；更正记忆后的主动跟进读取新版本；免打扰前后、跨午夜、突破开关、显式暂停、重启和已取消日程的组合；记忆页只读。既有测试中断言级联擦除、旧编辑控件及前端独立免打扰的部分需要按新约定更新，不能把旧行为当作新验收标准。
