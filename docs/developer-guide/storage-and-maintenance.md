# 存储与维护

当前正式 schema：workflow **5**、companion **4**、memory **3**、scheduling **1**。[数据库设计](../planning/companion-redesign/database-design.md)说明表、归属及迁移；相应 schema 模块集中定义，服务初始化不能自行补建表。

角色档案承载全部业务库和受管头像/桌宠资源；应用连接、凭据、外部工作区和模型缓存共用。只运行一个激活档案，关闭旧后台与数据库后再启动目标。旧结果按档案与运行实例边界丢弃，未激活角色不整理、不提醒。

迁移必须处理已知旧版、未知版本、失败回滚和备份恢复兼容，保持原计划和实际结果。测试里的旧 schema 输入是迁移夹具，不能因“旧版”而删除。P1 对开发期旧角色数据清理初始化的特殊决定不能泛化成未来用户数据策略。

维护沿既有实例互斥和所有权执行。备份/恢复核对归档、schema、哈希、资源与安全发布，部分失败不能伪装恢复成功。缓存验证不等于重新下载；普通测试不得读取真实凭据、角色数据库或应用的模型资产。具体命令见[用户维护](../user-guide/maintenance.md)，历史细节见[整理前指南](../archive/guides/developer-guide/storage-and-maintenance.md)。

Windows 工作库备份目前使用 create-new rename；其他发布路径有不同契约。故障注入应针对实际受测发布点，不能一律假设所有备份都使用 hard link。仍须保留不覆盖现有目标的断言。
