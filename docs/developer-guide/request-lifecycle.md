# 请求生命周期

用户提交经 ApplicationService 登记任务与会话，再由唯一 SubmissionDispatcher 交给 AgentCore。应用层准备当前角色卡、有效互动要求、相关长期记忆和双方会话历史；请求带档案、来源修订及隐私边界，不靠线程隔离数据。

模型返回下一步：直接回答、请求补充，或调用工具/内部管理接口。程序验证参数、来源和权限，必要时在原任务中等待用户确认。实际结果逐步入账并回到模型，继续预算内的下一轮；失败、部分成功和未知结果如实保留，不通过重复副作用“修复”。

追加要求在下一次模型判断采用。暂停请求持久保存，当前调用及已决定步骤组可完成，到下次判断前暂停并释放线程；恢复原任务时读取最新背景和累计预算，重新决定尚未执行内容，不能重放已完成步骤。授权等待、暂停、取消和终态分别处理。

可以最终回复时先生成内容，再同步自动记忆评估与缓冲保存，最后提交并发布；评估临时失败有限重试，耗尽不无限扣住已有结果。工具明细属于执行账本，模型只提炼值得长期保留的经历。

普通主动聊天也走此链路，来源标为主动请求，不伪造用户消息。内部整理经同一 Dispatcher 进入反馈服务；确定日程提醒沿 Scheduling 履约。详细规则见[执行决定](../design/companion/execution-lifecycle-decisions.md)。
