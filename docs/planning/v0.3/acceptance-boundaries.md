## 语义效果与资源评测建议

在实现前建立版本化、无真实私人信息的中文数据集，例如 80 条有目标记忆的查询与 20 条无关查询，涵盖同义改写、偏好更正、姓名/数字、时间与否定。建议正例 Recall@5 不低于 0.80、无关例误检接受率不高于 0.10；这是待冻结的项目目标，不是某个模型已达到的声明。用人工标注及词法基线比较，不能只测“向量shape正确”。

先以 5,000 条记忆、选定模型固定维度为小规模压力集；分别记录模型加载、query embedding、索引检索的耗时，区分冷启动/预热，并记录峰值内存。推荐初始目标为预热后的完整查询 p95 ≤ 2 秒、模型/检索增量峰值内存 ≤ 1 GiB；正式值需在当前空闲内存条件下测量并冻结，未达标则换更小模型、减少批量或降低已声明容量，不能只改报告称通过。

单次自动评估的请求次数、输出上限与超时应可配置，集成测试证明预算有效、错误显示降级；不以“评分高”替代事实来源确认。模型下载失败、缓存损坏、索引缺失和版本升级都有明确恢复/降级路径，缺模型时不得默默联网下载或伪造向量。

## 实测与发布门槛

1. 首先通过存储/迁移、MemoryEvaluator、UserProfile、Retriever 的确定性单元和真实 SQLite 集成测试。
2. 在 Python 3.11、3.12 运行完整回归及严格类型检查；两个环境的结果独立记录，环境跳过必须说明实际缺口。
3. 使用专门授权和有限预算验证真实 LLM 候选提取与工具完成后评估降级；不读取真实私密聊天作数据集。
4. 推荐语义模块要求真实本地模型基准、断网缓存恢复、删除/更正失效与容量/内存验证；mock仅证明接口，不能代替效果。
5. 回归 V0.2 的 Scheduling、原计划确认与取消/退出行为；本版不得因记忆改动而擅自启用后台提议或新工具权限。
6. 实际报告明确哪些里程碑交付。语义模型未就绪时基础记忆阶段可以验收，但不能称全版语义检索已完成；迁移数据丢失、权限绕过、幻觉入事实或重复副作用均阻止发布。

## 明确不承诺

Goal/Proposal 状态、队列、重启计划确认与执行未知状态移交 V0.4；其验收覆盖目标持久化、提议去重/过期、接受不授权工具和副作用不自动重放，详见 [路线](../roadmap.md)。这些不再计入 V0.3 的通过项。

- 数据库持久化不等于模型推理全本地；选定记忆/评估文本在云模型模式下会外发，后台外发默认关闭。
- 数据库删除不等于擦除已存在的日志、备份或云端数据；保留/清理策略单独说明。
- 本版不交付主动提议或目标管理；后续提议也不是无人值守执行器，无默认后台截图、文件整理、自动消息或任意shell执行。
- 尚无系统弹窗、Qt/Live2D、人格/情绪、全时唤醒、跨设备同步、完整OS隔离或推理模型native多轮续接。
- 现有Task与Waiting私有计划仍是进程内状态；长期Goal/Proposal持久化不自动使旧Task可恢复，也不提供跨存储exactly-once工具执行。
