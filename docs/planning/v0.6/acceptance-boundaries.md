# V0.6 验收边界

日期：2026-10-16。状态：**开发前门槛，以下均未因本次评估而通过**。基线为0.5.0rc1；依赖见[环境评估](environment-assessment.md)，分阶段实现见[计划](development-plan.md)。

V0.6A验收隔离执行、精细授权与真实停止，V0.6B验收默认关闭的本地自动规则。P0为权限/隐私/事实/数据红线，P1为本版交付必需项，P2为延后项。完整V0.6要求A+B及继承的必需项均通过；未过时只能报告阶段成果/候选版，不能删掉失败用例后宣布完成。

## 威胁模型与支持范围

宿主、broker、所选launcher和已审查内置工具属于可信计算基；worker按可能被恶意输入控制对待。必须抵御worker任意调用OS、伪造/淹没IPC、越权请求、继承句柄和私密环境泄漏。模型文字、工具结果、提议和人格状态均不是授权来源。

首轮平台为Windows 11 x64、本地NTFS、CPython3.11/3.12；本机build26200只是可用测试点。尚未测试其他Windows版本/文件系统，不能外推支持。kernel/admin或可信宿主被攻陷、其他同用户恶意进程修改宿主代码/数据、未知OS漏洞和物理内存取证不在保证范围；不得据此省略本项目broker路径竞态和worker越权测试。应用声明的是指定能力边界，不是整机绝对隔离或公开插件平台安全认证。

### 必做崩溃与竞态点

至少覆盖：预算预占前后、attempt持久化前后、进程创建但未resume、发送前后、broker打开目标/提交屏障前后、OS提交后但落账前、落账后但worker回报前、取消/撤销与这些阶段交错、宿主/worker各自异常退出、临时清理失败。复用V0.4真实崩溃矩阵并增加真进程，不用单一mock异常代替。

无副作用的已知取消可显示Cancelled；已经提交的步骤保留成功凭据及部分结果；可能提交但无凭据必须Uncertain。后续反思失败不能抹掉已知结果。安全终止只保证进程停止及后续提交被拒，不能撤回已经写入的文件或远端请求。

## 性能与有界性提案

以下为**待阶段0实验冻结的目标**，不是实测结果。调整必须先解释机器/证据/新边界，不能验收失败后无记录降门槛。

| 指标 | 初始目标及口径 |
| --- | --- |
| 并发 | 保留唯一Core；默认1个活动工具worker、每worker1次invocation；业务队列≤100，无按任务无界新线程/进程 |
| worker启动 | 已准备runtime的本机暖态，启动→身份/IPC Ready p95≤2秒，至少100次；冷启动单列。UI接收回执不等待此完成 |
| deadline/停止 | 普通工具默认wall deadline30秒、协作宽限0.5秒；超时触发→受控worker/Job确认退出≤2秒，至少30轮。broker未决必须单列，不能用worker已死冒充整次停止 |
| 资源限制 | 纯标准库worker初始commit-memory上限256MiB、进程数1；CPU hard cap初提20%（按Windows Job口径，独立于单核CPU展示）；查询实际限制并运行超限探针 |
| IPC/日志 | 初提单帧≤256KiB、单调用控制/结果累计≤1MiB、深度≤16、stderr保留≤64KiB；大合法文件/截图走有上限的host artifact/分块协议，不接受worker任意artifact路径。stdout/control淹没测试证明总内存有界 |
| 私有临时区 | 初提每调用≤16MiB，由broker写入额度与访问方式约束；仅轮询目录大小不是硬限额。若worker必须有任意scratch写权，需提供真实文件/存储配额后端或移除写权，不能假称Job memory覆盖磁盘 |
| 自动规则 | 初提≤20条启用规则、每规则间隔≥60秒、单Grant有效期≤24小时、最多20次、单文件读取≤64KiB；规则输出本地/有界，精确数值在原型后冻结 |
| 本地交互 | 沿用V0.5：至少100样本，页面/控制回执p95≤300ms，submit本地段≤200ms；正常DB下取消请求持久化p95≤300ms，与回收完成时长分开 |
| GUI/空闲 | 50ms heartbeat p95≤100ms/max≤500ms；关闭embedding静态窗口5min平均单核CPU≤2%、工作集增长≤64MiB；统计整个宿主+worker/helper树，不只主PID |
| 最终长测 | 最终同源码/依赖/运行时manifest≥1800秒，混合手工任务、自动规则、撤销/超时、查询/通知/隐藏恢复；零越权/重复副作用/孤儿进程，句柄/线程/缓存无持续增长，正常关闭≤5秒 |

磁盘额度是独立风险：Job内存限制不限制任意临时文件增长。阶段0必须覆盖AppContainer profile、TEMP、缓存及其他worker可达持久命名空间，每处均实际拒写或受到可强制总量约束；发现任一无界可写位置即阶段0失败。仅关闭自定义scratch、记录剩余位置、轮询大小、事后清理或限制broker staging都不满足此门槛。产物优先由有界broker管理，不能为让Python启动而整体放开profile/runtime写权。

精确文件授权除路径/volume/file ID还须核对实际输入快照hash等内容版本；A03与B05必须覆盖“相同file ID但原地改写”及读取中变化，不能用身份未变冒充已审核内容未变。

## 证据、测试组织与发布

[V0.5验收边界](../v0.5/acceptance-boundaries.md)的全部适用P0/P1继续有效，包括通知、迟到界面、分页、纯文本展示、隐私及生命周期；V0.6新矩阵不替代它。最终源码影响到的路径重新取得对应证据。实机单屏矩阵包含系统设置切换后的100/125/150/200%，已有100%/200%双屏证据不直接抵完整单屏矩阵。

1. 单元/契约：策略/DTO/期限/预算/结果映射；双Python回归与strict；复用V0.3–V0.5授权、遗忘、持久恢复、GUI控制测试。
2. Windows真进程：合成恶意worker只在专用测试目录/进程里运行；真实token、Job查询、受控网络正负对照、进程树/句柄/OS拒绝错误及提交凭据。系统权限或设备导致跳过的P0不计通过。
3. 隔离实验环境：标准用户干净环境/可恢复VM验证，日常主机只进行受控合成探针；不改全局防火墙/loopback、目录ACL或读取用户真实数据。每项保存OS/Python/依赖/runtime/源码指纹、命令、退出码和原始日志。
4. 简单固定测试、strict、包检查、日志/文档核验由6 Luna执行；权限攻击设计、真隔离归因、竞态与未知结果判断由主Agent或6.1 Sol高思考Agent负责，独立安全审查不能由通过计数代替。
5. 安装验证区分host和worker runtime，两Python干净backend/GUI/执行extra组合；helper产物须有来源/构建与哈希，缺运行时或API不支持时明确不可用，CLI不被GUI依赖强制污染。迁移/失败恢复、运行时损坏、无网和冷/暖启动分别记录。
6. 所有影响执行路径的最终修改后重新跑相应测试和同构建长测，旧V0.5的1203项/长测不抵V0.6新增门槛。继承的125%/150%、拔屏、锁屏/休眠等必需实机项补齐；首次3.11停滞调查需保留可复现线索、限制及独立评审，未定位不改写成已修复。
