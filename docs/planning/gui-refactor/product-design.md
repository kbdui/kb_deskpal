## 1. 产品目标与已确认选择

Deskpal 是一个有持续人格、能记住用户认可的信息、陪伴日常并能受控办事的桌宠 Agent。日常入口是桌宠和对话，任务执行是对话中自然展开的能力，管理页面负责整理和追溯。

用户已在本轮确认：

| 决策 | 已确认方向 |
| --- | --- |
| 视觉 | 温暖陪伴：暖白底、柔和配色、圆角卡片，突出角色和对话 |
| 单击桌宠 | 在桌宠旁打开可输入、看回复、确认任务的小对话窗，可展开主窗口 |
| 会话关系 | 共用人格与长期记忆，各会话保留独立聊天上下文 |
| 默认会话 | 固定“日常聊天”，不可删除入口；可以清空记录、单独遗忘长期记忆 |
| 小窗默认会话 | 每次重新打开默认进入“日常聊天”，允许手动切换专项会话 |
| 模型使用 | 默认云模型，仅在设置中切换本地模型；聊天区不反复询问本地/云选择 |
| 设置边界 | 所有配置功能集中设置页；聊天、记忆、工具目录与桌宠上没有设置快捷入口 |
| 可定制素材 | 在设置中选择、预览、替换头像与静态桌宠图片 |
| 工具目录 | 独立“工具插件”入口，查看现有工具并预留扩展接口 |

其余尺寸、配色数值、设置分类和实施细节是本方案建议，后续可根据实际界面调整，不冒充用户逐项确认。

### 产品原则

1. **陪伴优先**：打开应用能直接说话，先看到角色、会话和回复，而非一排技术管理页。
2. **事情有始有终**：提交、等待确认、执行、结果、提醒到期都在原会话中可追溯。
3. **长期关系需要持久数据**：聊天存档、模型短期上下文、长期记忆是三个独立概念。
4. **人格影响表达，不改事实与权限**：失败不能包装成成功，模拟情绪不能替用户同意。
5. **普通操作不需要理解内部协议**：中文名称、明确动词、字段解释替代 ID、hash 和 JSON。
6. **同一设置一个权威来源、一个配置入口**：所有配置在设置页完成，日常页面只保留完成当前任务的操作。

## 3. 信息架构

主窗口设置五个一级入口，设置固定在导航底部：

| 入口 | 用户在这里完成什么 | 原入口归属 |
| --- | --- | --- |
| 聊天 | 日常聊天、专项会话、原地任务确认、回复 | 对话与会话 |
| 安排 | 待我确认、提醒与日程、进行中、历史；目标与建议为二级区域 | 任务授权、目标/里程碑/绑定、提议 |
| 记忆 | 看看它记住了什么、审核候选、更正、遗忘，按来源查阅 | 记忆与画像候选 |
| 工具插件 | 当前可用能力、来源、权限说明、版本、可用状态和故障原因 | 新增，只读能力目录 |
| 设置 | 人格与表达、桌宠、隐私、模型连接、通知和维护 | 所有原有设置面板 |

“人格与表达”是设置中心的首项。聊天头像是展示内容，没有点击改头像或调整人格入口；模拟情绪只显示简短只读状态，不占一个技术仪表盘页。用户需要配置时从统一的设置导航进入。

**会话栏属于聊天页**：只有聊天页展示“新建专项会话 / 日常聊天 / 专项列表”。切换安排、记忆、工具插件或设置时隐藏整个会话栏，并移除其布局列，内容区扩展填满可用宽度；不能只把文字隐藏留下空白。回到聊天恢复原会话和草稿。窄窗口用聊天专属会话选择器，其他页同样不显示它。用户截图中的常驻会话栏正是首版示意未实现此条件造成的布局问题。

“安排”不是第二个必须访问的审批站。用户从对话进入某项详情后，明确提供“返回日常聊天 · 定位这条消息”，恢复会话、草稿、滚动位置。后台提醒只加角标或轻提示，不抢页面。

目标、里程碑、来源绑定保留业务能力，但改成“目标详情 → 分步计划 → 关联提醒/任务”的嵌套流程；关联对象按名称选择，不让用户复制内部 ID。提议显示原因、来源和下一步，接受仍不等于授权执行。

## 4. 主窗口与视觉规范

建议初始窗口 1120×760 逻辑像素；以可用工作区为上限。紧凑布局在约 900 宽时折叠会话列表，侧边详情变为抽屉；小屏下允许各区域纵向滚动，不裁掉确认和发送按钮。

```text
┌ Deskpal ──────────────────────────────────────────────────┐
│ 导航     │ 会话                  │ 日常聊天               │
│          │ ＋ 新建专项会话        │ 角色名 · 温暖 · 可以聊 │
│ 聊天     │ 日常聊天  固定        ├────────────────────────┤
│ 安排  1  │ 整理项目资料          │ 我：20 分钟后提醒喝水  │
│ 记忆     │ 周末出行计划          │                        │
│ 工具插件 │                       │ [喝水提醒 · 等你确认] │
│          │                       │ 时间 / 内容 / 执行动作│
│          │                       │ [允许创建提醒] [取消] │
│          │                       │                        │
│ 设置     │                       ├────────────────────────┤
│          │                       │ 跟我说点什么…          │
│          │                       │ Enter 发送       发送  │
└──────────┴───────────────────────┴────────────────────────┘
```

以上布局只是结构示意，不要求用字符框实现界面。

### 视觉语言

| 项目 | 建议值 / 原则 |
| --- | --- |
| 画布 | 暖白 `#F7F5F0`，内容面 `#FFFEFB`，导航 `#EFEEE7` |
| 主色 | 深鼠尾草绿 `#456255`，浅色选中态 `#E4ECE4`；主按钮用白字 |
| 正文 / 辅文 | `#2F352F` / `#656B63`；实际实现测量各状态对比度 |
| 提醒 / 失败 | 暖琥珀与暗红，始终配文字和图标；不只靠颜色区别 |
| 字体 | 使用 Windows 系统中文字体；正文 14–15，消息正文 15，标题 18–22 逻辑像素 |
| 间距 | 基础步长 4，常用 8/12/16/24；消息行距约 1.5 |
| 圆角 | 输入与按钮 8–10，消息和任务卡 12–16；避免所有区域都套多层卡片 |
| 图标 | 一套统一线性图标，关键操作始终有文字，删除/取消不只放图标 |
| 动效 | 只用于展开、状态切换等短反馈，约 120–180 ms；支持减少动效 |

角色与内容共存：聊天头部有小头像和姓名，空会话可以有轻量角色欢迎区，开始对话后收敛；不让大插画长期占据聊天空间。内置静态 PNG 作为默认，设置页允许用户导入头像和静态桌宠形象；不将 Live2D 或新生成角色美术设为本轮前置条件。

首轮实现暖色亮色主题，颜色集中为 tokens，后续深色可扩展；本轮不以多主题数量替代交互质量。使用现有 PySide6 Widgets + QSS/委托绘制，不引入 WebView/Electron 重写产品。

### 通用交互

- 控件全部使用中文显示标签；内部枚举不直接展示。空态解释下一步，失败信息附可执行动作。
- 聊天、列表、详情各自拥有滚动区；输入区固定在聊天底部，不把整个页面包成单一长表单。
- 新消息到来时，若用户正在底部则跟随，否则显示“有新消息”，不打断向上阅读。
- 内容不解析可执行 HTML，链接不自动打开，外部内容不成为按钮或命令。代码块可复制。
- 窗口、键盘焦点、选中、不可用、保存中、保存失败均有可见状态。
- 所有 ComboBox、SpinBox、Slider 禁用滚轮改值，包括获得焦点时；展开下拉框的滚轮只能滚动列表，点击/明确键盘确认才选中。滚轮事件向滚动容器传递，不吞掉页面滚动。

## 5. 桌宠与小对话窗

### 操作规则

| 动作 | 行为 |
| --- | --- |
| 左键单击角色 | 打开/收起小对话窗；打开时默认日常聊天，保留尚未发送的该会话草稿 |
| 拖动角色 | 超过系统拖动阈值才移动，松开不触发点击；保存位置 |
| 右键角色 | 打开紧邻角色的快捷菜单，屏幕边缘自动避让 |
| 小窗“展开” | 打开主窗口并定位同一会话、同一任务，不能重复提交消息 |
| Esc / 关闭小窗 | 隐藏，不结束会话、不取消任务；草稿在当前进程保留 |
| 点击小窗外 | 可隐藏非固定小窗；有未提交授权或草稿时内容保持，下次可恢复 |

右键菜单只保留 **聊一聊、打开主窗口、收起小窗、暂时隐藏桌宠** 等窗口动作，不包含大小、置顶、穿透、静音或跳转设置项。首轮的右键快捷设置方案按本轮用户要求撤回；这些配置统一迁入设置。“暂时隐藏”不修改持久启用偏好。

缩放范围建议 60%–160%，默认 100%，提供 80/100/120/140% 预设和可拖动滑块；不支持滚轮缩放。预览实时，拖动结束后保存。图片、命中区域、位置约束一起变化，状态文字保持可读，不随角色无限缩小。设置中提供“恢复大小与位置”。

仅在设置中开启/关闭鼠标穿透。托盘只提供“打开主窗口”和“退出”等窗口动作；用户打开主窗口后从设置导航关闭穿透。设置操作旁说明恢复路径，不在托盘另造配置开关。

### 小窗内容

小窗建议宽 360–420、高度随内容到约 520 的上限，受可用屏幕尺寸限制：

1. 标题：角色名、当前会话名称、会话切换、展开、关闭。
2. 正文：最近消息、当前任务卡、提醒结果；更早记录分页加载或在主窗口查看。
3. 输入：最多数行自动增高，Enter 发送，Shift+Enter 换行。
4. 简单授权：完整显示提醒时间、内容等必要参数，原地确认。
5. 复杂授权：展开同一审核组件；若参数、文件内容、多个步骤无法在小窗充分审阅，点击“展开审核”，主窗口打开对应卡片并保留选择。不给看不到完整范围的“一键同意”。

小窗是正常可获得输入焦点的独立窗口；角色画布仍可不抢焦点。不能直接向当前 `WindowDoesNotAcceptFocus` 的角色窗塞文本框。

未主动打开小窗时，到期提醒/回复只给有限提示和角标，不主动显示完整私人消息。小窗关闭后不进行独立聊天轮询，任务和提醒仍由应用服务继续管理。

## 6. 对话、长期会话与记忆

### 会话类型

- **日常聊天**：首次初始化原子创建且只有一个，固定置顶，后端拒绝删除或归档。清空聊天后仍保留同一入口。
- **专项会话**：用户命名，或以首条消息本地裁剪生成可改标题，如“整理项目资料”；支持重命名、归档、恢复、删除。关闭窗口不删除记录。
- **独立请求**：保留给现有 CLI/接口的无历史请求，不在 GUI 聊天再增加模式选择器。必须明确说明是否仍保存任务记录，不能称为隐身模式。

旧“同时最多四个临时会话”改为持久目录分页和有界热缓存。缓存淘汰只能触发重新读取，不删除会话。默认会话可以长期保存，展示端分页；模型每次仍只读预算内有效上下文，不承诺把所有历史放进模型。

### 三类数据的区别

| 数据 | 用途 | 默认范围 | 清理含义 |
| --- | --- | --- | --- |
| 聊天记录 | 用户跨重启浏览消息与任务卡 | 所属会话，本地持久 | 清空后不再用于该会话上下文，处理相关来源依赖 |
| 模型上下文 | 当前回复的有限输入 | 仅当前会话，受来源/用途/预算约束 | 缓存过期可从仍有效记录重建；隐私撤销后不能重建被阻断内容 |
| 长期记忆 | 稳定偏好、已认可信息与允许的事件 | 会话共享，继续受原有来源权限约束 | 显式更正或遗忘；普通聊天记录不自动全部转为长期记忆 |

专项会话不自动看到其他会话原始聊天，只能使用允许共享的长期记忆。人格全局共享；会话临时风格覆盖只能在设置内选择目标会话并明确“仅当前会话”，不会静默改全局人格。聊天中的本次表达要求仍可作为请求意图，但不生成另一组配置控件。

清空记录与遗忘记忆提供独立选项；存在依赖关系时先展示实际影响范围。不能一方面声称“全部忘记”，一方面保留可重新检索的任务正文副本。旧备份、导出和已发云端内容按现有边界单独说明。

### 发送与回复

- Enter 发送，Shift+Enter 换行；输入法正在组合文字时 Enter 只确认候选，不发送。粘贴多行不自动发送。
- 点击发送立即出现本地“正在发送”占位；只有收到持久受理回执才显示“已发送/排队”。失败保留原文并允许明确重试。
- 每条请求有独立的后端任务和状态；普通聊天显示消息与轻量进度，不把每句话都展示成任务卡。审批、需追踪的工具操作和副作用结果使用任务卡。切页、切会话、小窗展开不改变归属；后台回执写回原会话，不依赖当前选择。
- 同会话允许继续输入，按受理顺序处理。上一轮等待授权时，后续普通聊天可以继续，但前一计划仅作为待确认草稿，不能当作已完成事实。
- 不伪装流式生成；后端尚未提供流式能力时显示“正在思考”和最终回复。
- 用户消息/助手回复/任务事实分开显示。任务失败而表达服务也失败时，仍能看见可靠工具结果及可理解的降级说明。

## 7. 任务与授权：在对话中办完

以“20 分钟后提醒我喝水”为例：

1. 请求出现于原会话，依次显示“正在发送 → 正在理解”。
2. 持久计划进入 Waiting 后，原消息下出现“喝水提醒 · 等你确认”。
3. 卡片显示实际计划中的提醒内容、时长/时刻、时区、执行影响和授权范围。相对计时若实际从执行时起算，明确写“执行成功后 20 分钟”，不能伪造一个已确定时刻。
4. 普通单步提醒使用明确动作“允许创建提醒”；按钮点击本身就是对完整已展示普通工具集合的显式授权，无需勾一个技术工具名再点另一按钮。拒绝用“取消这个请求”。
5. 多工具计划先展示所有步骤，按钮“允许本计划列出的操作”；高风险工具独立显示且默认未选，要求额外明确勾选。未满足全部必要授权时不启动执行，并在本地及服务端说明缺失项。
6. 确认后卡片进入“正在提交确认”，禁用重复操作。收到受理回执显示“确认已受理，等待执行”，不能直接显示“已完成”。
7. 可靠成功后卡片变为“提醒已创建”，显示真实到期时刻和“查看提醒”。不再残留授权复选框。
8. 到期时同会话增加提醒事件，安排页显示“已到期”；可给桌宠角标和系统通知。系统通知关闭或应用已退出时，明确展示实际可用的提醒渠道。

### 审核卡结构

```text
喝水提醒                         等你确认
执行动作    创建一个计时提醒
提醒内容    喝水
触发时间    执行成功后 20 分钟
通知方式    应用内提醒（系统通知未开启）
作用范围    本次计划中的 1 次提醒创建

[允许创建提醒]   [取消这个请求]   [查看完整步骤]
```

多步骤不能只显示摘要而隐藏实际参数。文件读写显示文件路径、覆盖方式和内容预览，删除显示完整对象范围；长参数可在结构化详情展开查看，内容过大时显示有界预览与专用全文查看。未识别的字段以中文/原字段名的键值结构完整回退展示，不丢弃、不误称无需授权。

工具名、任务 ID、plan hash、契约版本保留在“技术详情”，用于排错与审计，不作为普通列表标题。技术详情仍是纯文本，不允许用户编辑后覆盖原计划。字段翻译和风险说明由可信工具目录维护，模型不能决定授权文案或风险等级。

**权限语义不变**：仍是绑定原计划的工具名级授权；同一工具在计划中调用多次时必须列出所有调用。卡片不是逐路径、永久许可或全局白名单。要调整参数，创建新意图并展示新计划，不暗中修改已经审阅的计划。

### 状态与可操作内容

| 后端事实 / 交互态 | 用户文案 | 可用动作 |
| --- | --- | --- |
| 请求尚未受理 | 正在发送 / 发送失败 | 失败时重试，复用命令标识 |
| Created / Planning | 排队中 / 正在理解 | 请求取消 |
| Waiting 且可审阅 | 等你确认 | 明确允许、取消、查看步骤 |
| 确认提交中 | 正在提交确认 | 禁止再次确认；保留取消入口 |
| 确认已受理且尚未执行 | 等待执行 | 查看进度、请求取消 |
| Running | 正在处理 | 请求停止后续步骤，不能承诺撤回已有操作 |
| Completed | 已完成 / 提醒已创建 | 看结果，无授权控件 |
| Failed / Cancelled | 未完成 / 已取消 | 看原因和已产生的效果；不自动重做 |
| NeedsReview | 需要重新查看 | 解释原因，重新获取计划并明确确认 |
| Uncertain | 结果需要核实 | 查看步骤与人工证据，不提供直接重试原计划 |

任务中心与两种聊天窗口共用同一任务状态和授权组件。当前计划已变化、权限被撤销或会话被清理时，旧控件立即失效，显示具体原因。

## 8. 设置整合与人格体验

| 分类 | 内容 | 修改反馈 |
| --- | --- | --- |
| 人格与表达 | 角色名、平衡/温暖/简洁预设、自定义维度、回复详略、幽默、追问、临时风格、模拟情绪开关 | 显示影响范围；保存成功后才更新权威状态 |
| 桌宠与外观 | 用户/角色头像、桌宠静态图片、启用、大小、置顶、穿透、位置重置、小窗行为、减少动效 | 本地素材导入与预览，后台保存成功才应用；失败保留旧形象 |
| 通知与打扰 | 到期提醒、待确认、回复提示、系统通知、静默时段、托盘/关窗行为 | 明确哪些渠道开启，模拟情绪不改变这些开关 |
| 记忆与隐私 | 记忆模式、聊天存档说明、云用途分类许可、清空会话、遗忘、数据范围 | 高影响操作给具体范围回执 |
| 模型与连接 | 默认云模型、本地模式切换、服务地址、模型名、API 密钥输入/替换、有效凭据来源、连接状态 | 密码框一次性提交后台，保存与生效分开；不回读已有密钥 |
| 工具与插件 | 插件配置、未来能力启用状态、连接凭据管理 | 只展示后端实际支持的配置，查看目录不授予执行权 |
| 数据与高级 | 备份恢复、模型缓存、维护入口、诊断、技术详情 | 沿用独立维护生命周期；显示切换过程 |

人格维度在普通页面用有含义的两端标签，如“简洁—详细”“克制—活泼”；精确数值放高级展开。模拟情绪说明它影响表达与桌宠表现，不制造“真实情绪”或关系分数的承诺。关键任务状态始终优先于情绪图。

用户在聊天中明确说“这次回答简短一点”仍可作为本轮意图处理，但聊天不出现人格编辑、范围选择或保存全局偏好的配置控件。需要持久保存的表达偏好候选集中“设置 → 人格与表达”审核。称呼、语言等原有画像候选作为记忆内容继续在记忆页审核；这属于记录管理，不是另一个设置面板。重复偏好语义明确领域权威，避免互相覆盖。

聊天输入区取消“本次数据用途”和本地/云选择器。新安装默认云模型，用户在“设置 → 模型与连接”一次配置服务与密钥，普通新消息按已保存的云处理选择提交；模型未配置时给出“请先在设置中配置模型”的静态说明，不弹出每条消息的重复问询，也不在聊天嵌入配置快捷按钮。

执行位置（云/本地）和数据用途是两层状态：原有仅本地来源、记忆和类别许可继续有效，切云不追溯放宽旧数据。若本条请求绑定不可出云的来源则明确阻断并说明原因。用户可在设置中改变后续请求策略；不能静默上传受限来源。已显式配置本地的旧用户保持原选择。`offline` 固定示例单列为高级“离线演示”，不能冒充本地推理模型。

首次使用在设置内呈现模型配置引导，默认选中云模型；没有密钥时保留聊天壳和持久记录可访问，发送按钮说明未就绪，不直接退出应用。后端配置工厂相应支持未就绪的设置阶段，不能靠伪造密钥启动生产模型。旧用户的人格、桌宠、模型选择和既有数据许可保持原值。

### 图片导入

设置中的头像和桌宠采用独立槽位，支持 PNG/JPEG、预览、替换、恢复默认。头像可分别设用户和角色；桌宠至少支持一张主形象，思考/专注/愉悦/提示等静态差分可选。缺差分时用自定义主形象，不突然切回内置机器人；重要状态仍用文字表达。

“上传”在本地桌面产品中是选文件并导入应用管理目录，不上传到模型服务。预览/裁剪方式、大小限制、保存状态和失败原因明确可见；原文件不修改，导入后移动原文件不影响使用。桌宠透明 PNG 效果最好，JPEG 允许使用但提示会保留背景。详见[素材接口](settings-assets-and-tools.md)。

### 工具插件目录

工具插件页显示分组列表/搜索与详情：名称、用途、来源、版本、当前可用性、所需权限、典型输入输出以及失败原因。普通用户无需阅读 JSON schema。用户可理解“创建计时提醒”需要确认、“读取文本”受工作区限制。

首期读取真实已注册的可信内置工具；不把“现有工具目录”包装为已支持第三方安装市场。后续外部插件、连接器可复用目录条目和能力接口；安装、连接、启停等配置只在设置中，并且只有后端实际支持时才显示。查看详情不执行工具，不授予永久权限。

## 9. 本轮边界与完成标准

本轮必须同时交付：持久会话、原地授权与回执同步、统一设置、可读的业务详情、桌宠小窗/缩放、输入与滚轮规范、提醒到期展示、完整视觉层，以及本轮追加的默认云模型/密钥配置、头像与静态素材导入、可扩展工具插件目录。

保留当前单实例、单 Core dispatcher、Tool Manager/Sandbox、用途和来源限制。桌宠小窗不启动第二个 Agent；持久聊天不恢复执行权；重启不自动重放工具。

不自行恢复已搁置的 Live2D、V0.6 隔离执行、无人值守/精细授权，以及 HM08 真实模型追加实验。对这些边界的清晰展示属于本轮，改变其能力不属于本轮。

体验验收以一条完整路径为中心：**启动 → 日常聊天 → 发提醒请求 → 原地确认 → 看真实结果 → 切页返回 → 重启保留记录 → 到期得到可见提醒**。另覆盖专项会话、清空/遗忘、复杂授权、失败、中文输入法、多屏和鼠标穿透恢复。具体清单见[实施与验收](implementation-and-acceptance.md)。
