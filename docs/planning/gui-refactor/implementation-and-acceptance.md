## 2. Agent 与工作区约定

- 主 Agent：理解需求、产品/技术设计、任务边界、架构和权限审查、整合、最终交付。
- 关键编码：6.1 Sol，高思考；不要把设计决策整体交给子 Agent。
- 简单固定检查：6 Luna，高思考；失败保留证据交回，不修改断言、扩大授权或跳过问题。
- 子任务写明目标、允许修改文件、接口依赖、禁止触碰范围、开发/测试阶段、交付证据。使用工具的真实模型/思考设置，不只在消息中口头声明。
- Git 由用户提交，禁止自行 stage/commit/push。接手时工作区已有文档、脚本等未提交改动，不能覆盖或清理；本轮只新增设计目录并小幅补导航。
- 不读取真实密钥或生产数据库做试验。测试夹具使用临时 data_dir；真实模型请求及原有暂缓实验不是普通 GUI 回归的前提。

### 建议编码任务切分

1. **会话与隐私基础**：conversation/workflow/application 会话相关代码和迁移；先交 DTO 及数据库契约，再编码。备份版本适配由同一任务或明确后继负责，不能遗漏。
2. **任务审核与提醒**：task_review/confirmation/reminder 及 facade 操作；共享 service/desktop 的改动须由主 Agent 协调串行整合。
3. **主界面与桌宠**：GUI shell/state/components/settings/pet；在接口明确后交 Sol 实现，复杂小窗复用共用组件。
4. **机械验证**：测试阶段由 Luna 按主 Agent 给出的固定命令和样本执行，失败交 Sol/主 Agent 定位。

上述切分是后续执行计划，本轮没有启动生产编码子任务。

## 4. 测试执行规则

本轮是设计阶段，不运行 pytest、mypy、实机 GUI 或真实模型测试。文档阅读、静态证据核对与设计示意不等于产品测试。

后续开发交付时，提供已经存在的测试文件名与确定命令，再按用户启动测试的指令执行。基本命令遵循[开发约定](../../guides/development.md)：`python -m pytest`、`python -m mypy --strict src scripts/check_memory_api.py scripts/benchmark_memory.py`；GUI/容量脚本按[开发者验证指南](../../developer-guide/development-and-testing.md)选择与改动相关的最小集合。

先做新后端状态/迁移与定向 GUI 检查，再运行必要回归；无需无变化反复跑全仓。固定执行交 Luna，归因和修补交 Sol/主 Agent。

证据记录必须包含：环境、命令、退出码、通过/失败/跳过/未执行、首败原因、修补文件、复测范围。Qt offscreen 只能证明组件行为，不能证明真实 IME、Windows 焦点、托盘通知、DPI 和鼠标穿透；物理桌面单列人工结果。
