## 已冻结的集成方向

- 工作库迁至 schema3，统一纳入会话、素材和提醒投影表；不新增第五个业务库。
- 会话摘要同时提供 `context_epoch` 与兼容字段 `epoch`；`submit` 保留 `expected_conversation_epoch` 并支持明确的新字段。
- 生成模型的执行位置与协议分离，应用层使用 `config.llm.is_cloud` 判断用途；本地 embedding 配置不随云聊天默认改变。
- 素材槽位为 user_avatar、character_avatar、pet_main、pet_thinking、pet_focused、pet_pleased、pet_alert；正文通过专用图片通道，不进入普通 JSON 回执。
- GUI 不直接持有 SQL/Core，不读取密钥；维护和生产宿主不会同时持有 data_dir。

实际接口见[开发者说明](../../developer-guide/gui-refactor.md)和[整合契约](integration-contract.md)。当前没有产品测试通过结论。

## 开发中的源码审查记录

- 默认会话除禁止删除/归档外，也限制修改固定名称；服务与 SQLite 触发器共同保护，不能只隐藏 UI 按钮。
- 旧配置同时有环境密钥和凭据引用时，迁移必须保留原本实际生效的环境来源；新建配置再采用明确的凭据模式。
- 图片发布在创建目标硬链接后中断，会留下受控临时名和目标的双硬链接。增加有界、精确的暂存恢复，不放开任意硬链接；换图前回收无引用资源，防止正常换图累积触及容量上限。
- 清理提醒正文时保留资源到任务的非正文墓碑，用已 scrub 的任务阻断后续调度事件重新带回旧 label；只删除 UI 关联会使提醒作为“未关联来源”复现。
- Waiting 阶段的计划解释写入展示时间线，但不提前当作已完成聊天事实冻结给后续轮次；终态表达可以更新同一条目。
- 持久上下文重建重新验证当前隐私屏障、会话版本与来源，不将旧任务执行票据当作历史内容永久可用的凭证。
- 同一任务可创建多个提醒，消息唯一约束应仅限制 user/assistant/task_card；提醒按事件身份单独去重。

这些是源码审查与相应实现调整，尚待 T1 行为验证。
