# Phase 05 实施记录

2026-10-30。主动协调、通知控制及多步任务暂停已完成代码和定向隔离验证；本记录末尾列实际证据及未验证部分，不把真实模型效果或原生实机视作通过。开发与测试代码由父 Agent 编写，机械测试由 6 Luna 高执行。

## 用户能看到的变化

主动关注不再逐条要求接受。安排页的“建议”改为只读“关注”，展示事项、依据、时间和处理状态；旧提议保留为可靠事件接收和历史兼容资料。普通主动聊天从协调器提交，经唯一 Dispatcher 进入 AgentCore，允许正常回答、调用已有工具、安排复查或安静结束。安静不生成空消息；主动消息不会伪装为用户消息，后续聊天只把它作为助手的历史表达。

主窗与桌宠小窗共用任务卡，提供暂停、继续和追加要求。请求暂停后显示“正在暂停”；已开始的模型／工具调用及已决定的步骤组可以完成，到下次模型判断前保存结果并变为“已暂停”，释放执行线程。继续使用同一任务和累计预算，模型读取实际结果、最新有效角色与会话背景及追加要求；不重放已完成操作。授权等待单独保留。恢复后先让模型重新判断未执行意图，旧未执行步骤只在新快照中退出，原计划字节保留；任何新操作仍重新确认，继续不等于授权；取消后的任务不可继续。若已直接进入最终收尾，仍按原同步学习顺序完成并如实显示终态。

聊天窗口“通知”菜单分别控制主动聊天和提醒，聊天内也通过同一策略服务落实有期限的要求。暂停不删除日程、不取消任务、不修改系统权限。提醒不依赖模型批准，暂停期间正常到期并保留收件箱状态，恢复不补弹；通知最终校验再次检查策略。

## 模块与执行边界

`proactive/coordinator.py` 管理机会和有界登记，内置事件、模型复查、交流机会、低频整理四类方法，使用内部注册表增删可信方法，不引入插件执行框架。停用方法取消未处理关注，发布前重查有效状态。既有 `LocalRuleEngine` 的日程／计时器 cursor、身份、锚点和来源检查复用；同一实际目标／里程碑在同一 15 分钟窗口的事件合并来源后再检查，不按语义关键词猜测同一事项。规则只报告机会，含义由模型理解。新机会不会让主动模型自述成为新的用户事实。

协调器不调用模型。普通交流进入 Core，纯内部整理排入同一 Dispatcher 调用 P4 反馈模块，已约定提醒继续由调度履约。用户工作优先，已经开始的整理不自动让位；协调器不建立第二个 Agent。后台仅存在于当前激活档案，关闭和切换沿 P1 生命周期执行。

当前内部预算为主动交流最短间隔 15 分钟、每档案 24 小时最多 16 次检查；同一真实来源的模型复查每天最多安排 4 项，单项只在无工具执行且模型明确临时失败时有限重试，最多 3 次。复查时间至少延后 15 分钟，关注窗口最长 7 天。普通主动聊天遵守已有静默时段；内部整理不发消息，检查间隔至少 6 小时，读取有界的缓冲、争议和已采用理解，没有新修订或到期复查要求时不重复调用。整理完成后的自身修订记入基线，避免自我变化再次唤醒。上述是资源预算，不是对事实确信度或用户空闲的规则判断。

主动工具范围由程序限制：可进行可信只读查询、安排或结束关注；涉及明确用户意图的记忆／角色修改、通知和任务控制不授予主动任务。对外实际操作仍遵守已有工具契约与准确授权。角色性格、关注理由和上一步工具许可都不能扩张权限。来源发生更正、遗忘或失效时阻止旧任务继续；待处理关注的派生正文也参与清理。

## 数据库与接口

工作库正式从 schema 4 升级为 **5**，角色库 4、记忆库 3、日程库 1 保持不变。新增表由 `workflow/schema_v5.py` 定义，在 `WorkflowStore` 的升级事务内创建和校验，不由服务临时建表。旧计划、步骤结果、消息及角色资料不重写。升级前保留已有备份行为；Windows 的工作库备份采用不覆盖目标的原子 rename，其他平台继续 create-new hard link。归档只读检查支持 schema 5，不在查看备份时迁移。

| 新记录 | 内容 |
|---|---|
| `task_control`、`task_control_receipt` | 暂停意图、实际检查点、累计处理耗时和命令去重；任务本身新增非终态 `Paused`。 |
| `notification_policy`、`notification_policy_receipt` | 主动聊天／提醒分别保存暂停、恢复时间及修订；命令可核对、重复不再执行。 |
| `attention`、`proactive_method`、`proactive_meta` | 关注理由、实际来源列表、时间窗口、触发方法、尝试次数、关联任务、处理状态及频率／整理恢复标记。 |

| 应用接口／工具 | 用途 |
|---|---|
| `task_pause`、`task_continue` | 独立控制通道，立即登记意图；不排在被控制的任务后面。 |
| `notification_policy`、`notification_control` | 查询或调整通知策略，主窗和小窗共用。 |
| `attentions` | 有界、可读关注列表，不暴露完整原始来源正文。 |
| `task_list`、`notification_status` | 模型读取实际任务编号／状态与通知范围，不猜编号。 |
| `attention_schedule`、`attention_end` | 模型有依据地安排复查或结束当前关注，不能充当工具授权。 |

暂停状态和已完成结果在重启后保留，等待用户明确继续。恢复前检查档案、会话 epoch、来源及权限，不能恢复已清空／遗忘内容，也不自动重置执行预算。原有未知结果和崩溃恢复屏障保留，不将任务暂停解释为任意位置都可安全重放。

## 验证记录

最终合并去重 **511 passed、1 skipped、0 failed／error（512 个唯一用例）**。包含 **36 项 P5 专项、29 项 GUI、342 项后端回归（341 passed＋1 skipped）、101 项配置及 4 项提醒回归**，重复复跑不累加数量。**36 个改动源文件 strict 检查通过**；后续修改的控制、日志协议、Core／loop 及反馈模块均再作相应 strict 复查。未运行全仓测试。

| 范围 | 实际覆盖 |
|---|---|
| 主动链路 | 实际工厂、Dispatcher、Core 与账本；真实来源的事件合并和去重，主动回答及安静，不生成假用户消息；后续历史只保留助手表达。 |
| 工具与边界 | 主动任务不能冒充用户修改角色／记忆；需许可的外部操作等待确认；来源撤销不继续，模型等待期间新增暂停阻止晚到消息。 |
| 通知与生命周期 | 主动聊天／提醒独立控制、定时解除和重启保留；无模型也能实际到期，暂停期间记录为错过，恢复不补弹；档案生命周期复用 P1 定向回归。 |
| 整理与频率 | P4 真实反馈复查保留候选，原话与理由可查，不额外发布聊天；无变化不重复；触发注册／停用只撤销对应机会，临时模型失败有限重试，配置错误不重试。 |
| 暂停与继续 | 步骤组完成后暂停，线程释放处理其他工作，追加不自行恢复；重启保留、取消后不可继续、累计预算不重置、清空来源不复活、落库失败不假报成功。 |
| 授权等待续接 | 原计划字节保留，恢复先判断修改后的目标；合成用例追加 new.txt、重新确认后真实写入且旧文件不存在，账本仅有一次实际写入。 |
| 同步收尾 | 无下一次判断时照常完成，不误报已暂停；内部整理模型等待时用户任务正常登记并排队，无自动抢占。独立任务反馈使用真实 single 归属，不误查空的持久会话摘要。 |
| 界面与存储 | 主窗和小窗共用状态及按钮，小窗无工具详情；关注可读、无接受入口；记忆旧测试适配树选择及右侧编辑后，可读面积与草稿断言保留。旧库 4→5 保留数据，缺表拒启，归档与旧库恢复回归。 |

首轮工具 schema 的联合类型不受既有校验器支持、执行日志协议缺少 origin、恢复的 Created→Running 非法跳转及无步骤 continue 检查点空回复，均已修正并复测；没有放宽计划校验。等待授权恢复时补齐“先再判断、退出旧未执行步骤”的行为。复核实际结果还修复了独立任务反馈的内部会话归属，36 项 P4 和 22 项 P3 再次通过。

回归中旧默认／schema 断言及 ReminderInbox mock 按新增接口更新；P2–P4 专项显式关闭 P5 后台触发以保持场景隔离，P5 独立覆盖自动调度。三项旧 GUI 测试使用了已退役 list／编辑按钮，改为现有树选择及右侧编辑，保留 140／170 像素可读空间、窄宽窗口、正文复制和草稿保存要求，17 项复测全部通过。

默认沙盒的合成硬链接探针返回 WinError 5，而放宽权限后的同一类合成探针成功。原备份／配置及真实文件工具回归因此使用获准放宽权限的独立临时目录重跑，配置、缓存、临时目录仍隔离，凭据变量清除；不通过 mock 文件写入、跳过用例或放宽断言解决环境限制。唯一跳过为 Windows 不允许创建合成符号链接的已有保护用例。
