# P5 验收：主动行为、整理、通知与任务暂停

状态：定向隔离自动化完成（511 passed、1 skipped、0 failed，合并去重）；真实模型效果及原生实机仍未验证。最终证据及场景范围见[实施记录](implementation.md)。依赖 P1–P4；对应[开发文档](development.md)。使用可推进的时钟、合成事件和临时档案，避免长时间真实等待；系统通知与实机另验证。

| 编号 | 场景 | 合格标准 |
|---|---|---|
| P5-01 | 到点的已约定提醒，模型不可用 | 提醒按策略履约，不等待模型批准；无普通主动消息冒充提醒。 |
| P5-02 | 多个事件涉及同一面试事项 | 合并成一次有界检查，不分别调用并重复关心。 |
| P5-03 | 模型决定安静或安排稍后检查 | 不强制发消息；后续检查有理由、时间和取消条件，不无限自我唤醒。 |
| P5-04 | 用户在复查前已说明结果 | 核对最新交流，取消或更新旧关注，不再重复追问原问题。 |
| P5-05 | 仅因用户没发消息而兜底检查 | 不认定用户空闲，不采集屏幕／摄像头；无未结有价值事项时安静。 |
| P5-06 | “今天别主动找我” | 普通主动聊天暂停，已约定提醒照常；重启后策略仍有效，到期解除。 |
| P5-07 | “连提醒也暂停，明早八点恢复” | 真正外发受控，日程仍保留；恢复按实际时间核对，未激活档案不自行弹出。 |
| P5-08 | 模型判断中用户暂停或切换档案 | 发布前再次核对，不越过新暂停、不把 A 的消息发到 B。 |
| P5-09 | 停用 A、推进时钟、切回 A | A 停用期间无检查、学习和通知；重开无积压消息补播，过期关注消失。 |
| P5-10 | 主动建议删除文件或修改安排 | 进入既有任务链，需许可时等待确认；不由主动模块直接执行。 |
| P5-11 | 主动整理一批缓冲，不需要聊天 | 调用 P4，实际合并／修正／清理可核对，不发消息也算正常完成。 |
| P5-12 | 无新信息的缓冲反复触发 | 不每次重审；重要不确定项不被固定过期规则清除，模型自述不充当新证据。 |
| P5-13 | 停用一个触发方法 | 其未处理检查取消；真实日程、记忆和已执行事实不被删除。 |
| P5-14 | 事件重复投递、重启后恢复 | 检查、通知和操作不重复；幂等回执和实际收件箱可核对。 |
| P5-15 | 模型提出很快下次检查或整理失败 | 统一频率和调用预算有效，有限重试后止步，用户沉默不触发反复催促。 |
| P5-16 | 集中整理已开始时收到用户请求 | 允许等待当前调用结束，无自动抢占要求；新任务后续正常受理，无同队列同步等待死锁。 |
| P5-17 | 普通主动检查，分别返回聊天、安静、需工具 | 记录证明均经 Dispatcher 进入 AgentCore，协调器未直接模型生成后发布；来源明确非用户指令，安静无空聊天，工具仍按任务用途与许可执行。需要学习时同步反馈在发布前完成。 |
| P5-18 | 模型或工具执行中请求暂停，包含一组已决定步骤 | 立即登记并显示“正在暂停”；当前调用及步骤组允许完成，下次模型判断前实际转为“已暂停”，不再调用下一轮模型或工具，不强行中断或回滚。 |
| P5-19 | 已暂停任务期间追加要求，再明确恢复 | 追加要求本身不续跑；恢复使用原任务标识，模型看到实际结果、新要求及最新状态；已完成步骤不重放，累计预算不重置。 |
| P5-20 | 暂停后重启或切换档案再切回；暂停期间处理另一任务 | 暂停及进度持久保留，不自动续跑、不串档案；原执行线程已释放，其他工作可正常调度，不因暂停持锁等待。 |
| P5-21 | 等待授权时暂停后恢复，或恢复时来源已更正／清除 | 恢复先让模型核对尚未执行的意图，原计划字节保留，退出旧未执行步骤；不等于授权，不执行未经确认的新内容；来源与会话有效性重新核对，旧结果不能绕过清空／遗忘检查。 |
| P5-22 | 重复或并发暂停、恢复、取消，任务已完成时收到暂停 | 去重与状态转移可靠，无双执行者或终态复活；已暂停可取消，取消后不能恢复；已完成如实返回终态，未到暂停边界不假报已暂停。 |
| P5-23 | 已进入最终同步整理收尾时请求暂停 | 没有下一次行动判断时允许依既定顺序正常完成，如实返回终态，不强行抢占整理；新增聊天也不自动触发任务或学习让位。 |
| P5-24 | 暂停状态落库失败，或与通知暂停交替操作 | 保存失败不假报暂停成功、不丢已执行事实；任务暂停不误改提醒／主动聊天策略，通知暂停不冒充任务暂停。 |

## 真实效果及实机

获准真实模型后，测试共同准备事项、结果已告知、忙碌时暂缓、无需表达的纯整理等场景。评估主动内容是否依据真实资料、是否重复、是否尊重明确范围；不以“调用了模型”证明时机合理。

实机检查系统通知权限、主窗与小窗入口、快捷暂停、恢复和日程导航。暂停成功查策略和实际外发，不只看回复。模拟调度通过不能替代 Windows 系统通知验证。

另核对多步任务的暂停／继续入口：主窗、小窗状态同步，“正在暂停”与“已暂停”明确区分；暂停期间追加、恢复、取消及授权等待呈现一致。核对暂停后真实调用停止于约定边界、恢复沿原任务继续，不能只凭按钮文案判断通过。这些新增场景使用 P5 独立证据，不沿用 P3／P4 的通过结果；原生实机部分仍未验证。

回归参考：`tests/unit/workflow/test_local_proposals.py` 以及现有提醒、调度和桌面通知覆盖。旧“所有普通建议都必须人工接受”的断言按三类动作调整，工具许可断言保留。

退出条件：可靠提醒、普通主动、实际操作和内部整理四条路径清楚，所有适用场景有记录。重复通知、越过暂停、错档案消息、未授权操作或自唤醒失控阻断交付；未执行实机／真实模型部分标未验证。
