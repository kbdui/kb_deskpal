# Phase 03 实施与验证记录

2026-10-29。父 Agent 编写全部源码和测试代码，6 Luna 高执行测试，失败由父 Agent 归因和修补。依据重设计讨论、十项补充结论及本阶段开发／验收要求实施。P4 自动学习与 P5 主动触发、通知暂停策略仍待后续开发。

## 多轮执行与持久记录

`AgentCore` 通过 `agent/loop.py` 执行“判断 → 当前操作组 → 真实观察 → 下一次判断”。独立操作可以分组，有结果依赖的操作留到后轮；成功和失败都作为观察提供，工具正文明确标为外部数据。宿主生成每个步骤的稳定编号，跨轮编号不碰撞。对有副作用的相同工具及规范 JSON 参数阻止重复执行；可信只读工具允许再次查询。此去重不会自动撤销已经完成的操作；需要明确再做一次时可另建任务。

原 `immutableplan` 保留首份计划，`decision_round` 逐次追加累计快照；旧字节和执行记录不被覆盖。最新快照只供尚未执行的步骤续办。`task_call_attempt` 保存规划用途的逐次调用，`model_decision_attempt` 审计关联判断轮次、尝试与观察数量。`context_history` 保留被替代的输入快照；已记账的角色修改和记忆更正会建立新的有效来源，而不是继续使用旧资料。记忆更正沿既有契约产生替代 ID，当前依赖同时切换 ID 和修订。工具查询记忆也登记真实依赖和用途，旧仅本地资料的派生回复保持仅本地。

执行记录有 Started／Succeeded／Failed／Uncertain。`ToolResult.outcome` 默认 `known`，可信工具可以返回 `unknown`；未知结果立即收敛为 Uncertain，不再规划或重放副作用。取消仍在既有安全边界检查，不要求每个工具都能中断；不可中断调用返回后保存真实结果，再停止后续。恢复遇到 Started／Uncertain 不自动重做；完整记录且等待新一组许可的任务可重新审核，只执行未完成组。

预算为初始判断之后最多 8 次观察后再判断、规划用途总计 24 次尝试、总工具步骤沿现有 `max_tool_steps`（默认 8），180 秒协作式执行窗口；来源更新也有持久快照，恢复时其计数使预算更保守。不可中断的调用依赖其原有超时，180 秒不是线程强杀。每次判断最多重试两次，只有明确的 `RetryableLLMError`（超时、临时连接故障）可重试；配置错误不盲重试。重试只重新调用模型，已记账工具不再执行。输入继续受已有字节预算约束。

## 判断、补充与权限接口

模型可以返回工具调用，或正文；无工具时还支持 `{ "action": "answer|clarify|quiet", "reply": "正文" }`。澄清进入独立的 `AwaitingInput`，不混入 Waiting 许可审批。`task_answer(task_id, content, command_id)` 为同一任务登记回答并续办；重复 command_id 不重复排队。主窗与桌宠共享任务卡均显示实际问题和“补充回答并继续”。普通聊天没有必须执行的工具步骤。

`task_append_requirement(task_id, content, command_id)` 走 Bridge 控制通道，仅登记内容、顺序和真实任务归属，不等待工作队列结束。下一次模型判断采用已经登记的修改；已经决定的独立操作组可以完成，不逐工具抢占。最多 64 条、单条 8 KiB、合计 32 KiB。已收尾任务明确返回未接受；最后一次判断之后才到达的要求保留未消费记录，并在结果警告中说明未纳入本次执行。主窗和小窗均有“追加要求”。

每个新操作组重新检查 Tool Manager 的实际权限。之前允许相同工具，不会授权下一轮的新参数。Waiting 保存本组准确参数，确认必须匹配最新计划哈希；参数变化或旧哈希不能沿用。重启后不恢复旧进程授权。计划详情只列尚未执行步骤，历史结果另行保留。

| 操作 | 当前风险与权限 |
|---|---|
| 时间、文件读取／搜索／分类、记忆检索、角色读取 | 自动；仍校验参数、来源、工作区及字节上限。 |
| 当前档案日程／计时器创建、修改、取消 | 普通本地管理，自动执行；契约版本改为 2，旧计划权限条件变化会阻止继续使用。 |
| 明确记忆保存／更正／遗忘、角色卡修改、取消其他任务后续步骤 | 自动管理；CAS、真实来源和隐私清理仍生效。 |
| 工作区文件写入／复制／移动等 | 保持各工具现有许可与路径检查，不由模型决定风险等级。 |
| 文件删除等高风险操作 | 保持高风险许可，准确展示参数后明确同意。 |

## 内部管理与后续阶段边界

注册 `memory_search`、`memory_remember`、`memory_correct`、`memory_forget`、`role_read`、`role_update`、`task_cancel`。经同一 Tool Manager 校验和执行，适配现有领域能力，不在运行中的 Core 中调用需要等待 worker 空闲的管理入口。日程与计时器复用原工具。移除聊天“记住”前缀的直接保存分支，CLI `--tool` 转为交给模型理解的结构化请求；界面的显式管理按钮继续直接调用管理服务。

`memory_forget` 复用现有隐私屏障与删除作业。Pending 仅表示已接受；屏障会撤销旧上下文，旧 epoch 的 `wait` 回执也会被拒绝，随后由安全边界完成清理，不强行使用已撤销资料生成成功回复。新历史快照另存删除用的来源索引，旧记忆只留在审计副本中时，明确遗忘也能找到并清理这些副本。详细的学习缓冲与派生理解整理仍在 P4 接通。角色卡调整后，下一次判断和最终表达读取同一新版本，不伪装为自动学习。

`TurnFeedback.finish` 是 P4 的同步收尾契约，直接在唯一 worker 中调用，位于终态提交及回复发布之前，不排回自身队列再等待。可记录警告；整理失败不会回滚实际工具结果或无限扣住回复。目前没有据此声称新的自动学习已启用。

`submit_proactive(goal, basis, command_id)` 是 P5 协调器接入 Dispatcher／Core 的内部入口。任务持久标为 proactive，包含真实依据，没有用户消息和默认工具许可。只有这种来源可以 quiet 结束，保存工作状态而不生成空聊天。当前没有实现 P5 的触发器、关注安排、发布前暂停策略或通知管理工具，也不会用固定“已暂停”回执冒充这些功能。
