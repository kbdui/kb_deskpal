# P3 开发：多轮执行与内部管理接口

日期：2026-10-29。状态：代码与定向隔离验证完成；真实模型与原生实机未验收。实际接口、预算、权限和结果见[实施记录](implementation.md)。依赖 P1、P2；契约见[公共架构](../architecture-and-contracts.md)，验收见[本阶段清单](acceptance.md)。

## 目标

从静态整份计划执行改为“模型判断 → 操作 → 实际结果 → 再判断”。复用现有任务、工具管理与执行账本，接入内部管理功能，不引入第二个 Agent 或完整沙箱。普通聊天可直接产生草稿，所有聊天回复均经过表达润色，再走同步整理收尾；无工具不省略润色。

同一 Core 也接收 Dispatcher 转交的普通主动交流任务，明确区分来源、目标和依据，不伪装成用户新请求。模型可安静结束或安排后续关注，不强制生成聊天；实际发布前核对有效通知状态。主动调度与权限的完整路径在 P5 验收，纯内部整理和约定提醒按公共契约分流。

## 调用与执行契约

| 对象 | 必需语义 |
|---|---|
| 模型判断 | 提出一个步骤或互不依赖的步骤组、提出澄清问题、或形成最终回复。每轮消费真实观察结果。 |
| 模型调用记录 | 工作、用途、判断轮次、尝试序号和结果状态。网关及持久表同时解除“每用途只能调用一次”的硬限制，改为总预算。 |
| 步骤 | 稳定标识、参数快照、实际权限和执行状态。模型重复提出相同业务操作时结合账本判断，不仅靠随机 call_id 去重。 |
| 等待确认 | 保存具体待执行操作和参数；确认后执行原内容，之后新操作不能继承成全局同意。 |
| 澄清 | 保存待补充目标与上下文，用户回答作为明确续办资料；不把普通信息缺失混成权限审批。具体状态沿合法任务状态表扩充。 |
| 结果 | 成功、失败、无变化或未知明确区分，工具输出中的文本指令不能接管用户目标。 |

不得为了保持旧表结构，把新计划覆盖到一个已执行计划里。已有执行记录不可被新一轮模型判断改写。跨重启只恢复可靠的状态，不自动重做 Started／Unknown 的副作用。

## 主链路

1. 绑定档案、后台代次和会话，准备 P2 快照及已执行事实。
2. 在模型判断开始时，纳入已经登记但尚未采用的追加要求，记录本轮消费顺序。
3. 模型根据当前目标、角色、历史、记忆及结果选择下一步；程序检查结构、工具、预算与权限。
4. 需要确认则等待明确回执，其他合法操作通过 Tool Manager 或内部管理适配执行并记账。
5. 将实际结果作为观察资料送回下一轮模型，不把计划本身当结果。独立步骤可成组，依赖结果的步骤不得提前猜参数。
6. 模型认为可完成时形成回复内容，调用反馈接口同步评估和保存缓冲记录；随后提交任务并发布回复。P4 完整实现反馈，P3 只定义并联调其契约，不把空实现当自动学习已交付。
7. 达到预算、取消、需要澄清或结果未知时，说明已经做了什么和剩余状态，不能用“完成”概括未完成任务。

## 内部管理能力

| 能力 | 实际执行归属 |
|---|---|
| 记住、更正、遗忘、检索 | 现有记忆服务；P4 对接新记录、缓冲与遗忘传播。 |
| 修改相处要求及角色资料 | 角色状态和范围管理接口；不允许任意 SQL 或修改他档案。 |
| 创建、修改、取消日程或定时器 | 现有调度管理工具；真实返回值决定是否成功。 |
| 取消任务 | 任务管理服务控制后续执行，不要求每个工具有 cancel 方法。 |
| 暂停／恢复普通主动聊天与提醒 | P5 通知与主动策略服务；P3 建立契约，不在服务未实现时只写一条“已暂停”。 |

界面和模型复用同一管理能力。操作名与参数在实施时冻结、文档化；普通记忆学习不逐条确认。形成工具风险清单：保留必要路径与参数检查，低风险操作自动完成，需许可和高风险操作按实际影响确认，不能让模型自报安全等级。

移除 `记住` 前缀直接绕过规划、CLI 明确工具绕过模型等用户聊天路径；显式结构化管理接口本身仍由界面／服务直接调用，不为每次按钮操作强加模型。离线演示仅用于可识别的测试或演示入口，不冒充真正本地模型。

## 追加要求与取消

独立短控制入口只登记任务关联、内容与顺序，不能等普通任务队列运行结束。下次模型判断读取；不增加逐工具追加检查。错过判断的要求允许当前步骤组执行完，后续判断再采用。任务若已收尾，回执明确该要求未纳入本次执行，不能伪造已经遵从；后续续办仍使用原会话记录理解。

正式取消沿任务层已有取消状态和执行边界停止后续工作。不可中断调用可以先返回，已完成操作保留；回撤由用户作为新任务发起。把自然语言修改与取消控制区分开，不能为了简化追加规则删掉既有取消检查。

## 失败、恢复与预算

规划总轮数、工具总步骤、调用时间和上下文长度都有内部上限；初始值沿现有配置扩展，实施时记录，不新增需要用户理解的复杂滑杆。模型输出错误不执行任何猜测参数。中间工具失败可回模型选择替代方法，但结果未知的外部副作用不盲目重试。

等待确认重启后重新核对参数、来源与当前权限，不重用旧进程授权。模型重试不重做已执行工具。调用网关、执行账本与持久任务状态同时改造，不能只改内存计数。

## 完成条件

P3 全部适用验收通过；明确管理操作从聊天到真实服务可核对，多轮调用和恢复不重复副作用。交付新输出协议、状态转换、调用预算和权限表，列出 P4/P5 才完整实现的接口，不宣称桩响应就是交付。
