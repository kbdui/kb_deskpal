## 全阶段共同遵守的决定

1. 每个角色有完整独立档案，所有数据库与必要资源随档案切换；关闭旧后台后才打开新后台，未激活档案不运行。
2. 同档案长期记忆跨会话可检索；会话临时要求按自身范围生效。人格和记忆唯一连续，备份不成为人格版本选择器。
3. 五层业务含义为长期人格、当前情绪、对用户状态的理解、当前互动方式、表达调节；撤掉旧独立互动状态模型及重复状态路径。
4. 角色卡和学到的习惯参与理解、规划与表达。语义判断交给模型，程序落实归属、参数、权限、时间、保存和去重。
5. 多轮观察实际结果后再决定下一步；工具事实与模型建议分开，不重复执行已完成的副作用。
6. 本轮同步顺序为生成回复内容、自动记忆评估并保存缓冲记录、提交任务并发布回复。整理失败有限重试，耗尽后不扣住已有实际结果。
7. 缓冲仅有已确认的五项业务内容；理由由模型写，真实消息关联由程序保存。没有独立人工候选待办或复杂证据关系网。
8. 追加要求由独立入口登记，仅在下一次模型判断采用；不增加逐工具的追加要求拦截。正式取消仍由任务层停止后续工作。
9. 不要求每个工具都能中断或撤销；已完成操作保留，需要回撤时用户另行请求。
10. 清空聊天不动长期记忆；遗忘复用管理能力；删除角色清除完整档案；日程和任务取消按实际操作及权限处理。
11. 人格、普通自动学习和正常主动能力默认工作；缺少模型连接明确报错，不伪装为离线智能。模型连接默认面向云模型，本地连接留在设置中可选。
12. 2026-10-30 新确认的多步任务暂停／继续在 P5 接入，实际证据见该阶段实施记录。在下次模型判断前实际暂停，释放执行线程；恢复同一任务并采用最新状态和追加要求，不重放操作或重置预算。与通知暂停、取消和后台自动让位分开。

## 实施和交付纪律

用户明确要求修改代码或开始测试前，保持讨论和文档工作。执行测试时遵守[开发约定](../../developer-guide/development-and-testing.md)，本目录不自行授权真实密钥访问、真实模型调用、生产数据迁移或实机操作。

每阶段交付：实现与接口变更说明、涉及数据迁移及恢复方法、调用方清理清单、验收记录与未决项。使用[验收记录模板](acceptance-record-template.md)。未测试不得标为通过；离线固定响应不得证明真实语义效果。

现有测试和版本证据只能作为回归参考。需要修改旧断言时说明新的行为依据，不能删掉权限、去重或生命周期检查来获得通过。阶段验收失败时记录首败和实际修补，再作相应复测；不要求重复执行无关的大范围检查。

完整 OS 沙箱、Live2D、复杂逐类云端许可、绕过规划模型的快捷路由、学习自动让位、逐工具追加要求抢占、通用撤销框架、跨角色共享数据层和复杂插件执行框架。相关长期方向见[正式版后规划](../../roadmap/post-release.md)。现有工作区、凭据保护和必要执行权限继续保留。
