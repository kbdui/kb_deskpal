| 编号 | 场景 | 合格标准与证据 |
|---|---|---|
| P2-01 | 保存开放角色卡，重启并发问 | 角色卡完整可编辑、保存后可读，规划与表达输入均使用该档案同一版本的角色背景。 |
| P2-02 | 角色卡与当前问题没有字词重合 | 必需角色资料仍进入上下文，不受长期记忆相似度门槛影响。 |
| P2-03 | 助手提出甲、乙方案，用户说“第二种” | 规划输入有必要助手方案和用户当前选择；模型能定位乙，不能把助手建议自动视作已执行。 |
| P2-04 | 历史包含曾提过的删除要求，当前只问近况 | 历史可被理解但不重新发起删除，不凭旧聊天取得新执行权限。 |
| P2-05 | 会话 A 倾诉、会话 B 处理代码 | A 临时要求仅在 A 有效；B 仍能给适用方案。输入中的范围与查询结果可核对。 |
| P2-06 | 本次简短、当天少玩笑、以后少追问 | 模型正确给出适用范围；模拟时间推进后当天要求到期，单次要求不变长期人格。 |
| P2-07 | 用户说疲惫；角色刚共同完成任务 | 用户状态与角色反应分开，不自动将疲惫复制为角色悲伤；本阶段可通过显式有效状态验证数据分层。 |
| P2-08 | 旧状态迁移与新输入重复进入 | 约定只生效一次，旧 cue／独立候选入口不再写另一套状态；无未清理调用方异常。 |
| P2-09 | 来源更正、状态重置或切换档案后旧快照返回 | 旧快照不能覆盖新状态或进入新档案；清空会话不删长期记忆。 |
| P2-10 | 历史超预算或摘要来源不可用 | 裁剪有界，当前请求仍在；不截断到反转原意，不把缺失内容编成事实。 |
| P2-11 | 云模型正常新数据、旧仅本地标记、本地连接 | 业务流程使用同一接口；新连接说明清楚，旧限制未处理前不外发；本地能力不被“必须 cloud_allowed”无条件阻挡。 |
| P2-12 | 模型连接缺失或人格保存失败 | 明确报连接／保存问题，不伪装已学习、不静默切到离线演示。 |

## 真实模型效果检查

使用两份明显不同但目标相同的角色卡，例如“重实践、先核实限制”与“喜比较推导”。面对相同学习安排问题，允许规划关注点不同；事实、权限和用户当前目标必须一致。保留模型标识、场景、实际输入摘要和结果，不能仅检查回复里出现角色名字。

真实测试至少涵盖指代、临时与长期要求、用户自述与推测的区别；表述可变化，不能仅靠一组固定句式通过。真实调用未获准或未执行时，这部分标为未验证。

回归参考：`tests/unit/conversation/test_context_and_model_gateway.py`、`tests/unit/agent/test_planner.py`、`tests/integration/application/test_conversation_pipeline.py`、`tests/integration/application/test_persistent_conversations.py`。旧“人格变化不得影响规划”断言按新要求调整，权限与事实断言保留。

退出条件：输入证据证明角色参与规划，范围和来源检查通过，迁移不双写；真实语义效果缺项单列，不用离线结构结果代替。
