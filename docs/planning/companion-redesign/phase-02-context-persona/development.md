# P2 开发：统一上下文与角色建模

日期：2026-10-29。状态：代码已实施，定向隔离验证完成；真实模型与原生实机未验收。实际范围和结果见[实施记录](implementation.md)。依赖 P1。参考[公共契约](../architecture-and-contracts.md)，验收见[本阶段清单](acceptance.md)。

## 目标与范围

让开放角色卡、当前会话进展和有效要求进入理解、规划与表达。以五层业务含义承接旧职责，迁移调用方后删除旧独立互动状态模型，不再用支持／专注／庆祝模式代表全部理解。

本阶段建立稳定读取、保存和上下文接口，P4 完成自动情绪及习惯学习；不把有限预设隐藏起来就宣称开放人格完成。用户写下的身份设定、学到的习惯、用户事实及本轮要求保持可区分。

## 代码入口

## 记录与接口

| 内容 | 设计要求 |
|---|---|
| 角色卡 | 自然语言身份、背景、性格、价值取向及初始相处方式；稳定标识与修订。不是有限选项拼接。 |
| 已学习惯 | 与用户角色卡分开更新的局部记录，能追溯来源；不提供人格平行版本切换。 |
| 用户状态理解 | 含义、自述／推测性质、简短理由、范围与有效期，不将其自动变成角色情绪。 |
| 当前互动方式 | 会话、当前轮次或明确扩展的时间范围；来源可更正，旧要求可到期。 |
| 当前情绪 | 预留 P4 四项记录读取接口；不存在有效状态时使用中性或仍有效状态，不凭空补编。 |
| 工作上下文 | 双方近期交流、当前进展、已有决定、待解决问题、真实工具事实和必要引用。 |

统一准备不可变的本轮快照，包含当前档案和后台代次、会话、各来源修订。规划和表达取同一角色背景，按用途裁剪资料而非重新挑选一份可能矛盾的人格。后续轮次从更新后的有效状态重新准备。

## 开发步骤

1. 增加角色卡及分层状态的保存和读取边界，复用现有角色状态存储。首次新版档案按最新决定从空数据开始，不转换被清理的旧人格；如用户显式导入旧备份，再将其有限身份转换为明确标注的可编辑导入内容，不自动杜撰背景。
2. 盘点旧 `InteractionState` 的 sessions、cue、偏好候选、来源与去重职责，逐项转交对应模块或运行记录。先接替调用方，再删除旧维护逻辑；临时兼容只为迁移，不持续双写两套状态。
3. 准备上下文时，必需的角色卡和有效要求直接读取；长期记忆按相关性检索。不能让角色卡因相似度不够而被丢弃，不能默认把整个档案发送模型。
4. 规划输入可使用相关助手历史来解析“第二种方案”等指代；每条区分用户要求、助手建议、用户已采纳决定和真实执行结果。过去说过的请求不自动重新发起。
5. 为会话摘要定义更新接口和来源，P4 接入实际总结与召回；本阶段先保证近期上下文与摘要输入的来源、顺序和有效性。清空时摘要和会话临时状态一起失效，长期记忆保留。
6. 模型理解临时要求与期限，程序落实保存和范围读取。对于一次／会话／当天／持久的表达含义不再依赖固定关键词覆盖；解析失败时说明未保存，不凭规则伪装为已理解。
7. 将云／本地模型差异集中于适配和出站边界，业务传递统一上下文。正常新数据随已配置模型按说明使用；旧“仅本地”数据在迁移说明处理前不得外发。移除日常五类许可开关的产品依赖，不顺手取消凭据和网络安全边界。
8. 人格正常默认工作，角色卡进入规划和表达。身份或状态更改时使旧派生快照失效，P3 消费新版快照和输出协议。

## 优先顺序与变化

用户当前明确要求优先于旧推测和一般习惯，真实工具事实约束结果陈述，角色卡不能授权危险操作。临时“简短”不写成永久寡言，某会话“先倾听”不扩展到其他会话，明确“以后都这样”才进入适用的长期记录。

允许内部表达指标兼容现有桌宠状态，不将六轴作为唯一人格，也不固定情绪到六轴的映射。本轮表达调节由有效状态形成，不再永久存一份派生的 cue。

## 失败与兼容

必需角色资料不可读时明确标明异常，不在后台悄悄换人；可选历史超预算按完整资料单元裁剪，并保留当前目标和必要来源。保存失败不能回复“已设置”。模型不可用明确提示，不默默回退到固定命令演示。

清理旧入口时同时审查 CLI、Facade、Bridge、测试替身和回复协议；P3 一并完成多轮协议切换。过渡版本不把尚未接入的自动学习显示为已启用成功。

## 交付条件

包含五层归属表、旧字段迁移清单、准备上下文接口和出站资料说明。完成 P2 验收，证明角色实际进入规划、相关双方历史可见、会话要求不串用；自动学习效果不在本阶段提前冒称完成。
