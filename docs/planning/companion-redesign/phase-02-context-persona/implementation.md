## 实际实现

角色存储升级到 companion schema 3：开放自然语言角色卡独立于模型学到的习惯；用户状态理解与互动方式分别记录。情绪预留四项内容：描述与强度、原因来源、发生时间与持续范围、不确定性。表达调节由本轮资料形成，不另存 cue。角色卡默认参与规划和表达，桌宠旧 DTO 只接收中性兼容投影，不再按工具成败机械更新情绪。`save_feedback` 是后续学习模块的持久化边界，本阶段没有自动调用它学习。

`InteractionCoordinator` 为每轮绑定档案、后台代次、会话及来源修订；同一份角色快照进入规划与表达，修改后旧快照不能继续执行。角色卡直接读取，不经过相似度检索。工作上下文提供双方近期交流，明确区分历史用户要求、未确认助手建议与宿主记录的工具结果。当前用户可以采纳助手的特定方案，历史请求本身不能重新启动操作。

临时交流要求由独立的 `context_understanding` 模型用途解释，最多一次调用，返回自然语言内容、明确／推测性质、理由、范围、期限及替换目标。程序绑定真实消息来源、检查修订、保存并控制到期。支持本轮、当前会话、当天及明确持续要求；持续推测不在此直接成为人格习惯。保存或解析失败的警告进入回复输入，不假报已设置。本阶段新增这次理解调用；P3 后续可与统一决策协议进一步整合。

会话摘要新增有来源和 CAS 的保存／读取接口，保留进展、已采纳决定及待解决问题；自动总结在 P4 接入。来源不可用时摘要不进入上下文。超预算省略完整历史轮次。清空会话清除摘要和该会话要求，独立长期记忆保留。明确跨会话的当天／持续要求不因关闭窗口而消失。

## 旧入口与兼容

删除旧 `InteractionState` 和 `InteractionOperations` 的状态维护模块；旧 cue、独立偏好候选、有限身份及五类云许可不再由当前应用入口读写。设置改为开放角色卡编辑，保留未保存内容和修订冲突反馈；CLI 使用 `character_card`／`reset`。回复协议仅返回 `reply_text`，不再输出 cue 或偏好候选。归档识别 schema 3，旧备份仍可导入。

旧人格库的一次性转换只读取实际设置并标注为可编辑导入内容，不杜撰背景；旧自定义内容保留 `local_only`。设置说明重新保存后会按当前连接使用。新角色卡正常随所选模型处理，无五类日常开关。记忆与历史的旧来源限制继续在出站准备时落实，没有取消凭据保护或网络边界。连接缺失不切到离线演示；测试显式选择离线或注入模型替身。
