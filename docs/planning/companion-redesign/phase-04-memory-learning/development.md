# P4 开发：记忆检索、反馈学习与遗忘闭环

日期：2026-10-29；2026-10-30 完成代码及定向隔离自动化。依赖 P1–P3，阅读[公共契约](../architecture-and-contracts.md)，验收见[本阶段清单](acceptance.md)，实际接口、迁移、验证和未验证边界见[实施记录](implementation.md)。

## 目标与范围

反馈学习模块在应用服务层装配，复用模型网关、记忆和角色状态服务。处理本轮提炼、相关话题的被动复核、集中整理，以及模型理解的短期情绪和长期习惯。程序保存和校验结果，模块不重做原工具任务。

普通学习和人格默认工作，不逐条让用户审核。学习指持续记录与行为调整，不是训练模型权重。当前角色完整档案内运行，不访问其他档案，也不建立第二个记忆库或复杂证据关系网。

## 代码落点

`memory/contracts.py`、`coordinator.py`、`repository.py`、`retrieval.py`、`evaluation.py`；`companion/*`、`application/effects.py`、`interaction.py`、`privacy.py`、`conversation_service.py`、`agent/core.py`、`workflow/humanization.py` 与调用网关。P5 调用本阶段统一反馈接口，不复制理解逻辑。

## 记录结构及新旧对接

| 对象 | 最小业务内容与归属 |
|---|---|
| 长期事实与知识 | 内容、来源性质、适用主体和时间、可保留的不确定性。位于当前档案，供各会话按相关性使用。 |
| 情景记忆 | 有意义的角色经历及时间、参与上下文和真实来源；不是每调用一次工具就新增人生经历。 |
| 待复核缓冲记录 | 当前理解、预期去向、来源／理由、不确定性与适用范围、整理状态与时间。与正式记忆兼容，可采用、修正、继续保留、合并或清理。 |
| 来源关联 | 程序保存实际会话和消息引用及必要修订；模型写理由。多段交流仅用简单引用列表，不增加支持／反驳图。工具事件引用执行账本中的真实结果。 |
| 当前情绪 | 描述与强度、原因及来源、发生时间与预计持续范围、不确定程度。可混合反应，不固定为单一模式标签。 |
| 学习记录 | 来源、简短理解和理由、实际改变或保留的内容、范围与复查安排；按档案持久保存，不保存完整私有思考。 |

记忆“已采用”不等于客观真实，整理工作“已完成”不等于该理解已确认。弃用旧偏好池和人工接受／拒绝链；原有 MemoryStatus、ClaimType 等如何映射，在 schema 迁移表明确，不简单把所有 CANDIDATE 批量 ACCEPTED。

`working` 由会话上下文承担，目标仍由目标服务管理，相处习惯归人格，执行明细归执行账本；不为凑齐旧五类建空功能。旧记录保留其真实来源，明确归类，不伪造缺少的角色经历。

## 同步收尾与工作记录

本轮已有可靠的用户输入、工具结果及回复内容后，在提交任务和发布回复之前执行提炼。将助手生成的内容标为模型建议或解释，不当成独立事实证据；当前工具失败也可提供有效反馈，模型连接失败不解释为用户讨厌角色。

2026-11-01 真实调用修补：这里的回复内容为规划草稿，最终表达在反馈提交后读取宿主回执；整理完成但无新增记录、缓冲保存、长期采用、失败不能混为一谈。读取不到回执也不声称成功。所有反馈时间字段统一要求完整的带时区 ISO 日期时间或 null，含 valid_from／valid_to／expires_at；不把无时区日期悄悄解释成某个时区，不放宽原始来源与引用校验。

同日真实响应进一步确认反馈达到 max_output_tokens 时被服务截断。默认评估上限调整为8192、超时40秒，用户显式设置仍优先，原有8192／60上限和三次尝试预算不放宽。测试也必须给结构化反馈足够额度，并保留全局调用／输出预算；不能用太低的测试截断上限将服务正常的容量行为误判为存储实现故障。

| 状态 | 落实要求 |
|---|---|
| 待处理 | 登记工作、来源范围和修订、幂等标识；不等于已成功学习。 |
| 处理中 | 短事务领取、增加尝试号，释放数据库锁后调用模型。 |
| 已完成 | 校验并保存结果后记录完成；无值得提取内容也可完成。单库内结果与完成标记同事务提交。 |
| 失败 | 记录可诊断原因与次数。临时错误有限重试，配置错误直接说明；最终失败仍允许发布本轮实际结果。 |

幂等标识基于本次工作和来源范围，重复回调只采用一次。可用“记录已保存”回执恢复跨库人格调整，不能假设记忆库和角色库同事务提交；恢复不重做工具。来源被明确遗忘时不重试恢复它；清空聊天导致尚未完成的旧整理资料失效时停止旧写入，但已有长期记忆保留。

同步提炼只完成本轮评估与缓冲保存，不要求所有存量不确定理解都当场复核。后续被动或主动整理可继续；不改为回复发布后与下次聊天并行提炼，也不设计自动让位。短事务之外才进行模型调用。

## 检索与会话摘要

1. 先限定当前档案、有效记录及被允许的资料来源，再作词法／语义候选检索。必需角色卡和有效要求走直接读取，不和普通记忆抢相似度名额。
2. 相关未确定记录可提供给模型，但明确其性质和依据；不能作为工具许可。必要时模型改写查询、补查真实来源或重排候选，次数和长度受预算控制。
3. 重新评估数字、否定词等硬过滤，避免排除有关的变化或反例。保留实际期限、遗忘和来源有效性检查；相似度不判断真实性。
4. 同档案跨会话记忆可用，临时会话要求不跨会话。事实带时间区间，区分过去和现在，不简单用新值抹掉整个历史。
5. 摘要保留当前目标、已决定内容、未决问题与假设，关联原消息并按需要更新。原文更正或明确遗忘后同步失效相应摘要，不通过旧摘要恢复内容。
6. 超预算保留完整有效片段和当前请求，按优先级缩减，不截断否定或来源；找不到时承认未知，不让模型补编“记得”。

## 人格与情绪学习

同一反馈入口，短期和长期两种速度。模型先理解反馈针对答案、方式、语气还是一时请求；临时反应可进入本轮，持久状态在对应事件可靠记录后落实。长期线索进入缓冲复核，明确且内容清楚的用户要求可经模型直接更新。

不每轮重写整张角色卡，不把一句“这次简短”永久修改身份；多次总结也不是新证据。人物姓名和背景保持连续，普通局部习惯自动采用、有记录、可纠正，并在下一轮规划和表达里实际使用。

替换旧 `outcome_delta` 和工具成败固定情绪入口，保留有效事件投递、去重和时间控制。旧与新不能对同一事件各更新一次。六轴只可作为内部表达兼容，模型结合场景决定表现，不固定“高兴=幽默值增加”。无新模型判断时沿用仍有效状态并平滑减弱或中性表现。

## 整理与遗忘

反馈接口接受一批有界来源或待复核记录，返回整理决定，复用记忆管理服务执行合并、修正、采用、保留或清理。P5 只安排何时调用它，不自行决定记忆内容。

用户明确遗忘在当前任务通过管理接口落实。相关缓冲、摘要和学到的派生习惯使用简单来源关联重新核对，程序阻止明确已遗忘内容重新写回；不要求用户审核普通整理。低确信度和时间久本身不是必删条件，模型判断重要不确定内容可长期保留。

清空聊天只清该会话正文、摘要和临时状态，已有长期记忆与习惯不级联删除；引用标注原文不可用，不以“保留依据”为名暗藏整段聊天副本。新理由只能根据仍有效资料形成。模型声称已遗忘前必须取得实际管理结果；无法访问的外部副本和旧备份不伪称已擦除。

## 开发步骤与完成条件

先完成记录及迁移，再实现反馈统一入口、同步工作与有限重试；随后接通检索摘要、情绪和局部习惯，最后去除旧固定规则、候选审核和工具事件自动入人生经历的路径。期间保持来源和删除规则，不靠多套逻辑双写兼容。

交付 schema 映射、幂等与恢复说明、检索策略、反馈接口、旧入口移除清单及 P4 验收记录。只有“提炼—保存—召回—实际采用—纠正／遗忘”全部联通才算自学习交付。


## 2026-10-30 补充开发：通用复查与情绪影响

遵照[补充确认](../../companion-model/2026-10-29-redesign-follow-up-decisions.md#十一2026-10-30-补充确认任务上下文统一复查与情绪变化)。反馈输入使用已冻结的目标与修订，补入仍可读的真实原消息；实际完成复核与尝试选入分开记账。反馈模型可以通过可选 followups 返回通用内部维护或可能的主动交流安排，复用已有学习投递回执和 P5 关注存储；提交后跨库投递幂等恢复，不另设情绪任务队列。

当前情绪的四项业务内容保留，真实更新时间、半衰期和已有来源引用作为宿主元数据；在读取时计算 influence_weight，不因读状态或空学习结果而写回、重置时间。默认半衰期 6 小时，模型可给 15 分钟至 7 天的有界值；这是影响参数，不是固定语义判断、清除期限或前端设置项。重启沿用已保存更新时间，旧资料缺少计时依据时不当作刚刚产生的情绪；跨库延迟投递使用已保存的学习时间，不按每次投递重置。显式到期前再逐渐收敛至零，避免在期限处从强影响突然消失。情绪续期、缓和或改变由模型根据实际资料决定，需要复查时采用同一 followups 链路。
