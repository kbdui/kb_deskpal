# Phase 04 实施与验证记录

2026-10-30。状态：代码、接口和定向隔离自动化完成；真实模型语义效果与原生实机未验收。依据两份重设计讨论、公共契约及 P4 开发／验收实施。父 Agent 编写源码和测试，6 Luna 高执行隔离验证，父 Agent 复核与修补。

## 统一记忆与持久缓冲

缓冲直接使用记忆修订体系，没有另建偏好池。`MemoryDraft.content` 是当前理解，`destination` 是事实／经历／习惯去向，`reason` 保存模型理由，`uncertainty` 保存不确定性与适用范围；原有状态、记录时间和新增 `review_after` 表达整理安排。有效时间仍由 `valid_from/valid_to` 表达，复查时间不等于删除期限。模型选择输入目录中的来源键，程序将它们映射到真实消息、记忆修订和工具账本引用，保存在简单的 `learning_link` 列表中。

普通推测进入 `candidate` 缓冲。模型后续可以采用、修正、保留、归档或合并；使用同一稳定 ID 增加修订。明确保存继续通过可信管理工具立即执行。采用仍保留原来的 `claim_type`、不确定性和时间，不把模型分数当真实性。习惯推测必须复核既有习惯缓冲；内容清楚的长期明确要求可以直接落实到角色习惯，临时要求仍走 P2 的范围模型。

只保留事实知识和有意义经历作为长期内容。当前工作归会话上下文，目标／日程归自身服务，工具调用明细归执行账本。精确重复有主机去重，含义相近、矛盾或合并由模型决定，不设提及次数门槛。

## 同步收尾、重试与恢复

`ApplicationService` 装配 `FeedbackLearning`，通过 `TurnFeedback` 接到 Core 的最终回复形成之后、终态提交和对话发布之前。输入区分当前用户话语、尚未发布的助手草稿、已发布历史、真实工具结果和已有理解。反馈模型没有工具权限，不能在整理时重新执行来源任务，也不能改写角色卡。

`learning_job` 分开保存 pending／running／completed／failed／cancelled、尝试次数和安全故障分类。调用前短事务领取，释放锁后请求模型；仅临时模型故障最多尝试三次，配置、格式、来源失效不作无意义重试。空结果正常完成，最终失败也继续发布原任务的实际结果。网关同步放宽 memory_evaluation 为三次，其他用途边界保持。

本批记忆、来源、学习记录和完成标记在记忆库同事务提交。角色变更通过 `learning_role_outbox` 投递，角色库的回执和变更同事务保存；投递后确认失败可重新接收，回执阻止重复成长。重启在唯一后台的安全边界恢复未提交的有效评估和已提交的角色投递；不重规划、不重放工具。隐私代次、会话、角色或来源修订变化时阻止旧结果；不假设四库原子提交。

整理更新当前引用后，本轮旧上下文进入可追溯历史，旧来源仍保留遗忘索引；当前依赖和最终快照相应交接，避免把本轮自己的合法更新误判为外部冲突。最初计划字节不覆盖，已完成步骤不重做。

## 情绪、局部成长和实际采用

模型输出四项当前情绪：描述与强度、原因来源、时间范围、不确定性；程序落实期限、来源、保存和去重。用户疲惫与角色自己的反应分开。没有模型判断时沿用仍有效状态或中性表现，不按工具成功／失败增减固定情绪。

角色习惯按稳定 ID 局部新增、修正或删除，保持角色卡和背景不变，供下一轮理解、规划与表达直接读取。`learning_record` 保存简短理解、理由、范围和实际去向，可关联本次工作、真实来源及角色投递状态。它不保存私有思考过程，也不提供人格版本切换。

输入候选不等于实际学习依据。各项习惯和情绪只保存实际选用的宿主引用；未被采用的输入不成为其删除依据。保存前在角色库同事务内验证必需上下文仍能读取，超过 32 KiB 则回滚新变更和回执，保持已有角色可用，不先存成下一轮打不开的状态。

## 检索、摘要与清理

检索允许相关缓冲进入，但明确标示状态、来源、不确定性和未验证性质。移除数字不一致、否定词不同就直接排除的语义硬过滤；查询可同时看到历史时段和当前事实，指定 as_of 时仍按时间区间筛选。词法计算避免长问题稀释短记忆，原句一致有排序优势，正反例仍保留原文。词法与语义候选结合、有界融合和完整片段预算继续工作；必要重查可以使用 P3 的 `memory_search`，由规划模型改写查询，受同一多轮预算约束。没有新增每轮固定的模型重排请求。

每轮反馈可更新已发布部分的会话摘要，保留进展、决定和未决问题，假设与建议仍标明性质。当前尚未发布的回复不伪装成摘要来源；原消息关联由程序保存。摘要更正、明确遗忘和清空分别处理，旧内容不能借摘要恢复。

清空聊天保留已形成的长期理解和习惯，清除来源原话、quote 副本，将实际引用标为不可读（包括已学到的角色状态引用），取消未提交的旧工作和待投递旧状态。明确遗忘沿既有共源保守管理／清理链处理，清除相关缓冲、派生引用、学习正文及待投递副本；不是程序按词义拆分原话进行局部删词。幂等标识保留为不含正文的技术记录。外部副本、用户备份和已产生的外部操作不宣称被擦除。

## 数据库与兼容映射

记忆库从 schema 2 升级到 **3**；任务库和角色库保持 **4**，日程库保持 **1**。新增学习工作、来源、学习记录和角色投递表；`MemoryDraft` 的新增字段随同不可变修订保存。迁移与版本提交在同事务中，当前版缺少必要结构拒绝打开。归档只读检查支持记忆库 3，不在检查期间迁移。

| 旧记录 | 新版处理 |
|---|---|
| accepted | 保留原归属、断言性质和期限，不解释为已验证事实。 |
| candidate／disputed | 保留为待复核理解，不批量采用。撤去旧系统自动附加的七天 TTL，真实指定的期限保留。 |
| rejected／archived／deleted／legacy | 保留既有状态；不因开启自动学习而恢复。 |
| 每任务的工具元信息 episode | 归档供历史查看，不再参与正常经历召回；明细仍由执行账本负责。 |
| working／goal／relationship 长期类别 | 旧内容归档，不为旧枚举增设空功能。 |
| 旧学习领取 receipt | 不再当成已成功学习的凭据；新版工作单独记录尝试和完成。 |

普通学习默认 `automatic`。旧 explicit_only／candidate_review 配置读取时映射为自动学习，不再沿旧人工审核链运行；明确 paused 仍作为用户暂停自动学习保留。旧 local_only 资料继续受现有边界保护，本地理解后的派生内容不能扩大用途。

## 入口与旧路径清理

- `FeedbackLearning.finish`：当前交流的同步收尾。
- `ApplicationService.enqueue_learning_review`：向同一 Dispatcher 申请有界内部整理；与用户请求串行，不创建聊天消息。P5 再决定触发时机，不在 P4 偷启随机主动调度。
- `learning_records`／`learning_review` 桌面接口：有界读取学习记录及接收整理命令，前者每页最多 20 条。
- 移除 Core 的工具元信息自动 episode、旧 learn_with_client 提炼链、独立 offer_profile_candidate 与旧领取即完成路径；不再装配或投递 `CompanionEffects` 的固定成败入口。
- 记忆页面去除接受／拒绝候选菜单，展示去向、理由、不确定性及复查时间；保留更正和明确遗忘。旧低层 accept/reject 存储方法仅为兼容接口，不成为新版普通学习的产品流程。

后续 P5 接入合适的整理机会、通知和生命周期控制；P6 完成学习记录等统一用户体验。离线演示明确返回空反馈，不伪装真实理解能力。真实模型的同义理解、假设识别、长期成长和自然表达仍需独立验证。
