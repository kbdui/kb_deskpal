# Phase 06 实施与验证记录

## 实际界面

主窗口已经采用 PySide6 的 QFluentWidgets `FluentWindow`，导航只有聊天、安排、记忆、工具插件和设置。**角色切换仅在设置，桌宠小窗从桌宠或托盘打开**。会话目录点击聊天标题按需打开；日常聊天标明固定，专项会话仍可管理。主窗和小窗继续共用 ChatCoordinator，页面切换不重建聊天或清空草稿。

按钮、下拉、输入、树和列表、滚动容器及 Pivot 页签统一复用 Fluent 控件。通用适配放在 `gui/components.py`，不保留另一套旧窗口骨架或下拉绘制。原生文件选择器、必要系统对话框、托盘及透明桌宠窗口保留 Qt 专用实现。主题只定制业务表面，支持跟随系统、浅色和深色，不再给整套控件套旧全局 QSS。主窗默认约 1180×800；常规宽度展开导航，窄窗收起导航。窄窗选择记录后进入完整详情，可返回列表再选，不继续把列表、表单和正文同时挤窄。

执行记录改为工作区内部右侧栏，不使用 QDockWidget。聊天里的原地授权与任务控制保留精确计划、修订和真实作用对象；原始结果和技术记录从统一侧栏查看。关闭侧栏释放订阅和私有文本。小窗没有执行详情按钮，但可确认适合小窗审核的操作，或展开主窗完成完整审核、追加要求、暂停和继续。聊天标题的执行入口优先查看最近任务，单条任务入口仍定位对应记录。

记忆页按“记住的内容、一起经历、仍待明确”阅读，也能查看全部记录。右键和详情中的更多操作提供更正、遗忘；新建与更正分开，无选择时不露出空编辑器。学习记录显示最近的理解、依据和不确定性，不恢复接受／拒绝候选的审批流程。遇到后台新修订，保留草稿与旧修订，用户核对详情并点击“采用刚读取的版本”后，才改用新修订保存。

安排分为日程、任务和后续关注；目标、分步计划及关联功能保留在任务分区。日程按日期显示，默认查询接下来的安排，也能查历史。“在聊天中修改或取消”只填入草稿，不自动发起操作。任务默认看待处理和进行中，可筛已暂停等状态。尚未开始的关注可结束，正在执行的操作仍走任务控制。目标的新建和编辑有明确模式，依赖选择的状态操作放入对应编辑区，保存期间防重复提交；缓存中的未保存草稿也会阻止无提示进入维护。

角色卡、学习形成的习惯和只读当前情绪、模型连接、通知、头像和桌宠形象都集中设置。目标／关联不再另外询问云或本地用途；新条目沿设置中的输入策略，修改既有条目不主动扩张原范围。连接与密钥继续通过已有维护 worker 和凭据服务保存，密钥不回显到普通 DTO。修改前等旧 Host 和桌宠资源关闭，再由相同 Fluent 设置外壳接手，保存后明确重新打开后台，并恢复设置页及窗口位置；没有实现成不安全的热更新。

## 后端和接口

本次没有新增数据库版本或迁移用户数据库。工作流、人格、记忆、调度四库仍为 5／4／3／1。

| 接口 | 本次改动与边界 |
|---|---|
| `memories` | 新增可选 `group=all/facts/episode/buffer`，默认 all 保持既有调用语义。SQLite 先按当前修订、状态与去向筛选，再分页；不会只过滤已取回的前 50 条。墓碑仍在全部记录中可查。 |
| `schedule_items` | 新增 `status=upcoming`，在数据库分页前筛出仍待到期的计时器与尚未结束的日程。原有 all／单状态查询保留。 |
| `attention_end` | 桌面明确选择一条 pending 关注，以标识、预期状态和稳定命令提交；结束与幂等回执同事务保存。状态变化则拒绝；内部检索途中被结束的关注不能重新激活。不是撤销已完成操作。 |
| `learning_records` | 接入 Bridge 的读取通道，显示最近 20 条真实记录；关闭或销毁窗口后丢弃晚到回执，隐私清理会清掉已显示内容。 |
| 既有会话／任务／资源／设置接口 | 复用服务与协调器，保留会话代次、隐私屏障、精确授权、暂停检查点、图片导入校验和后台所有权。未增加绕过规划模型的快捷执行。 |

## 依赖和静态检查

实际安装并锁定 PySide6 6.12.0、PySide6-Fluent-Widgets 1.11.3、PySideSix-Frameless-Window 0.8.2、darkdetect 0.8.0、Windows pywin32 312。官方 Fluent 依赖完整 PySide6，因此附带 Addons、WebEngine/Pdf，应用未使用 WebEngine。依赖入口和 Windows 约束已同步。

组件库没有 `py.typed`。`typings/qfluentwidgets/__init__.pyi` 只描述本项目实际使用并与安装源码核对过的公共接口，不替换运行时组件，也不关闭整个 GUI 的类型检查。少量旧调用适配器明确注明签名差异。涉及 GUI、记忆分页、Facade、调度和主动协调器的 37 个文件严格类型检查已通过，最终复测以原始记录为准。

## 已发现的问题与复核方式

首次检查发现库的页面动画会延后提交页面索引，已关闭主页面切换动画，保证显示和读取同步。整批回归还触发一次主题更新原生崩溃，栈位于第一次初始化时的 Fluent 样式重设。修补取消中途替换全局 QStyle，改用官方 lazy 刷新，调色板按明暗幂等设置。包含先创建、销毁聊天控件再构造主窗的同一四节点顺序，连续三轮各 4 项通过；这只证明该复现序列已通过，不代表原生长期稳定性已验收。

旧 GUI 用例按本次已经确认的行为更新：按需会话目录取代常驻侧栏；记忆查询增加显示组；缓冲更正保留同一条理解及其修订，不要求先人工接受；只读原始结果从侧栏验证。外部 SQLite 竞争测试改锁实际活动角色库，不再错误地锁应用根目录下的空库。模型失败验证改查用户可读失败说明与内部真实错误，不能要求原始异常直接进入聊天。没有放宽实际写入、许可、隐私或所有权断言。
