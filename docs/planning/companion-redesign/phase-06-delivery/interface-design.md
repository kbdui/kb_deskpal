# Phase 06 界面重设计：以聊天为中心的角色工作台

日期：2026-10-31。状态：用户已确认，Phase 06 代码已实现，真实模型与原生整体验收未完成。用户已允许界面明显区别于旧版；本方案替代开发文档中“不重新设计一套 GUI”的旧布局限制。业务含义仍遵守 [28 日讨论](../../companion-model/2026-10-28-character-memory-redesign-discussion.md)、[29 日确认及后续补充](../../companion-model/2026-10-29-redesign-follow-up-decisions.md)，不改写原始约定。

## 一、这次要改变什么

当前后端已经具备独立角色档案、固定日常会话、多轮任务、追加要求、暂停与继续、自动学习和通用后续复查。旧界面却仍以通用表单、分页条、固定操作区和原始数据详情来组织这些能力。新界面应围绕“与当前角色聊天，并把事情办妥”组织入口，而非让用户理解后台模块。

不增加首页仪表盘、人格数值看板或常驻的技术信息区。打开主窗口就是当前角色的聊天。身份感由角色头像、名字、语言和连续交流体现，不靠不断展示“自动学习开启”“六轴参数”“云用途许可”等说明。

本次交互预览中的角色、消息、记忆与安排均为示例。预览可切页和演示局部操作，所有变化只在预览内生效，不读取真实配置、发送模型请求或调用工具。HTML 只是设计表达，正式实现仍为 Python / Qt Widgets。

## 二、整体布局与视觉方向

主窗口采用 QFluentWidgets 的 PySide6 版本，以 FluentWindow 承担标题栏、主导航和页面切换。全局导航仅保留“聊天、安排、记忆、工具插件”，设置固定在底部。按用户最后确认，角色切换与创建、删除、备份等档案管理全部放在设置，不在导航增加角色切换入口。桌宠小窗也不作为导航项，通过桌宠本体或托盘打开；角色卡编辑只在设置中。

与旧版最明显的区别是：取消常驻第二列会话列表，取消无内容的固定详情栏，减少铺满全页的边框大卡片。聊天占据主要空间，会话列表由标题旁的入口按需打开；任务和执行详情从右侧按需出现，关闭后还给聊天空间。切到其他页面，会话列表不会残留。

保持暖白、灰绿和低饱和强调色，但不复刻旧布局。桌面应用感优先于网页仪表盘感：统一字号与行距、紧凑导航、清晰的层次、足够的留白；用户消息使用柔和底色，角色回复以头像和正文区分。较大的卡片只用于授权、表单和确有边界的内容。首版使用稳定的实色背景，不以大面积毛玻璃、复杂动效作为交付条件。深色主题沿同一组件体系适配。

默认主窗约 1180×800，常规宽度下导航约 176–200、右侧详情约 300–360，其余由内容弹性分配。这些是布局基准，不是强制固定宽度。宽屏限制正文阅读宽度，窄窗先收起导航和会话列表，再将详情变为可返回的独立详情视图，不继续挤压输入框。最小窗口尺寸经原型与实机验证确定，不把网页预览的手机折行等同于桌面缩放验收。

## 三、聊天：结果直接说，确认就在眼前

顶部展示当前会话名称；固定日常会话标记“固定”。点击会话名打开列表，可进入专项会话、创建或管理归档。默认日常入口不可删除，但聊天记录可在隐私操作中清空。每个会话保留消息、草稿和滚动位置；页面切换不会重建或清空聊天。

聊天正文只呈现用户消息、角色自然语言回复以及确有必要的交互卡片。空日程查询成功后，由模型说明查询范围内没有日程；查询失败不能显示成“没有安排”。工具参数、完整路径、调用编号、逐条返回值不铺入聊天正文。

需要许可时，在所属任务的消息旁展示紧凑授权卡：操作是什么、准确作用对象、是否覆盖或删除、必要参数及查看完整位置的入口。主按钮明确为“允许本次保存”等具体动作，旁边提供“不允许”；不预勾选长期授权，不把一次同意扩成全部未来调用。提交后立即显示处理中并禁止重复提交，最终以实际任务状态替换卡片。模型增加步骤或改变参数后重新核对，不沿用旧许可。

正在运行、等待补充、正在暂停、已暂停、失败及结果待核实都使用可理解的短状态。运行任务旁可“补充要求”“暂停”或“取消”；暂停任务提供“继续”，不向所有状态固定摆放一排无效按钮。“补充要求”先选定任务，输入框明确显示关联对象；登记成功只说明下一次模型判断将读取，不宣称已经执行。取消只停止后续操作，不声称撤回已完成影响。

输入框 Enter 发送、Shift+Enter 换行；中文输入法正在选字时不发送。发送失败保留草稿，页面切换保留输入内容。普通聊天中不放人格编辑、模型类别选择、情绪滑杆或学习开关。

## 四、执行记录：主窗口右侧的任务详情

主窗口提供统一“执行记录”入口，点击聊天任务摘要或安排中的对应任务也能定位同一详情。默认不为每条消息重复增加技术详情按钮；没有任务记录时给明确空状态。侧栏绑定档案、会话及任务，切换后不残留旧对象。

详情按“请求目标 → 当前状态 → 实际步骤与结果 → 必要下一步”排序。步骤名称用“读取文件”“保存清单”，时间先用“刚刚”“今天 14:30”等易读形式，完整时间与位置按需查看。错误、部分完成和未知结果单独说明；不将模型规划当执行事实。原始协议如确需保留，只放在折叠的诊断层，密钥和敏感诊断仍不可泄露。

右侧栏是详情，不代替就地授权。用户不打开它也能完成普通的确认、补充和继续操作。权限卡里的完整对象参数仍应可检查，不因追求简洁而隐藏危险操作范围。

## 五、安排：日程、任务、后续关注分清

“安排”内用轻量分段导航区分三类内容，不默认展示复杂月历和统计卡片。

| 分区 | 默认内容 | 行为 |
|---|---|---|
| 日程 | 按今天、接下来分组的日程与提醒，近期事项优先 | 选择后查看时间和提醒；编辑/取消作用于实际条目，必要许可就地呈现 |
| 任务 | 进行中和待处理优先，已完成可收起 | 点击定位同一任务；补充、暂停、继续和取消随真实状态变化 |
| 后续关注 | 模型安排的后续复查，用简短理由和预计时间说明 | 区分“内部维护”和“可能主动交流”；可查看或结束关注，不逐条审核候选 |

目标与里程碑仍保留，在“任务”内按需展开“长期目标”，避免额外增加一级导航或丢失已有能力。约定提醒不依赖模型重新批准；后续关注到期也不保证一定联系用户。内部维护包括记忆、习惯、情绪和其他未决事项，沿统一复查链路，不新增情绪专属面板。

## 六、记忆：一条理解，一份可读来源

主内容按“记住的内容、一起经历、仍待明确”组织。这是显示分组，分别对接事实/知识、情景内容和尚未确定的缓冲，不新增数据库记忆类别。人格习惯的编辑入口仍在设置；缓冲中涉及习惯的内容可在“仍待明确”中解释其用途，不恢复独立偏好候选池。

列表显示完整意思、简短时间与必要的不确定标记，不拿 JSON 开头、内部标识或工具调用号作标题。选中后在右侧查看正文、原消息摘录与会话、适用范围和模型给出的简短理由。理由不是私有思考记录，来源不存在时如实显示“原消息已清除”，不编造依据。

“更正、遗忘”归属具体记录，通过右键和同行的更多菜单提供；右键落在子项上也定位所属可交互记录。编辑区域在右侧，未选择记录时显示“选择一条记录查看详情”。新建记忆是独立动作与独立表单，不再与更正共用一个含混的双入口页面。保存冲突保留草稿并核对最新修订。

“仍待明确”不是待用户审批列表，没有“接受候选/拒绝候选”固定按钮。系统可长期保留不确定；用户仍可更正或明确遗忘。学习记录以“何时、根据什么、实际改了什么或保留了什么”的易读时间线按需打开，不和工具执行记录混在一起；工具明细只在任务账本出现。

## 七、工具插件：看清能力与范围

按文件与文档、日程提醒、记忆与角色、实用工具等实际目录分组，展示可用工具的用途、可用状态、作用范围和许可要求。点击工具查看详情，必要时提示对应连接未配置等实际原因。单次工具许可仍归所属任务，不在这里做“永久允许所有操作”的快捷按钮。

插件保留独立的来源、版本、状态和能力声明接口，但当前没有的安装、市场或任意第三方执行能力不做成看似可用的按钮。受管工具、模型连接与第三方插件的安全边界不混称；正式沙箱继续是后续方向。

## 八、设置：所有配置集中，业务数据归属说明准确

| 设置分区 | 内容与边界 |
|---|---|
| 角色 | 开放角色卡、模型学到的相处习惯和只读当前情绪说明；角色卡参与理解、规划和表达，不展示六轴/预设/人格版本切换 |
| 模型连接 | 默认云连接，按需切本地；地址、模型、凭据状态、替换/移除密钥、明确的连接检查；密钥不回显到只读 DTO 或日志 |
| 外观与桌宠 | 应用主题、头像和桌宠静态图上传预览、尺寸及恢复默认；头像/受管宠物资源归当前档案 |
| 数据与隐私 | 当前角色档案管理、备份恢复、清空本会话与长期记忆管理的区别；连接/密钥/外部工作区/模型缓存为应用级共用 |
| 通知 | 当前主动聊天与约定提醒的实际暂停状态及快捷恢复；聊天里的要求与该页面调用同一策略服务 |

学习默认自动，保留用户主动暂停学习的现有能力，不新增默认拒绝或人工审核流程。设置可以说明当前状态，但短时交流方式主要由聊天表达，不做一排“支持/专注/庆祝”模式按钮。情绪时间权重为内部参数，不向用户增加滑杆。

连接与密钥继续复用既有凭据和维护服务。工作台设置内发起编辑后，等待旧后台与桌宠资源安全关闭，由相同 Fluent 设置外壳承接原维护表单；保存后明确重新打开后台，恢复设置页和窗口几何位置。维护期间没有可用的聊天导航，不假装热更新，也不通过普通 settings DTO 写密钥。角色档案管理同样遵守这一交接。未发送草稿及未保存表单先提示用户处理，关闭和重开状态如实显示。

## 九、桌宠与小窗

桌宠本体保留透明、拖动及必要的置顶行为；不强行改成带完整导航的 FluentWindow。小窗内部统一使用同一套控件、间距和主题。

单击桌宠或从托盘打开小聊天窗，默认当前角色的日常聊天；右键桌宠提供聊天、打开主窗口、调整大小和通知设置等紧凑操作。通知与免打扰的实际开关集中到设置，小窗没有设置栏。小窗包含消息、输入、必要的任务确认/补充/暂停/继续，没有执行详情按钮。主窗与小窗使用同一个会话和任务协调器，小窗展开主窗时准确定位当前会话，执行记录只在主窗查看。

原型中的桌宠预览只用于展示小窗与右键菜单方案，不是新桌宠资源，也不冒充 Live2D 功能。

## 十、组件落地与实际接口

尽量使用同一组件体系：FluentWindow、导航、按钮、输入与下拉、菜单、提示、设置卡片、列表/树和滚动容器优先使用 QFluentWidgets。聊天气泡、任务授权和详情按业务组合；布局、数据模型、信号、线程仍使用 PySide6。保留统一图标，不将 HTML/CSS 移植为另一套运行时。

旧全局 QSS 不能整段套在新组件上。先验证匹配的 PySide6/QFluentWidgets/无边框窗口依赖组合，再锁定版本；不混装 Qt 绑定，不一上来启用全部透明和动画效果。取消旧 QMainWindow/QDockWidget 的视觉骨架，右侧记录改成工作区内部详情容器；旧关闭、托盘、位置恢复与后台生命周期逻辑应逐项迁移，不能因换主窗口而丢失。

| 新界面行为 | 当前可复用的能力 | 实施时需补齐的部分 |
|---|---|---|
| 会话选择与聊天 | conversation_*、ChatCoordinator、草稿和消息投影 | 新窗口/导航绑定，按需会话面板及空状态 |
| 就地任务确认与详情 | task_review、confirm、task_updates、精确计划哈希及修订 | 新卡片呈现、正确禁用与完成替换，不把一次许可扩张 |
| 多轮补充/暂停/继续 | task_append_requirement、task_answer、task_pause、task_continue | 按任务关联的输入模式、状态同步及重启恢复呈现 |
| 记忆与学习记录 | memories、memory、learning_records | 前端可读投影和分组；现有分页接口未必支持全部新分组，需在服务层确定筛选契约，不能只过滤当前一页冒充全量 |
| 安排与后续关注 | schedule_items、tasks、goals、attentions、notification_* | 三个分区、记录级菜单与关注内部维护状态的友好名称 |
| 工具插件 | tools_catalog、tool_detail、plugins_catalog | 统一目录呈现与扩展空状态，不伪造安装能力 |
| 角色、连接和资源 | 角色卡服务、档案管理、现有维护/凭据服务、appearance_*、asset_import_* | 在同一设置体验中编排必要生命周期和操作回执；复用安全存储 |

实现时如果需要新增查询投影或适配接口，应同步修改后端，不让前端自行解释任意 JSON。头像上传采用预览/校验/应用流程，不能仅换一张界面图片就声称已保存。

## 十一、空状态、错误与验收

所有页面首次进入自动加载，区分“加载中、确实为空、读取失败”。失败后给就地重试并保留已有内容；刷新是恢复入口，不是正常使用必经步骤。下拉选项有悬浮与选中反馈，未主动编辑时滚轮不改值；长路径和时间按需查看，记录无选择时不显示无效编辑器。

验收覆盖正常/窄/宽窗口、125%–200% 缩放、多屏恢复、中文输入法、连续滚动、页间和主小窗切换、任务状态变化及数据晚到。主窗改用无边框框架后，还需单独验证拖动、缩放、最大化、系统贴靠、关闭到托盘与再次唤起。动画关闭或系统减少动态效果时功能不受影响。

本设计已获用户确认并开始实施。开发顺序为：组件和窗口兼容验证 → 统一壳与聊天闭环 → 任务/授权/右侧详情 → 记忆与安排 → 设置/连接/资源/档案 → 工具目录和桌宠小窗 → 全流程验收。原 P6 的业务验收项继续保留；窄窗记录列表在选择后转入完整详情，并可返回列表，避免同时挤压正文和编辑区。实现与证据见[实施记录](implementation.md)，原型检查不能替代 Qt 实机、真实模型或后端数据验证。
