## 2. 本版必交范围

一次一个桌宠窗口、一套可信本地静态图片；默认关闭，用户明确开启。优先 Qt Widgets/QPainter 直接绘制，复用现有 PySide6-Essentials，不新增独立渲染进程、Cubism、Live2D 绑定、PyOpenGL 或 WebEngine。

| 功能 | 可验收行为 |
| --- | --- |
| 实际静态图片 | 从项目资源加载真实透明 PNG 并绘制，检查 alpha/边缘/比例；原始图、定稿和运行资源有来源/hash。不能仅凭 mock 或文字占位宣称图片桌宠完成 |
| 状态展示 | idle/thinking/executing/success/failure，以及 queued/waiting/review/uncertain/cancelled/unknown/closing 的准确中性表示。推荐neutral/thinking/focused/pleased/alert五张同角色静态差分；只有neutral必需，差分缺失回中性图并保持准确标识，不增加人格/情绪算法 |
| 基础交互 | 拖动、点击本地反馈或显式打开主窗口、显示/隐藏、关闭桌宠、位置恢复；拖动不触发点击，状态变化不主动抢焦点 |
| 桌面适配 | 透明窗口、工作区夹回、逻辑坐标/DPR换算、多屏负坐标/混合缩放/屏幕变化、独立位置偏好 |
| 输入控制 | 置顶选项、交互/穿透切换；透明区域命中有原生证据。穿透后可从主窗口/托盘恢复交互，不能无路找回 |
| 生命周期 | 主窗口/托盘/宠物显示状态独立；关闭宠物不关闭后台任务；退出应用统一关闭。图片准备中退出、迟到回调、反复开关/释放正确 |
| 可靠降级 | 图片缺失/损坏/超量/读取失败、可恢复绘制异常时转项目自有中性标记并显示分类诊断；原 GUI/任务继续可用 |
| 资源控制 | 异步图片读取/解码、有限缓存与单个在途加载、无动画/帧循环、隐藏无专用周期绘制，重复开关与最终同构建长测 |
| 兼容性 | CLI 不安装 Qt 仍可运行；现有 GUI 不依赖桌宠或图片生成服务；偏好/资源缺失有安全默认 |

**不在本版：**Live2D/Cubism/模型动作、SDK/绑定评估或安装、拆件PSD/网格/变形绑定、序列帧/GIF/QMovie连续动画、自动摆动/呼吸、面捕/语音/音频、模型或皮肤市场、任意远程素材/脚本导入、独立渲染进程/IPC、人格情绪算法、V0.6实验与完整安装器。静态状态图按事件切换，不属于逐帧动画。

生图可承担角色概念和透明PNG；正式使用前仍检查形体、透明边缘、状态一致性和来源。角色方向不阻断窗口/契约开发；自有中性标记只作为缺资源降级，最终静态图片验收仍需实际合格PNG。Live2D由未来更新重新立项、重核环境和许可，不能继承本版静态验收为其通过证据。

## 3. 架构、线程和数据边界

1. 唯一执行入口保持 ApplicationBridge → DesktopFacade → ApplicationService → 单 dispatcher/Core。桌宠 controller 不持 Application/Core、DB、API key、生产配置，不直接执行工具/提交/确认/恢复计划。
2. 桌宠只消费经过定义的、无用户正文的 PresentationSnapshot；本地图片与角色描述无工具字段、授权字段或可执行脚本。图片仅由固定expression_id映射到代码声明的随包相对资源，不接受外部manifest/任意路径。点击仅本地反馈/导航并重查，不提供工具确认快捷入口。
3. 后端和CLI不反向依赖PySide6/具体图片渲染；关闭桌宠后原功能保持。图片失败不能改TaskStatus、增加attempt或触发任务重放。
4. QWidget、QPixmap、QPainter、窗口几何、偏好和QObject最终销毁留在Qt GUI线程。文件读取/预算预检/QImageReader解码在受控后台线程，不在该线程创建QPixmap/Widgets。
5. QImageReader及文件句柄由工作线程独占；结果作为不再修改、拥有完整缓冲的QImage交付GUI，后续转换受像素预算约束。不得跨线程复用reader、painter或可变共享图像。
6. 加载同一时间仅一个在途任务，至多一个合并后的最新请求。结果携generation；旧/关闭后的结果不更新窗口，也不能遗失线程所有权。GUI主线程不得同步wait/join/读盘/解码。
7. 隐藏与关闭区分：隐藏可保留受限缓存；关宠释放窗口/图片缓存和信号/定时器，不再发专用状态查询。宿主退出时异步等待所有自有工作结束；超时显示真实Closing，不强杀Core或遗失线程。
8. 本版没有自有GL上下文/渲染子进程，不设对应回收门槛；仍须处理Qt可恢复绘制异常、窗口销毁和宿主异常退出后的现有恢复语义。若图片解码导致原生崩溃，保留现场并作为阻断归因，不能用“静态图片”解释为可忽略。

## 4. 状态与输入语义

bridge Ready只表示应用可服务，不表示Core空闲。现有notification_feed受通知开关控制且只覆盖部分状态，不能充当完整状态来源；需新增Qt-free最小应用快照，后台经现有bridge读取，不读SQL或当前UI选中项。

| 权威输入 | 图片/标识语义 | 限制 |
| --- | --- | --- |
| 快照新鲜且无活动工作 | idle | 超时/查询失败显示unknown，不能装空闲 |
| Created/已受理但未规划 | queued | 受理不等于执行 |
| Planning / Running | thinking / executing | 不读取内部推理，不编造百分比 |
| Waiting | waiting | 不自动授权或表示成功 |
| Completed / Failed | success / failure短时标识 | Failed可能有部分副作用，不表示回滚 |
| Cancelled / NeedsReview / Uncertain | 中性cancelled/review/uncertain | 不惩罚用户，不自动恢复/重放 |
| Closing / Closed | closing /停止展示 | 迟到终态不能覆盖关闭 |

后端快照为schema_version/session_id/sequence/memory_epoch/status/task_id/revision七字段；bridge信封另携generation/privacy_epoch/request_id，GUI接收时钟控制有效期，不把这些信封字段额外塞入严格七字段DTO。均不含请求/结果/标题正文。宿主生命周期优先，活动工作优先于短时终态；旧/重复/乱序状态不重复触发反馈，恢复显示只刷新当前快照，不补播历史。快照可能合并短暂状态，不承诺每个瞬时阶段都有一张图。

表现词表固定为neutral、thinking、focused、pleased、alert：Planning→thinking，Running→focused，新Completed→pleased短时一次，Failed→alert，其余状态默认neutral并用文字区分。未知/缺失差分回neutral；取消/拒绝授权不显示受伤或惩罚表情。

状态文字收到有效快照后立即更新；同类图片合并，装饰切图可采用thinking延迟250ms/最短停留500ms/完成图最长1500ms的初始体验参数。Closing、失效/unknown、Waiting和Failed立即取消过时图/定时器并抢占，隐私epoch立即失效；不为防闪烁遮蔽真实状态或提频查询。定时器也必须重核generation/revision。图片切换不改变画布/窗口尺寸、锚点和点击区域，不设连续动画循环。

透明alpha不自动等于鼠标穿透。命中按本窗口图像/形状做有界判断，不采集全桌面、不逐帧读屏；使用当前DPR换算，拖动采用Qt阈值。单击导航必须来自明确操作；后台任务变化不能raise/activateWindow。

## 5. 精简后的验收矩阵

U=纯逻辑，Q=合成Qt/offscreen，N=Windows原生实际图片/输入，R=资源测量。八组是有区分力的场景组合，不是通过数；实际执行状态见版本测试报告。每个行为选能证明它的最低成本层，不把所有单元边界再复制成原生测试；U/Q仍不能代替透明输入和实际DPI等原生证据。

| ID | 合并场景 | 必保的断言/证据 |
| --- | --- | --- |
| T01 | 图片/差分与降级 | 全部定稿PNG一次尺寸/alpha/来源/hash/预算检查；相同画布/锚点、差分可辨；缺失差分/未知id回neutral，neutral缺失/一个损坏/一个超量夹具走安全降级。原生一次观察正常图片和切图，无每图片×故障×Python重复矩阵 |
| T02 | 权威状态与有限展示调度 | 参数化覆盖状态映射、Waiting不执行、Completed只反馈一次；重复/乱序/generation/epoch/过期/恢复新快照、装饰合并与Closing/失败/失效抢占。确认通知关闭不影响状态，零工具/授权变化 |
| T03 | 图片加载与关闭竞态 | 一个可控慢loader覆盖隐藏/关宠/Host退出、超时和迟到返回；线程归属/引用与最终join正确、无主线程同步等待，旧结果与定时器不复活窗口 |
| T04 | 原生交互和控制恢复 | 一次串行检查透明区/拖动不点击、切图不跳动/抢焦点、置顶/穿透及主窗口/托盘恢复；无托盘逻辑用Q夹具。点击仅导航，不确认/执行工具；宿主保持最终输入控制 |
| T05 | 几何与代表性DPI | U覆盖越界/坏偏好/负坐标/屏幕消失夹回及1.25/1.5换算；N按实际可用100%/200%代表环境和一轮混合DPI往返，确认命中/尺寸/恢复。缺真实混合DPI设备如实未验证，不将模拟当实测 |
| T06 | 两条独立慢路径响应 | 慢Core和慢图片解码分别阻塞，验证GUI heartbeat、显示/隐藏/关闭响应，单个在途/背压/无线程增长；可共享场景脚本但不以一条替代另一条。不调用云API |
| T07 | 受影响回归和安装 | 主Python3.12一次受影响安全测试集、3.11一次同范围兼容：新状态/桌宠及既有GUI/bridge/host/桌面facade受影响用例；保留授权/遗忘/实例边界。一次无Qt CLI/禁宠GUI对照及wheel含PNG并离线启动；无关未改后端不反复全仓重测 |
| T08 | 最终构建资源/持续运行 | 一轮30分钟原生混合运行，内含5分钟热空闲和20轮开关/隐藏恢复/差分切换/释放；每轮回稳采样CPU/private bytes/RSS/句柄/线程/cache及正常退出，观察斜率和资源存活。无持续帧循环、关宠停专用查询 |

原A01–G02的逐项合并/删除/扩展映射见[取舍表](research-and-test-scope-2026-10-20.md#5-原矩阵到精简矩阵的追踪)。本版无外部资源导入/通用脚本入口，不建设任意路径逃逸或协议fuzz测试；固定随包资源定位（含一个空格/中文安装路径）与未知ID回退仍验证。未改的OS锁/后端崩溃恢复不另开重复实验，受影响既有回归仍保留；若实现改变其路径，重新加入专项。

扩展而非首版必交：125%/150%逐档原生全矩阵、每张图×所有DPI×两个Python的组合、真实拔屏/主屏重配全排列、锁屏/休眠/RDP认证。这些明确记未验证/待扩展，不能宣称对应环境已认证；核心逻辑屏幕消失/恢复新状态与实际可用混合DPI往返仍保留。出现新显示/会话故障或引入专用代码时，再补对应验证。

100轮开关、100轮隐藏及独立重复资源长测改成T08一次合并20轮取样；不是将原未测100轮记通过。20轮不证明无泄漏，持续增长/销毁异常先保留首败并父审归因，必要时再开100轮调查/复验；不得重复到通过。Live2D/GL/IPC相关门槛仍全部延期。

## 6. 资源与响应预算

阶段0用同一机器/Qt/QPA/显示器/DPR、相同合成负载比较“禁宠”和“启宠”。记录实际PNG与源码/依赖指纹，CPU口径为进程CPU时间/墙钟（100%=一个逻辑核）；GPU指标若可取得可附记，正常桌面合成不代表GPU完全零开销，但不要求Live2D/GL指标。

以下预算在2026-10-21最终验收前冻结，保持原候选值，未因心跳首败放宽。诊断采样已移出GUI线程并保留方法变化及首败，详情见版本测试报告：

| 指标 | 初始目标 |
| --- | --- |
| 资源输入 | 首版仅可信静态PNG；文件≤8个，单文件≤5MiB、合计≤20MiB；单图≤2048×2048、总解码像素≤8M；使用前校验尺寸/格式/预算 |
| 缓存 | 源图/缩放图缓存总量有明确计数与淘汰，预算32MiB；DPR/尺寸变化不无限积累旧副本 |
| 绘制 | 不设动画/FPS timer；只响应状态/尺寸/显示/系统重绘，隐藏/关闭无专用周期update；系统请求重绘不算应用自设帧循环 |
| 状态读取 | 最多一个在途快照请求，活跃显示时初始每1秒一次，隐藏/禁用停止专用轮询；事件更新可合并 |
| GUI响应 | 50ms heartbeat的p95≤100ms，最大间隔≤500ms；T06/T08收集控制回执目标p95≤250ms并报告样本量，样本少时同时列原始值/最大值，不额外手点100次凑样本 |
| 加载/关闭 | 图片准备2秒超时转降级并失效结果；取消不等于线程已退出。正常关宠/应用额外清理目标≤2秒，线程未停则保持Closing和所有权，不强杀 |
| CPU/内存 | T08内热空闲5分钟启宠增量CPU平均≤1%单核；private bytes稳定增量≤100MiB，峰值/RSS另报，不再另跑同样空闲基准 |
| 循环/长测 | 有界预热至资源回稳（记录实际次数），同一30分钟运行内20轮关宠回稳；private bytes相对预热基线增量≤20MiB、句柄≤10、线程回基线；结合斜率/未释放对象判断，不以末值掩盖持续增长 |

崩溃、错误线程销毁、挂起、持续增长、重复副作用或证据矛盾均阻断；先保留首败，再由父Agent归因/审改，Luna执行复验。不能以重跑通过结案。

## 7. 完成与证据

每项分别标已实现/已测/未验证/阻断/不适用及理由。证据用新的 data/validation/v07/<日期-场景-轮次>/，保存原始命令/退出码、绝对解释器、源码/依赖/图片指纹、资源曲线与人工范围；不覆盖首次失败，不读取真实配置/密钥/数据库。

合格静态PNG、完整桌宠交互、准确状态、生命周期/资源及受影响回归才构成本版技术完成门槛。图片缺失降级可单独通过，但不能代替正常图片加载验收。Live2D已明确移出本版，完成静态版不表述为Live2D完成；V0.7无需等待未来Live2D更新才能验收。

当前仅评非商业本机研发；未来发行前复核实际图片/Qt及依赖的分发条件。产品仍0.5.0rc1，不自动改版本。V0.5未结项及V0.6阶段0未通过状态继续独立保留。
