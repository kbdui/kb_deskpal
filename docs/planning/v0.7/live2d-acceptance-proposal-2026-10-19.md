## 2. 首版必交与明确排除

首版为 Windows x64、Python 3.11/3.12、现有 PySide6 GUI 的**可选表现层**。一次仅一个已核验本地模型、一个桌宠窗口、一个渲染 owner；默认关闭，开启由用户明确选择。先支持一个冻结的 Cubism 3+ `.model3.json` 资源闭包，不承诺 Cubism 2 或所有 Editor 新特性。

| 必交功能 | 边界/可观察结果 |
| --- | --- |
| 实际 Live2D | 真实 `.moc3`、纹理、`.motion3.json` 加载和播放；至少一段空闲动作与一段点击触发动作，证据含模型/动作 hash 与录屏或自身窗口帧 |
| 宿主状态展示 | idle、thinking、executing、success、failure；Waiting/NeedsReview/Uncertain/Cancelled、关闭和降级有准确中性表示；不编造后台细粒度进展 |
| 窗口互动 | 透明背景、拖动、点击、显示/隐藏、显式关闭桌宠、位置保存/恢复、置顶与输入穿透控制；鼠标命中与拖动阈值有区分 |
| 显示环境 | 逻辑坐标/DPR/物理 framebuffer 分开处理；缩放、负坐标多屏、工作区限制、断屏与屏幕变化后可找回 |
| 生命周期 | 主窗口/托盘/桌宠独立显示状态，统一宿主退出；加载中退出、反复开关/加载/释放、图形失效与异常退出可收敛 |
| 降级与资源 | 依赖/SDK/模型缺失、加载损坏、GL 失败、渲染崩溃/挂起不影响任务权威状态；有界帧率、队列、日志、启动/退出期限，隐藏停止绘制 |
| 依赖与交付 | CLI 无 Qt/Live2D 仍可运行；optional extras 由 pyproject 统一声明；给出安装、缺资源诊断、许可清单与同构建验证证据 |

不包含：模型商店/任意在线下载、用户脚本/可执行角色卡、面捕/摄像头/麦克风/语音口型、音频播放、全屏桌面采集、第二 Core、自主工具、V0.6 迁移、V0.8 人格情绪、完整安装器/自动更新。模型切换 UI 及任意第三方模型导入不作为首版必交；开发验证中的重复加载不等于承诺通用模型平台。

素材暂缺时可以交付“桌宠控制和降级接口已实现”，必须明确“真实 Live2D 未验证/被资源阻断”。只完成无模型部分不能称 V0.7 已交付。五种宿主状态可采用模型内合法动作/参数或中性状态标识组合，不能为了凑五个动作擅自修改素材；实际映射在阶段0随模型冻结。

## 3. 不可退让的架构与线程条件

1. 所有请求仍由 `ApplicationBridge → DesktopFacade → ApplicationService → 单 dispatcher/Core` 处理。表现层不能直接调用工具、写数据库、确认/恢复计划或修改工具参数；点击默认只做本地动作，打开任务仅导航并重新查询。首版桌宠不提供 confirm/submit/resume 的快捷按钮。
2. 渲染器仅接版本化、无正文的表现 DTO 和已核验资源描述；不得接 Application/Core、API key、配置文件、SQL 连接、整份 Task/Plan/Memory、任意 Python 对象/pickle。动作名来自固定映射，模型 JSON 内的字符串不是命令。
3. 后端及 CLI 不反向导入 PySide6/Live2D；桌宠关闭后原 GUI/CLI 行为不减少。渲染状态与任务状态为独立状态机，渲染故障不能改 TaskStatus、触发重放或增加 attempt。
4. 优先验证**独立渲染进程**，复用现成 SDK/绑定；原因是原生崩溃与耗时调用需要与宿主 GUI 分离。它是普通表现进程，**不是 V0.6 Worker/安全沙箱**，不能据此接受不可信模型或 Python 插件。
5. 宿主 GUI 主线程只做有界 DTO、窗口控制和异步进程信号；禁止 SDK 初始化、模型加载、同步 wait/join。渲染进程自己的 Qt GUI 线程负责 QWidget、上下文 current、纹理上传/绘制/显式释放；纯文件检查/读取可异步，不把同一个模型对象/GL context 随意跨线程使用。
6. 必须核对所选版本模型加载的 CPU/GL 分离能力、GIL、线程安全与析构路径。若只有单次长同步加载，不在宿主中调用；阶段0需如实报告渲染进程自身事件循环的停顿及控制超时，不把“另起进程”冒充加载全异步。无法满足冻结的响应/回收门槛时改适配或候选，不降低边界。
7. 资源释放必须在正确线程和有效 current context 下完成，处理 context 重建/丢失；不依赖 GC 恰好在 GUI 线程运行。进程退出是故障兜底，正常关闭仍要证明显式清理。宿主异常退出时子进程须独立发现父进程/IPC 消失并退出；单纯 closeEvent 不足。
8. 渲染子进程使用明确启动入口和最小环境变量白名单，不继承密钥环境，不加载 `.env`/生产配置/用户库，不把密钥放命令行。父子不因渲染重启而新建 Application 或提交任何任务。

## 4. 状态与交互判定

现有 `ApplicationBridge.state_changed` 表示 Initializing/Ready/CleanupBlocked/StartupFailed/Closing/Closed，**Ready 不等于 Core 空闲**。现有通知流仅覆盖部分终态，受通知开关控制，不能作为完整桌宠事件源。实施时增加 Qt-free 的最小状态投影/查询，提供当前活动任务的状态摘要；经桥接异步取得，不能从页面选中项、聊天文本或动画结束回调推断成功。

| 权威输入 | 展示语义 | 禁止推断 |
| --- | --- | --- |
| 无活动任务且快照新鲜 | idle | 查询超时不能假定 idle |
| Created / 提交已受理但尚未开始规划 | queued，中性排队提示 | 受理回执不代表已开始执行；不能播放 executing |
| Planning | thinking | 不显示模型内部推理或编造百分比 |
| Running | executing | 不把已入队/等待确认当作已执行 |
| Waiting | waiting，中性待审核提示 | 不自动授权，不播放成功 |
| Completed / Failed | success / failure，短时展示一次 | 动画完成不更改任务；有部分副作用的 Failed 不表示已回滚 |
| Cancelled / NeedsReview / Uncertain | cancelled / review / uncertain，中性提示 | 不惩罚用户、不自动恢复/重放，不用“失败已撤销”覆盖未知事实 |
| host Closing / Closed；数据过期 | closing / 停止；unknown | 迟到成功动作不能覆盖关闭/未知状态 |

投影带 schema_version、session/generation、单调 sequence、状态 revision、隐私 epoch、有效期和固定枚举；不含请求/结果/标题正文。宿主生命周期优先；活动工作优先于短时终态，最新 revision 优先，旧/乱序/重复事件不重播。加载、重连或恢复显示只读取最新快照，默认不补播历史成功/失败动作。查询过载采用最新值合并与失效标识，不能无限缓存或挤占取消/退出通道。

## 6. 性能与资源门槛的冻结方式

阶段0先记录机器、显卡/驱动、Qt/QPA、GL vendor/renderer/version、显示器/DPR、模型复杂度与资源 hash；在同环境测“宿主不启宠”的基线，再测整个宿主+渲染进程树。CPU 采用进程树 CPU 时间/墙钟（100%=一个逻辑核），不要混用任务管理器的整机归一化数值。GPU 指标不可得时记 unavailable，不能以0代替。

以下为首轮**候选预算**，尚未测量/冻结；阶段0按实测写 decision record 后、正式验收前冻结，失败后不能悄悄放宽：

| 指标 | 初始目标/测量方法 |
| --- | --- |
| 帧率 | 活跃上限30 FPS，空闲上限15 FPS；隐藏/关闭无周期性绘制，恢复钳制 delta，不补睡眠期间帧 |
| 宿主响应 | 50ms heartbeat：p95≤100ms、最大间隔≤500ms；100次显示/隐藏/关闭控制可见回执 p95≤250ms，包含慢 Core/加载探针 |
| 启动/故障期限 | 模型启动超时10s，关宠正常回收目标3s，表现子进程故障兜底目标5s；异步检测/回收，不强杀 Core；时限不代表所有模型可加载 |
| CPU | 单模型热空闲5分钟渲染增量平均≤5%单核、持续动作≤15%单核；隐藏后≤1%单核；报告峰值和采样粒度 |
| 内存 | 热稳定增量 private bytes 目标≤300MiB（宿主+子进程合计）；RSS 单列，不将进程退出后 OS 缓存当泄漏 |
| 循环稳定 | 预热10轮后100轮，每轮回到关闭/稳定状态；宿主最终 private bytes 增量≤20MiB、句柄≤10、线程回基线；同时看斜率和存活资源，不能仅末值达标 |
| GPU/长测 | 记录显存/引擎占用/GL资源计数（可得项）、30分钟趋势和退出回收；持续增长或未解释异常即不通过，缺指标明确未测 |

一次卡死、错误线程析构、崩溃、退出挂起、持续资源增长、任务重复副作用或证据矛盾均为阻断。先保留原始日志/转储/构建，不用“重跑通过”消除首败；父 Agent 归因与审查修复后，Luna 执行复验，父 Agent 最终验收。

## 7. 完成判定与证据格式
