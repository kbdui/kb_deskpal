# V0.4 验收边界

日期：2026-10-15。状态：**拟议通过标准，不是已完成测试结果**。配套[开发计划](development-plan.md)、[环境评估](environment-assessment.md)。V0.3 报告只作已有基线，不能自动算作 V0.4 通过。

## 交付闭环与范围

用户可用 CLI 创建带完成标准的 Goal/Milestone、显式关联日程/Task；开启本地提议后查询/接受/忽略建议。接受可靠形成持久工作项，忙时排队；需要工具确认时展示准确参数，普通与高风险授权保持分开。退出/异常重启能看到目标、提议、任务、已完成步骤和未知执行区间，重新审查后才恢复。

必需范围：单机单运行实例、工作库、显式 Goal、版本化 Plan、步骤检查点、本地规则、持久队列、CLI、恢复审查、Memory 派生副本清理和可观测故障。只完成 Goal CRUD 或把 Task 序列化，不算全版交付。

## 必须使用子进程的崩溃场景

只抛 Python 异常不足以证明恢复。采用合成工具与临时目录，设置可握手故障点，再终止或异常退出测试子进程；不得杀用户进程或修改真实文档。

| 注入点 | 重启后必须满足 |
| --- | --- |
| attempt 尚未提交 | 工具零调用，未开始工作待复核 |
| Started 已提交、工具尚未真正调用 | 保守 Uncertain；不能据测试知道“尚未调用”推断生产安全重试 |
| 工具已写合成效果标记、结果尚未提交 | Uncertain；标记保留且绝不自动再写一次 |
| 第一步结果已提交、第二步未开始 | 不重放第一步，展示部分完成，本版不自动恢复剩余步骤 |
| 全部工具结果已提交、Reflect 或终态落盘前 | 从结果收尾并警告，零重放、零自动补云 |
| 最后一步结果可靠提交，取消请求已提交，终态未写 | 保留取消语义及已发生效果，不能用默认收尾覆盖成普通 Completed |
| 取消请求已记录、工具结果仍未知 | 保留取消意图和 Uncertain，不伪装无副作用的 Cancelled |
| Proposal 接受事务提交前/后 | 事务前可重试；事务后重复接受返回同一 Task |
| inbox+接收cursor 或 Proposal+处理进度事务任一阶段 | 回滚重读或识别已提交；未处理inbox/continuation重启仍可续办，无重复/漏项 |
| deletion_job 已提交，Memory forget 尚未执行 | 相关计划/grant已阻断；重启先续办，清理失败仍保持阻断 |
| Memory 删除后、workflow 副本擦除前 | 启动先续办 deletion_job；旧请求/Plan/结果/提议不重新显示/出云 |
| 含敏感正文的 outbox 未投递时 forget，再恢复投递 | 待投递payload/回执缓存一并清理，JSONL不新增已忘正文；Uncertain保留不透明证据而非正文 |
| outbox 提交后、JSONL 确认前 | 允许同 event ID 再投日志，禁止再执行工具 |

Uncertain 人工复核只记录判断与证据；不直接给原步骤执行资格。新重试工作必须有独立 ID/计划/确认，且旧未知状态可追溯。失败结果可能包含部分效果，失败不构成自动重试许可。

## 竞争、事件和时间边界

- 并发提交、重复 command ID、双 accept、accept 与取消/过期、claim 与 close，通过事务/CAS 给出唯一结果，不依赖测试线程恰好串行。
- Goal 执行版本、Memory 修订/TTL/用途、工具契约/权限/workspace 在排队、规划、展示、确认、执行边界分别改变，旧工作均被阻止。
- timer/calendar 使用交错全局 event ID 和分页；空页、只含失效事件、源库换代/游标倒退/锚点改变分别验证。新启用默认不补读全部历史。
- 100个合格事件、每轮最多10建议，跨轮重启最终100个且无遗漏；同一事件超过单轮扇出上限时也不饿死后续。一个事件关联两个里程碑各有建议，取消其中一个只封禁相应作用域。
- 日程内部 occurrence revision 不等于全字段版本；修改标题、改提醒、删除日程后，历史事件仍可查，但旧 Proposal 不能拿历史内容作为当前计划。
- 静默期覆盖跨午夜、上海与 DST 时区、休眠/离线后启动；过期建议直接终结，允许用户显式查询历史。持久时点使用带时区 UTC，进程内间隔使用单调时钟；不把 monotonic 值跨进程持久复用。
- 首版只接受显式偏移的截止时刻和明确 IANA 时区；不猜测“明早八点”，不依赖 LLM 处理 DST 缺失/歧义时间。无时区数据时明确拒绝相关配置，不悄悄按 UTC 运行。

## 隐私与权限的专项验收

本地规则只消费用户绑定的 Goal/事件；普通聊天、Memory candidate/legacy/外部文档不能直接成为目标或自动副作用意图。不要只检验原 Memory text 是否外发，还需捕获 Proposal reason、TaskIntent、Plan reply/arguments、日志及在途结果派生链。

日程/目标原文即使允许显示在本地，也不自动获准送给云 Planner。新 Goal/SourceBinding 默认 local_only，派生用途取最严格限制；云规划需先明确修改原对象/绑定用途并递增版本，不能单独给 TaskIntent 换成 cloud_allowed 绕过来源。不能用“接受建议”隐式扩大用途。local_only 及派生受限内容在启动、出队和每次云出口前复核；在途已发请求不能撤回，响应过期/取消后不能重新发布工作。

Memory forget 清理明确来源派生的工作副本，不按相似文字删除用户独立创建的 Goal/日程。回执区分已清理、待重试、独立保留对象和历史日志/备份/外部副本；工作库清理失败时不返回全完成。删除/恢复接口必须走受控 Application，直接手工改 SQLite 不属于同步清理承诺。

实例锁测试、工作库崩溃测试不得作为常规 skip 计为通过；目标 Windows 环境不能执行时，对应里程碑未验收。旧 Windows symlink 权限跳过继续明确记录，不算本版已补齐 OS 隔离。

## 建议容量与资源门槛

以下为**开工前建议冻结目标**，尚未测量，不是已达性能。切片 0 可依据同机空闲资源调整并记录理由；不得在失败后只修改报告门槛。

| 维度 | 初始目标与测法 |
| --- | --- |
| 功能容量 | 合成 1,000 Goals、10,000 Tasks、20,000 step attempts、20,000 Proposals；分页查询 ≤100 条，稳定顺序 |
| 提交背压 | 默认最多 100 个待执行提交；满队列明确拒绝；失败接受事务不留下孤立 Task/Accepted |
| 事件处理 | 每流每批 ≤100、每轮新 Proposal ≤10；真实重复/重启不增加同一业务建议；积压跨多轮消化 |
| 本地交互 | 已预热无模型的 submit/accept/list，100次测量 p95 ≤200ms，含必要工作库事务，不含用户等待/LLM/工具 |
| 空闲资源 | 主动本地轮询启用、无事件5分钟；workflow增量 working-set ≤64MiB，CPU按单核100%口径平均≤2%；模型另计 |
| 关闭 | 无活动调用时≤5秒；阻塞测试工具时不强称完成，不释放在用依赖，仍可报告取消/关闭进度 |
| 稳定性 | 至少30分钟本地事件/提交循环，连接/线程无单调增长、队列不无限扩张；不替代Beta长期运行 |

资源报告记录机器/版本、冷暖状态、样本数、CPU百分比分母、RSS基线和峰值。V0.3 的语义 p95 不能拿来证明 workflow 开销；同样本版无需为了本地规则重跑模型调参或更换 embedding。

## 发布门槛与不承诺事项

发布前必须有实际接口文档、状态/恢复表、工作库 schema/备份说明、依赖约束、CLI 示例及测试报告。默认离线全套不读个人配置、不联网、不采屏；真实 API 如相关路径变化需独立说明必要性、合成数据和新授权预算，之前的三次授权不能复用。没有后台云功能，因此不以“后台金额预算”作为已完成能力。

完整 V0.4 必须通过所有必需项，失败/跳过/未实现分别列出；只有 Goal CRUD 或本地提议演示通过时，只能报告阶段成果。数据丢失、权限绕过、未知步骤自动重放、隐私副本复活、双执行者均阻止发布。

本版不承诺外部效果 exactly-once、自动回滚、同步工具强制中止、多实例执行、跨库任意备份恢复一致性、无人值守执行、后台云智能、精确费用预算、系统通知/托盘、Qt/Live2D、人格情绪、多轮 WorkingContext 或完整 OS 隔离。这些边界不妨碍本地目标→提议→持久任务→审查恢复的完整闭环。
