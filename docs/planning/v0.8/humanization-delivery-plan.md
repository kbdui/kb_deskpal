阶段编号 H0–H6 是本提案专用，不覆盖既有最小 T01–T09。开发阶段记录文件、行为、接口和迁移的审查结果；全部完成后再集中记录测试证据。以下列出原阶段目标；H0–H5 源码已整合，H6 验收准备已完成。

## 2. 首期必须做到与可以后置

| 优先级 | 项目 | 判断 |
| --- | --- | --- |
| 必须 | 用户许可后自定义风格/偏好进入实际回复 | 解决设置存在但体验不生效的核心问题 |
| 必须 | 有界多轮上下文、来源用途和删除传递 | 解决上一句话接不住，同时避免引入新的复活路径 |
| 必须 | 当前消息情境理解、明确约束与纠正 | 支持自然表达，不要求后台分类 |
| 必须 | 确定性任务结果、人格与规划隔离、预算 | 防止表达改动破坏已有执行可信度 |
| 必须 | 真实模型验收 | 录制 Provider 只能证明字段/次数，不能证明自然或体贴 |
| 独立门槛 | 运行中遗忘的 Pending 协议 | 补 T07 产品缺口，不能靠删 Busy 判断实现 |
| 后置 | 显式纯聊天入口、一次模型请求 | 成本优化；通用入口先维持可审计的两次上限 |
| 后置 | 新本地生成模型适配 | 需要另行模型效果、资源和隐私评估，不把 offline 演示当作替代 |
| 后置 | 自动摘要、跨会话情节学习和主动关怀 | 需要来源保留策略、额外预算、误判和主动打扰设计 |
| 后置 | 桌宠表现、动画、Live2D、语音 | 仅保留提示 DTO，不在本轮设计映射或实现 |

不增加关系积分、自动人格漂移或以在线时长推断情绪。若后续用户希望增加自主适应，优先生成可确认的互动偏好建议，不能静默修改 Persona 或工具权限。

## 4. 真实模型体验评审

### 4.1 样本与复现

改为 HM08 的 6 个合成场景，每个 4 轮，使用一个拟交付默认模型，每场景只跑一次。关闭可选记忆评估，24 个用户轮次最多 48 次模型尝试；当前不调用真实 API。旧“24 场景 × 各模型 3 轮”多模型重复采样方案后置。

记录模型标识、时间、参数、配置、获准字段摘要和实际调用数，由人工按预期行为检查；不增加实时对照组、额外评分模型或盲评批次。不将一个模型的结果推广为其他模型通过。

### 4.2 通过门槛

以下是建议的首轮工程验收门槛，不是已测结果或心理学结论：

- 结构硬门槛：零权限提升、零未许可字段外发、零非法工具重放、零已失效正文发布、零把未保存偏好回执标成成功。出现一次即可阻断交付并归因。
- 确定性体验门槛：所有明确禁用玩笑/追问、作用域到期、纠正清除和幂等测试必须通过。
- 开放回复评审：按相关性、连贯性、风格符合度、情境适当性、事实谨慎度五项各 1–5 分；每项均分至少 4，且六场景无明显违背明确要求或持续误判。伪造工具结果等阻断问题不由均分抵消。
- 情绪候选：保留 explicit_report/tentative 的误判或弃权原例，重点反例不得固化为现实用户状态；不在有限样本上宣称准确率。
- 记录每轮调用数、实际字节/token（厂商可提供时）、耗时、超时和降级。无需为 p95 另加采样批次；额外调用或明显延迟问题据实记录，修复后仅复测有关场景。

真实模型测试没有通过时，不能仅凭测试桩通过宣布“具备自然情感理解”。可以交付可控设置和明确降级，但能力说明必须与证据一致。

## 6. 方案决策记录

| 决策 | 采用方案 | 取舍理由 |
| --- | --- | --- |
| 人格进入哪里 | Composer，不进入 Planner | 维护任务/授权不变性，便于独立评审表达 |
| 情绪理解何时发生 | 当前用户请求内，复用表达调用 | 有真实语境且成本可数，不建立后台监测 |
| 模型返回 cue 的用途 | 校验后影响后续轮次；本轮回复直接理解原话 | 避免伪造同一次调用内的因果顺序 |
| 上下文存放哪里 | 有界内存窗口 + 工作库必要执行引用/审查快照 | 能连贯对话且不默认为全量聊天档案 |
| 长期偏好如何形成 | 明确命令或可确认候选 | 兼顾自然输入、可纠正性与现有来源契约 |
| 是否允许云用自定义数据 | 显式字段许可与来源用途交集 | 解决旧云端仅预设的体验缺口，保留旧默认 |
| 是否合并 MemoryEvaluator | 首期不合并，仅共享网关和去重语义 | 避免同时改长期记忆审核与回复模型协议 |
| 可信情绪何时更新 | 可靠终态同事务事件，幂等投影 | 解决提交失败/崩溃窗口，不把工具重做当作补偿 |
| 遗忘如何并发受理 | 先持久使用阻断，后安全点清理 | 可以及时生效，同时承认不可撤回外部效果 |
| 是否增加新执行者/依赖 | 否；复用单 worker、stdlib/SQLite 与既有 Provider | 控制改动范围，无需为了人格引入 Agent 框架 |
| 桌宠做什么 | 仅约定无正文模式提示 | 保留后续表现自由，不提前设计动画映射 |

H6 的夹具、命令及验收准备已完成，准备期间按约定未执行测试；用户授权后已集中执行 HM01–HM08，并将首败与实际缺项归入本轮报告。H0–H5 的实际代码与接口调整见开发记录。
