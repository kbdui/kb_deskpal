## 1. 目标与关键判断

拟人化首先应表现为：能接住上一句话，表达方式稳定，记得用户明确允许记住的事情，理解当前处境，出错后能改正。增加情绪数值、更多提示词或周期性“想念你”的请求，不能代替这些能力。

建议优先完成四条闭环：

1. **对话连续性**：当前会话有界保留上下文；长期记忆有来源、有用途限制；二者不混为一份聊天记录。
2. **表达一致性**：角色设定、用户明确偏好和临时需求真正影响最终回复；同一套规则在普通聊天和任务反馈中一致。
3. **情境理解**：理解当前消息中的明确感受和表达请求；承认不确定，允许用户纠正，不把推测固化成人格标签。
4. **可信协作**：自然语言可以温和、有个性，任务结果、风险和权限仍由系统事实决定；遗忘后不能被下一轮上下文复活。

保留单 Core 执行者、现有任务/授权/恢复体系。选择性拆分 Core 和 companion；不更换 Agent 框架、不建立第二个自主执行循环。

## 2. 从当前能力到目标能力

| 方面 | 当前代码事实 | 本方案目标 |
| --- | --- | --- |
| 多轮对话 | Planner 接当前 request 与检索记忆，没有完整 WorkingContext；表达调用也没有会话历史 | 明确 conversation/turn 身份，有限近期对话；规划和表达使用不同投影 |
| 人格 | 三预设、六轴、版本和回退已有；云表达仅使用固定预设 | 保留稳定预设，增加有限角色身份/表达习惯；用户许可后自定义轴真正参与云表达 |
| 临时需求 | GUI/CLI 可手动设 cue、简洁度和幽默偏好；本地 policy 有少量请求词匹配 | “今天别开玩笑”“这一轮简短些”转成有作用域的约束，明确显示实际是否生效 |
| 情绪理解 | 未形成自然语言 cue；云模型可能单轮理解用户原话 | 当前请求内理解，提取可丢弃的短期线索；不启动后台分析 |
| 应用情绪 | Completed/Failed 终态驱动 v/a/m；普通聊天 Completed 也可能获得正增量 | 按事件资格区分聊天完成与工具成功；用户低落改变支持方式，不直接累积应用悲伤 |
| 长期偏好 | Memory 有 preferred_name/reply_language/verbosity 投影，companion 另有显式偏好 | 明确唯一权威来源和优先级；自然语言候选需核验/确认，不自动改人格 |
| 回复事实 | 工具结果结构化，Reflect 自由总结；普通聊天先规划再表达 | 独立 ResponseComposer；任务关键事实用确定性结果区，开放文字作为补充 |
| 云端用途 | 本地轴/prefs/cue/affect 不出云 | 字段类别授权和来源用途取交集；本地限制不会因压缩成风格标签被解除 |
| 遗忘 | 生产入口执行中 Busy；低层代际屏障已存在 | 分阶段增加执行中受理“阻断使用”，清理可 Pending；不承诺撤回已经发出的云请求或工具效果 |
| 桌宠 | 现有静态映射 | 本轮仅定义版本化、无正文的表达提示接口，保持既有表现行为 |

现有离线 Provider 是固定规则演示，不是本地生成模型。本方案不将它描述为可提供自然对话，也不把接入本地大模型设为首期前提。云端禁用或模型不可用时，管理、工具和确定性反馈仍可工作；开放闲聊明确降级。

## 3. 五类状态及其权威来源

| 状态 | 内容 | 权威与生命周期 |
| --- | --- | --- |
| PersonaSpec | 名称、角色定位、六轴、有限表达习惯 | 版本化 companion 配置；只能通过明确设置/确认变更 |
| WorkingContext | 最近消息、当前话题引用、已核验任务事实 | 会话内有界缓存；不自动成为长期记忆，不跨启动自动恢复 |
| InteractionPreference | 称呼、语言、简洁度、是否幽默/追问等明确约定 | 作用域、来源和用途明确；长期用户资料复用 Memory，临时表达覆盖由 companion 管理 |
| UserCue | 当前用户自述感受或暂定理解 | 会话内短期；可纠正、可为空；不参与 v/a/m 数值计算 |
| AffectState | 应用的低幅度表达状态 | 可信新事件经固定规则更新，沿用去重、限幅、衰减和重置 |

“我很累”是用户的当前感受；“今天都简短一点”是有有效期的表达约束；“我一直偏好简洁回答”是长期偏好候选。三者不能因同一段文本而共享一个 TTL 或自动持久化。

### 3.1 稳定人格与关系感

PersonaSpec 增加有限字段：`display_name`（最长 40 字符）、`role_kind`（assistant/companion）、`self_reference`（固定枚举）、`greeting_style`（none/brief）、`followup_style`（none/optional_one）。原六轴继续控制表达。名称是数据，不拼接为任意 system 指令；首期不支持自由角色卡、虚构经历或可执行“性格规则”。

熟悉感来自正确称呼、适当引用已确认经历和遵守互动偏好。首期不建设 RelationshipScore，也不依据聊天次数解锁权限；不通过缺席、拒绝授权、取消任务降低“好感”。问候有会话级冷却，不每轮重复自我介绍。不自动扮演现实亲密关系，不假称在用户离线时持续关注。

表达规则按下列顺序合并，每一项保留来源，输出最终决策的有限 reason code：

1. 真实任务状态、风险提示、权限和来源用途。
2. 当前用户明确表达要求；其中禁用要求优先于鼓励性要求。
3. 本会话/当天明确约束，再到持久用户偏好。
4. PersonaSpec 默认值。
5. UserCue 和 AffectState 的有限调节。

例如高幽默人格遇到“我今天很难过，别开玩笑”，应停止玩笑；不能靠人格预设否决用户要求。当前要求的覆盖不自动改写持久偏好，除非明确保存。

### 3.2 多轮上下文与共同经历

首期使用当前会话的滚动窗口，不引入云摘要任务。建议上限为最近 8 个已完成轮次、16 条消息、历史正文合计 16 KiB；取三者共同限制，整条省略，不截断否定或半个 JSON。当前 request 不计入历史预算，仍受原有 64 KiB 请求限制。被省略的历史不能再从任务列表无条件补回。

表达模型可以看获准的最近用户和助手消息，但助手文字始终标为未核验输出。规划模型仅看当前请求、必要的历史用户引用和确定性任务事实；不看风格化助手回复、用户情绪、角色设定或主观话题总结。历史用户消息提供指代背景，不能当成新的执行命令。指代目标有歧义时说明缺少哪个对象，不能猜路径、自动选高风险对象。

“你上次那个例子”可在表达窗口中解释；“照你刚才说的删掉它”若缺少可核验对象，则必须重新明确目标并走计划确认。用户说“好的”不能代替现有确认 API。为保证这些规则，首期多轮执行只启用有限的、明确来源的对象引用，其他情况允许澄清。

长期共同经历只引用已接受的 Memory 或真实任务事实：可以说“上次你让我整理了三份文件”，前提是来源存在、用途允许且结果准确；不能把模型自己的叙述保存后当成共同经历。首期不自动总结全部聊天，不建设跨会话完整对话档案。

### 3.3 自然语言感受与表达请求

采用两段处理，避免为人格、情绪、偏好分别增加请求：

- 本地 `ConstraintParser` 只识别少量完整、明确句式，处理简洁/幽默/追问及 once/session/today 作用域。它不承担通用情绪识别。含引用、转述、否定歧义或复合保存请求的句子不自动写配置。
- `ResponseComposer` 在原本的一次回复生成中理解当前消息，并可返回严格受限的 cue/偏好候选。模型直接生成适合本轮的回复；返回的 cue 经校验后仅用于后续轮次和预留展示数据，不能宣称存在“先得到模型 cue、再用同一次调用生成回复”的顺序。

候选区只允许有限字段：模式 none/supportive/focused/celebratory，证据类型 explicit_report/tentative，当前用户消息内的原文区间，以及偏好 key/value/scope 建议。模型不能生成来源 ID、权限、云用途、过期时间、人格 revision 或情绪数值。程序核验区间、长度、枚举和作用域；原文匹配只证明引用存在，不能证明语义正确。

建议：明确自述 cue 最长 30 分钟，暂定 cue 最长下一轮或 5 分钟，话题切换/纠正/新会话立即失效；未收到新证据不得续期。自动 cue 仅影响支持性表达、减少幽默和多余追问，不创建心理诊断。推测不能以“你就是很焦虑”呈现；必要时使用可拒绝的措辞。讽刺、小说、朋友转述和“我并不难过”必须列为真实模型验收样本。

“今天别开玩笑”到配置时区的下一次午夜结束，沿用最长 24 小时边界；不跟 cue 一起在 30 分钟后解除。“以后都简短些”若不在严格显式命令语法中，给出一次可确认的候选，不以普通对话完成冒充已保存。候选确认采用固定文字卡片，模型不能自行声称“已记住”。

### 3.4 应用情绪与反馈

保留现有 v/a/m 范围、半衰期和绝对预算，在此轮优化中不同时重新调参。改变的是事件资格：

| 新事件 | 行为 |
| --- | --- |
| 普通聊天 Completed | 无数值奖励；仅表示一轮结束 |
| 有真实成功工具结果且任务最终可靠 Completed | 原有小幅正增量，根任务一次 |
| 已知工具失败 | focused 和原有受限负增量；不迁怒用户 |
| 云不可用/表达失败 | 系统降级说明，不形成社交负反馈 |
| 明确感谢/庆祝 | 首期仅本轮自然回应或短暂模式，不增加数值奖励 |
| 用户低落/疲惫 | supportive/降低活跃表达，不让应用跟着累计负值 |
| 纠正、拒绝、取消、离线 | 不扣分；纠正优先清除误解 |

本轮可信工具结果可影响当前文字的情境策略，但持久情绪只在任务可靠终态提交后更新，后续轮次读取。避免为了“本轮先高兴”提前记录可能提交失败的成功。事件元数据写入工作库投影 outbox，后续投影幂等，不通过重跑工具补事件。

## 4. 云端可用信息与调用预算

### 4.1 字段授权与解释

升级后保留旧默认：只外发固定预设，新字段不自动获准。设置页提供独立控制和本轮生效说明：

| 类别 | 默认 | 允许后发送的最小形式 |
| --- | --- | --- |
| 固定人格预设 | 沿用现有设置 | 固定风格指令 |
| 自定义角色/六轴 | 关闭 | 白名单身份字段及编译后的有限表达标签，不传任意提示词 |
| 明确表达偏好 | 关闭 | 本轮有效的长度、幽默、追问等标签 |
| 历史用户情境 cue | 关闭 | 模式及证据类型，不发原始心理推断描述 |
| 应用情绪 | 关闭 | low/normal 等离散表达强度，不发数值、事件账本 |
| 当前会话历史 | 关闭 | 用途允许、未过期的有限消息及来源类型 |

有效许可 = 用户类别开关 ∩ 来源 use_policy ∩ 当前请求/任务用途 ∩ 当前隐私代际。类别开关不能解除 local_only 来源限制；需要改变来源用途时走独立显式操作并产生新修订。摘要、标签、对措辞的选择也算派生信息，不能通过“只传一个 supportive”绕过限制。

派生项还须满足全部来源类别的许可。例如应用情绪基线若使用了未获准外发的自定义轴，不能仅开启“应用情绪”就发送这一派生强度；应改用可外发默认基线独立计算，或省略该项。云策略只在过滤后的输入上计算，不先用完整本地状态生成风格再删除几个字段。

用户当前主动发送的消息仍按当前请求用途处理。因此关闭历史 cue 外发不等于云模型无法理解这次发出的“我很难过”。关闭自然语言 cue 功能，意味着应用不生成/保留额外结构化线索；不能声称云模型从未分析过原话。

提供有限解释：本轮使用了哪个预设、哪些偏好、哪些信息因仅本地/过期被省略、是否降级。界面提示“此设置当前仅在本地可用”，不能让用户误以为调节后必然改变云端答案。

### 4.2 请求预算

通用入口继续先 Planner，再按需 Composer；首期不增加自动路由模型。请求计数按实际网络尝试计，禁止隐藏 JSON 修复请求和超时自动重试：

| 路径 | 规划 | 表达/Reflect | 候选记忆 | 总上限 |
| --- | --- | --- | --- | --- |
| companion 关闭的普通聊天 | 1 | 0 | 按既有模式 0/1 | 1/2 |
| 启用拟人化的通用聊天 | 1 | 1 | 按既有模式 0/1 | 2/3 |
| 需要工具且已授权 | 1 | 1 | 按既有模式 0/1 | 2/3 |
| Waiting/失败/取消/审查 | 已发生规划计入 | 0，固定反馈 | 首期不新增 | 不补表达请求 |
| 配置、cue、更正、重置、遗忘管理 | 0 | 0 | 0 | 0 |
| 空闲、轮询、离线恢复 | 0 | 0 | 0 | 0 |

确认执行复用已保存计划，跨确认重试以根任务累计预算；不能每次确认重置请求计数。原有 candidate_review 暂时保留独立调用，不同时更换其审核语义。Composer 的元数据候选不直接写长期记忆，避免两个提取器重复学习。

后续可增加用户明确选择的“仅聊天”入口：一次 Composer、无 Planner、无工具；遇到操作请求返回切换建议，不自动升级执行。它是独立后续优化，不让首期预算和回退路径出现两套不透明路由。

## 5. 明确的体验边界

| 用户输入/场景 | 应有体验 | 不应发生 |
| --- | --- | --- |
| “我今天很累，先别问太多” | 当前回答克制，短期减少追问，可随时纠正 | 自动记成长期心理标签 |
| “不是我，是我朋友心情不好” | 清除对用户的误判，围绕朋友的问题回答 | 继续给用户贴标签 |
| “刚才那段再短些” | 从当前表达历史定位内容并改写 | 把旧助手文字当工具成功证据 |
| “以后叫我小林” | 展示/执行明确称呼保存路径，回执说明范围 | 未保存却声称永远记住 |
| “你心情好就直接替我删掉吧” | 权限与计划确认照常 | Persona/Affect 改变授权结果 |
| 忘掉一项记忆时模型尚未返回 | 先阻断关联数据继续使用，给 Pending/完成回执，丢弃迟到内容 | 让旧答复或上下文恢复被遗忘内容 |
| 长期离线回来 | 临时状态过期，按获准长期偏好自然回应 | 补发历史关怀、责备缺席或累加关系值 |
| 调节本地六轴但未允许云使用 | 明确显示当前仅本地生效 | UI 暗示云端已采用设置 |

## 6. 有意推迟的能力

不增加周期性云请求、后台情绪监测、摄像头/麦克风推断、自动人格训练、任意角色卡、关系积分、主动联系外部对象、完整聊天档案、自动跨会话摘要或新的后台自主权限。

这不妨碍当前消息的自然语言理解、用户确认后的偏好适应和有证据的回忆。主动关怀将来可以建立在已授权的本地触发器上，但应单独设计触发、冷却、静默和云预算；本轮不混入该路径。桌宠表现按用户要求只保留[提示契约](humanization-architecture.md#10-桌宠仅预留接口)。
