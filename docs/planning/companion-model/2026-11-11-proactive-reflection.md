# 角色自主思考：设计与实施记录

日期：2026-11-11。本文记录本轮已实现的自主思考链路，不改变 28/29 日原始讨论，也不代表通用多人能力已开发。

2026-11-12 后续确认（待实现）：采用 [quiet 与按需记忆整理规则](2026-11-12-quiet-and-memory-consolidation.md)。普通自主思考 quiet 后只保留已提交成果及实际执行记录，不立即进入反馈学习，也不标记成果已整理；后续明确后台整理再处理。自由思考和 mode=reflection 本身不是整理例外。下文的即时学习、通常三次模型请求及相关用例通过，均是 11 日已有实现的历史证据，不能用来证明新规则已实施或验收。

角色可以在没有用户提问时探索自己的兴趣、自我认识及经历，形成简短想法，并决定是否继续探索、保存理解或向用户分享。程序提供机会并约束权限、次数与持久化；主题、内容、价值及是否需要更新旧认识由模型判断。没有新进展时允许直接安静结束，不强制产生日记或记忆。

## 触发与执行

新增默认启用的 `reflection` 主动方法。首次轮询登记四小时后的自由思考机会，不在启动时立即请求模型。自由机会和模型安排的继续思考共用滚动 24 小时最多三次、两次启动至少间隔一小时的限制；每次实际提交后，下次自由机会顺延四小时。预算、下次时间和关注安排保存在当前档案的工作流库，重启继续核对，不补做关闭期间全部积压机会。普通聊天或反馈学习也能提出 `mode=reflection` 的后续安排；它与记忆维护 `internal`、主动联系 `chat` 分开。

协调器先核对档案后台、清理状态、模型连接和执行线程占用，随后经现有 Submission Dispatcher → AgentCore 执行。繁忙时延后，不抢占当前工作；不在轮询线程里直接调用模型。用户任务与主动任务仍共享唯一执行线程。可以通过既有主动方法管理接口停用 `reflection`，停用时取消该方法尚未执行的关注；本轮没有新增设置页面或改变提醒控制。

内部思考不以允许发送聊天通知为前提，因此“暂停主动聊天”和免打扰期间仍可安静思考。若模型决定分享，继续经过现有最终表达润色及发布前通知检查；暂停或免打扰不会因自主思考被绕过。普通主动聊天的其他触发方法及约定提醒的履约方式保持原有含义。

## 思考成果与学习

新增自动管理工具 `reflection_record(topic, content, reason)`，只允许正在运行且未请求取消的主动任务提交。主题上限 512 UTF-8 字节，结论 4000 字节，依据/不确定性 2000 字节；每任务只接收一份成果，相同提交幂等，不同内容不能覆盖已提交成果。工具经现有执行账本运行，权限不会扩张，原先需要确认的其他操作仍需确认。模型可以不调用它，直接安静结束。

成果保存于当前档案 `workflow.sqlite3` 的既有 `context_snapshot`，使用 `purpose=reflection`，记录角色身份、任务、时间、主题、正文、理由及用途；同时登记 `reflection` 来源版本。没有新增顶层记忆类别或数据库 schema 升级。这个存储表示内部成果确实已提交，不等同于长期记忆已经采用。它与规划草稿、未发布聊天回复严格区分，不保存完整推理过程。

反馈学习读取宿主成果，在 catalog 中以 `character_reflection` 提供，关联实际角色的 speaker_id 与 `reflection` 来源引用；跳过该工具的普通 tool_result 证据，避免把“模型记录了一个想法”误当成想法内容已经客观成立。可形成假设、保留不确定理解、更新/合并旧理解或不保存。角色自身认识可以通过既有复核采用，无需用户确认；单凭这种来源不能写成用户陈述、客观观察，或自动采用对用户和外界的猜测。人格成长仍沿用 habit 缓冲与复核，不直接修改角色卡，不凭内部思考取得用户的明确授权。

提炼后的长期内容继续保存于 `memory.sqlite3`，稳定相处成长仍投递到 `companion.sqlite3`。下一次聊天通过既有相关性检索使用这些记忆，不单独拼入所有历史思考。学习安排继续探索时，可引用本次成果；工具安排继续思考时优先带上本次成果，避免仅拿原话重复思考。来源失效后，后续学习或关注不得把它当作仍然有效的依据。原有遗忘范围不扩大，聊天及实际执行记录不因本功能被连带删除。

## 模型指令与开销

规划系统指令增加自主选题、形成简短成果、允许 quiet、值得分享才 answer、使用 reflection 模式继续探索等要求。反馈系统指令解释新增来源，允许角色自身认识复核采用，并要求区分外界猜测、避免重复新建。模型自行决定语义，程序没有通过关键词决定“角色喜欢什么”或“应该有什么情绪”。

普通记录路径通常为：一次规划决定调用记录工具 → 工具回执后再次判断并决定安静结束 → 同步反馈学习。即通常三次模型请求；若对外分享，另有最终表达，补查、其他工具或有限重试也可能增加请求。不调用记录工具、没有新想法时不会强制新增成果或长期记忆，但正常反馈收尾仍沿用既有流程。因此“三次主动机会”不是“三次 API 请求”，也不限制其他主动方法的既有开销。日志新增 `character_reflection_submitted` 和 `character_reflection_recorded` 事件，模型逐次诊断继续走原有记录。

本节原测试结果对应 2026-11-11 旧收尾行为。“安静后立即学习”的预期已在 14 日更新，见文末实施补充；以下旧证据保留供追溯，不能用来判断当前 quiet 调用次数。

合成档案、可控模型完成六项新增定向用例：安静记录与学习并复核采用、学习安排继续思考、来源失效阻断；滚动预算与停用恢复不补做全部积压；模型安排后再次进入 Core 且不受聊天暂停阻止；预算重启保留；拒绝用户任务及已结束任务提交；禁止将自身猜测采用为外界事实。最终结果见 `build/reflection-final-boundaries-20261111.xml`，六项全部通过。

## 2026-11-14 按需整理实施补充（当前版本）

按 [是否回复与是否整理记忆的当前方案](2026-11-12-quiet-and-memory-consolidation.md) 调整：角色记录 reflection_record 后，模型独立决定 action 与 organize_memory。有值得保留的新成果，可 quiet + true 当轮整理但不发消息；也可 quiet + false 暂缓整理，只保存实际成果及工具回执。不因 quiet 自动跳过，也不因 answer 强制整理。没有新发现时通常可 quiet + false，不强制新增记忆。免打扰只影响实际对外发布，不替模型改变学习决定。

未整理成果在后续既有规划中有界提供给模型，模型选择 true 时由现有反馈阶段处理；明确的 internal 复查与已安排的到期记忆复查继续执行。取消同日较早的“八份材料门槛”和“每次回复必整理”方案；单批最多八份仅是输入上限，不触发调用。成功整理后才写实际来源正文的覆盖回执，保存成果不代表长期采用；最终决定经过多轮工具执行、快照与重启保留。不同路径的模型调用次数随选择变化，不再固定为两次或三次。当前测试和旧版本证据分别见[实施日志](../../reports/implementation-log.md)，未调用真实模型或修改真实角色资料。
