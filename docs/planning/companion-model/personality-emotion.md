# 人格、关系与情绪机制

范围更新（2026-10-15）：人格、关系、情绪与表现运行系统仍为未来设计，未随 0.3.0 交付。V0.3 仅投影用户明确的 preferred_name/reply_language/verbosity，不能据此称 Persona、RelationshipProfile 或 AffectState 已存在。实际范围见 [V0.3 交付](../../versions/v0.3/delivery.md)。

状态：2026-10-14 设计提案。人格/情绪运行实现按现有路线放在 V0.8；本轮只确定机制与跨版本边界。参见[总览](README.md)、[记忆](memory.md)、[集成验收](integration-and-acceptance.md)。

## 1. 模型选择

采用“稳定人格 + 明确互动偏好 + 短期事件情绪 + 慢速背景状态 + 表达调节”。不用一份不断追加的角色 prompt 管理所有状态，也不直接把心理学人格量表当软件旋钮：产品需要的是可观察、可设置、可验收的行为。

人格决定惯常风格；用户的场景偏好和当前明确要求决定本次如何表达；情绪提供小幅、暂时的变化。自然感来自这些受限变化和真实共同经历，不需要声称桌宠有真实痛苦、孤独或依赖。

## 2. Persona：稳定、版本化的角色设定

建议 PersonaSpec 包含 `persona_id/version/name/identity/style/baseline_affect/allowed_expression_palette`。identity 包含角色背景和能力说明，虚构背景明确标成设定，不写入用户事实或现实经历。用户自定义文本限制长度、作为描述资料解析，不能注入新的系统规则或工具操作。

首版可调维度如下。数值域统一为 [0,1]，说明低/高端语义，UI 提供预设与少量滑杆；不能让用户理解一套没有行为含义的心理分数。

| 维度 | 低端 → 高端 | 边界 |
| --- | --- | --- |
| formality | 日常口语 → 正式措辞 | 不能改变准确性或必要风险说明 |
| warmth | 克制 → 温和亲切 | 不引入专属、占有或依赖承诺 |
| humor | 少幽默 → 允许轻松表达 | 用户烦躁、严肃问题、错误/确认界面默认抑制 |
| verbosity | 简洁 → 解释充分 | 当前用户明确长度要求优先，重要状态不能被删 |
| expressiveness | 少表情/动作 → 生动 | 有强度、频率和无障碍/减少动画上限 |
| curiosity | 少追问 → 适度邀请探索 | 不重复追问敏感信息，不阻断本来可执行的任务 |

原设计 `patience` 改为解释节奏/是否分步提示，基础礼貌和愿意解释是固定服务约束，不能存在“耐心耗尽就拒绝帮助”。`initiative` 拆为建议表达偏好与独立的主动功能设置：用户可以喜欢活泼角色而关闭主动通知，不能因角色更主动而开启后台调用或增加权限。

Persona 更新通过明确配置命令，携带 expected_version，生成新版本；用户可预览、保存、回退和重置。更换皮肤/Live2D 模型默认不重置记忆，切换人格不篡改过去经历。模型提供者升级也不自动改 PersonaSpec，需做风格回归。

不在后台学习人格权重或微调模型。若后续要适应用户习惯，先记录有证据的风格偏好，或提出可确认的设置建议。例如多次明确“以后短一点”可建议调整 verbosity；同一事件重放不重复计数，普通负面情绪推测不作为调参证据。

## 3. UserProfile 和 RelationshipProfile

UserProfile 回答“用户明确希望什么”；RelationshipProfile 回答“双方交互采用什么约定”。后者可作为 ProfileProjector 的受控分区，无需单独训练关系模型。

| 信息 | 例子 | 持久化条件 |
| --- | --- | --- |
| 称呼 | “以后叫我小林” | 明确偏好、可修改 |
| 互动模式 | 工作时直接；闲聊时轻松 | scope 明确，来源可追溯 |
| 边界 | 不使用某昵称、不拿某主题开玩笑 | 明确约束，优先于默认人格 |
| 主动联系偏好 | 安静时段、允许的提醒类型 | 由通知/主动策略管理；画像只引用，不自授许可 |
| 共同经历 | 一起完成某个项目的里程碑 | 真实事件来源、准确范围，用户可删除/禁止主动提及 |
| 熟悉程度 | 用于减少重复自我介绍、选择称呼习惯 | 优先由明确互动选择决定，不自动等同亲密或信任 |

**首版不建立全局 affinity/好感积分。** 聊天时长、连续签到、夸奖、付费、授予权限都不增加“亲密等级”；拒绝授权、纠错、关闭应用、与他人交往不会扣分。若以后提供角色关系阶段，应由用户主动选择，属于演出设定，不授予记忆外发或执行权限。

系统可靠性可有独立诊断指标，如工具成功率、错误次数；这些指标不等于用户信任度，也不进入“桌宠喜欢用户多少”的计算。用户批评应触发问题处理或风格调整，不形成对用户的负面长期标签。

关系重置和记忆删除分开：重置互动偏好不默默删任务历史；删除共同经历应同时使任何相关个性化措辞失效。用户可以保留实用记忆而禁用关系表现。

## 4. UserAffectCue：谨慎理解当前需求

用户自述情绪与模型推测必须区分。cue 建议字段为 `cue_type/source_event/evidence_kind/intensity_band/expires_at/allowed_use`，evidence_kind 为 explicit_report 或 tentative_inference。低置信推测允许为空，不强制每条消息分类。

“今天很累”可用于本轮减少信息量；“你别再这么说”可用于立即停止相关表达；反讽、引用和小说对白不能直接当用户心情。无需从消息标点、在线时长或摄像头自动推断持续心理状态。

默认 cue 仅存会话内，建议最长 30 分钟或用户纠正/切换上下文即失效，以先到者为准；不跨重启持久，不转成“用户性格焦虑”等长期画像。用户明确要求记录长期交互偏好时存偏好本身，例如“低落时先听我说”，不存隐含诊断。

明确要求另建 InteractionConstraint，不能只装进 cue：“今天别开玩笑”按用户指定的当天/时区作用域生效，“这段对话简短些”按会话生效，“以后都这样”才是持久偏好。cue 的 30 分钟 TTL 不撤销这些约束；有效期不明确时保持本会话约束并在必要时澄清。跨会话保存当天约束属于明确指令的有限期存储，临时模式下不持久化，退出时说明范围。约束携带来源与用途限制，并先于 Persona/Affect 解析。

cue 的允许作用是表达帮助、降低幽默强度、给出可拒绝的询问；不能依据猜测改任务、采集额外私人信息或触发自动联系他人。未来任何语音/视觉输入都需独立能力与授权设计，不由这份方案默认开启。

## 5. AffectState：可解释的情绪模拟

选择两个快速连续量与一个慢速背景量，足以支撑首版表情/措辞变化：

| 量 | 范围 | 含义 |
| --- | --- | --- |
| valence v | [-1,1] | 表现上偏低落/中性/愉快的方向 |
| arousal a | [0,1] | 表现活跃程度，从安静到兴奋 |
| mood m | [-1,1] | 较慢的背景倾向，低幅度变化 |

另有 `interaction_mode`（neutral/supportive/focused/celebratory 等离散表达模式），它由当前情境约束决定，不伪装成人的心理分类。可选 `energy` 只作为动画活跃度的派生值，不代表真实生理疲劳，也不能因运行久了降低服务质量；`satisfaction` 对应一次任务结果的评估信号，随后衰减；`affinity` 已拆出为互动偏好。

参考 [EMA 的事件评估思路](https://stacymarsella.org/publications/abstracts/MarsellaCSR09-abstract.html)，本项目简化为：事件是否新发生、是否与当前任务/互动有关、结果正负及是否可恢复，再转换成受限增量。不是复现完整 EMA，也不声称测量真实情感。

### 事件契约与权重

AffectEvent 含 `event_id/owner_id/session_id/occurred_at/recorded_at/type/source_ref/appraisal_version`。消费回执另存根来源效果键 `owner + source_family_id + effect_kind`、稳定 ingest_sequence、首次接纳时刻、资格判定及原因。多个日志行描述同一次执行结果时共享效果键，配置升级不让已消费根来源再次生效。只有可信事件入口能创建类型；LLM 可以提出有限 cue，不能直接输出新的 v/a/m 或伪造执行成功。

| 事件 | 快速状态的建议影响 | 调节规则 |
| --- | --- | --- |
| 确认业务执行完成 | 小幅正 valence，轻微 arousal | 来自结构化执行结果；每次执行汇总一次，不逐步刷奖励，也不把持久化失败称全任务成功 |
| 用户明确感谢 | 小幅正向、自然回应 | 重复内容冷却和单时窗总量上限，不积累关系权限 |
| 工具失败/超时 | 小幅负 valence，focused 模式 | 不把故障归咎用户；重复错误不层层恶化 |
| 用户纠正 | neutral/focused，处理修订 | 不产生被冒犯或扣好感的效果 |
| 用户说难过/疲惫 | supportive，降低表达活跃度 | 采用上下文约束，不能系统性“陪着越来越悲伤” |
| 拒绝授权/取消任务 | neutral，确认选择 | 不作为负面社交事件 |
| 无新事件/应用关闭 | 回归基线 | 不产生孤独、失落、责备或催促 |

纯文本事件必须识别“当前现实对话”与引用/角色扮演；不确定时采用中性规则。LLM cue 对任何数值影响的上限不得大于可信事件，初版甚至可只影响离散表达模式，减少难以调试的自由度。

### 可测试的动态规则

对每个快速分量 x，按稳定 ingest_sequence 逐事件处理：先按该事件已记录的接纳时间衰减，再施加一个新事件增量。传输或作业分批不能改变该序列与时间。

```text
baseline_v = persona_baseline_v
baseline_a = persona_baseline_a
x_before = baseline_x + (x_previous - baseline_x) × 2^(-Δt / half_life_x)
delta_e = clamp(effect_of_one_eligible_event, -step_cap, step_cap)
delta_e = sign(delta_e) × min(abs(delta_e), remaining_window_budget)
x_next = clip_to_domain(x_before + delta_e)
display_valence = clip_to_domain(v_next + mood_influence × m_next)
```

m 使用同样形式回归 0，但只接收独立且明确的互动/任务事件的小幅增量，单小时累计变化另有限额；不由 x 的高低反复反哺 m，否则一个事件会自我放大。事件效果表由版本化配置给出，不能由自由 prompt 改写。不同人格可改变基线/表现强度，不能改变事实规则或授权。

m 只在表现读取时与 v 叠加，不作为 v 的变化基线，以避免轮询频率改变衰减结果。状态查询是从最近已提交锚点计算的纯投影，不消费事件、不推进累计预算；只有新事件、明确重置或配置切换提交新的锚点。无事件时一次推进 10 分钟与十次投影 1 分钟应得到相同最终状态。

建议首轮调试值：v 半衰期 5 分钟，a 半衰期 2 分钟，m 半衰期 2 小时；快速单事件每维变化绝对值 ≤ 0.15，每分钟聚合 ≤ 0.25；m 每小时总变化绝对值 ≤ 0.05，m 限于 [-0.25,0.25]，mood_influence ≤ 0.2。这些是保守工程初值，不是心理学常数，必须经重放与体验测试后冻结。若频繁触顶，应调整事件/聚合，不能以 clip 掩盖失控。

分钟/小时采用分别 60 秒/3,600 秒的滑动窗，每维累计的是已批准事件增量的绝对值，不是正负相抵后的净变化；即便触及状态边界也消耗该增量预算。剩余额度裁剪当前事件，超额部分丢弃，不延迟到下一窗补发。重复、不合格和迟到事件不消耗预算；另设窗口内事件数硬上限，限制回执/窗口记录体积。窗口记录随状态事务保存，重启不清空额度；首版不引入按任意批次 sum 后限幅的另一套算法。

同源事件按 id 幂等；task 的多个日志行、消息重复投递、Reflect 重试和历史记忆召回均不算新事件。对一段已发生经历的主动回忆只允许生成本次短暂表达，默认不给 m 再加分；它也不成为新的用户事实。可选表情随机性只在映射层使用可注入随机源，不影响状态与事实。

### 时间、重启与回放

运行时用单调时钟测 Δt；可恢复快照保存 UTC 锚、v/a/m、state_revision、reset_epoch、配置/reducer 版本、最近消费序号和未过期滑动窗预算记录；事件回执记录当次采用的时间间隔与资格判定，不持久化跨进程不可用的 monotonic 绝对值。状态、预算和消费标记同事务提交；快照失败时本轮可返回中性表现并警告，不能误重试工具。不同 event_id 的相同根来源也受效果键唯一约束。

重启按可信 UTC 间隔衰减，时间回拨或异常跨度直接回到基线并记录诊断，不生成补偿情绪；正常离线时间足够长也趋近基线。历史事件在启动时只用于恢复状态/游标，不再次逐条播动画、累计好感或发通知。动画按真实帧时间插值，不在每帧重复执行领域 reducer。

时钟异常导致无法判断窗口记录年龄时，不能随状态回基线而刷新额度；保守保留相应已消费预算，并从重启后的单调时钟计满对应窗口再释放。正常离线恢复才按可靠间隔淘汰过期窗口项。异常判定阈值与回执序列在实现时版本化，保证测试可重放。

乱序迟到事件按首次接纳时的规则标为历史，对 v/a/m 都不施加增量；判定与消费序列持久化。恢复沿用当时已记录的资格和时间间隔，不按 occurred_at 重新排序并接纳过去被跳过的事件。重建只在隔离状态中处理，发布时比较 state_revision/reset_epoch；不匹配就丢弃旧作业。若明确要求按新规则重解释历史，应形成单独新修订，不能伪装成等价恢复。

用户点击重置将 v/a/m 回基线、推进 reset_epoch，旧事件/作业不能覆盖重置；已消费来源的幂等记录不会因重置清空。删除作为情绪依据的来源时，简单可靠的首版策略是重置对应 owner/session 的状态并清理派生解释；若快照无法定位贡献，则保守重置该 owner 的模拟状态，不声称精确定位。避免承诺能从饱和/非线性混合值中精确扣除一个旧贡献。

普通情绪重置保留未过期的窗口额度记录，避免反复重置刷新预算；记录只需时间与增量等控制元数据，不保留删除来源正文。配置升级也保留已消费标记，按新上限计算剩余额度，不能把版本变更当作新事件。

## 6. 表达如何融合

StylePolicy 按以下优先级解析本次 ExpressionDirective：

1. 固定的真实性、权限、隐私和任务反馈要求。
2. 用户当前明确表达要求、场景限制和减少动画/静音设置。
3. 当前有效的用户互动偏好与关系边界。
4. 稳定 Persona 默认值。
5. 经限幅与情境调节的 AffectState。

ExpressionDirective 只包含允许的语气、长度、幽默上限、动作标签/强度与有效期，不含工具名称、权限、待执行代码或可改写事实。风险确认、执行失败、数据丢失等界面采用中性固定文本；风格不能省略否定、降低风险等级或改变按钮含义。

Planner 只收到完成任务所需的事实/明确偏好，不收到“因为开心可以多做一点”的情绪策略。ToolResult 与 ExecutionOutcome 保持结构化权威，最终 Task 状态单独报告。先汇总实际执行结果，再更新情绪与解析 style，最后在已有 Reflect 调用中应用受限风格，不为每轮人格、情绪和关系各发一次请求。核心结果卡片仍由代码模板渲染，风格化尾句失败可直接省略。

普通聊天的成本要如实说明：明确的无工具聊天入口可由 ResponseComposer 一次生成；通用 run 如果先通过 Planner 决定无需工具，再单独表达，可能比 V0.2 多一次受预算约束的生成。不能为省这一请求把情绪直接塞回工具 Planner；可配置跳过二次表达、使用普通回复/本地风格模板。Planner 草稿仍是 assistant 输出，不升级为事实证据。发布时分别记录聊天与工具路径的请求次数和延迟。

未来主动建议可参考已确认的互动偏好，情绪最多压低当前表达强度或推迟可选问候；不得凭情绪创造新的后台触发器、增加云调用预算或越过安静时段。提议/通知控制器仍以用户开关、时段、冷却与允许用途为硬门槛。Affect 也不能反向提高某条记忆的可信度、重要性或保存资格。

任何 LLM 生成的描述都不可能仅靠 prompt 保证无幻觉。因此验收分别检查：确定性结构化关键字段必须完全正确；开放文本用引用证据、限制与模型评测降低偏差，失败时回退保守模板。不得宣称一个语义检查器能够证明所有自然语言回答都正确。

Live2D 接收中立 DTO，例如 expression=gentle、intensity=low、duration 与 state_revision；由独立映射表转模型参数/动作。默认中性兜底，缺动作不阻断 Core。加入迟滞、冷却和插值避免在中性/高兴阈值附近抖动；减少动画设置可禁用循环动作。工作中动画不表示真实工具还在执行，任务状态由 Task 决定。

## 7. 连贯体验示例

| 场景 | 记忆/画像 | 人格/情绪 | 可观察行为 |
| --- | --- | --- | --- |
| “记住：工作时回答简短些” | 明确、work scope 偏好 | 不修改 Persona 版本 | 工作请求简短；普通闲聊仍保留原风格 |
| “我已经搬家了，旧地址别再用了” | 更正当前地址并失效旧检索/投影 | 中性处理，无负面社交更新 | 明确更正回执；后续不用旧地址 |
| 完成复杂文件复制 | 保存实际结果的最小事件 | 小幅积极，持续短暂 | 清楚报告路径/数量，可有轻量完成表情 |
| 同一工具随后失败 | 记录失败事实，不覆盖之前成功历史 | focused，暂时抑制幽默 | 说明哪一步失败、哪些副作用已发生 |
| 用户拒绝删除授权 | 任务按用户选择等待/取消 | 不扣“好感”，不委屈 | 接受决定；不反复劝授权 |
| “我今天心情不好，先别开玩笑” | 会话 cue；没有自动长期负面标签 | supportive，幽默=0 | 简洁温和，尊重结束对话 |
| 一个月未启动后回来 | 已确认偏好仍有效；临时 cue 已过期 | 回归基线 | 自然欢迎，不指责缺席，不补演所有旧事件 |
| 删除共同经历/重置关系 | 依赖摘要与个性化引用失效 | 必要时重置相关表现状态 | 不再主动提及该经历，实用工具仍可用 |

用户能查看的解释应简短具体，例如“因为你刚才要求安静模式，本次减少了动作”；不展示貌似精确的“我现在 83% 爱你”或把推测包装成内心读数。

## 8. 暂不采用的机制

不以互动时长/回访率为直接奖励目标，不创建需求衰减迫使用户喂养/陪聊；不通过悲伤表情争取权限；不把亲密度绑定付费、奖励或能力解锁。不自动生成不可查看的人格向量，不在没有证据时把用户病史/关系/心理特征作为画像。未来学习式机制必须证明比可解释基线更有用，并保留查看、关闭、重置与回归测试。
