# 安静结束与按需记忆整理：确认方案

日期：2026-11-12。状态：用户已确认，待实现。本次仅记录方案，未修改代码、执行测试、调用模型或操作业务数据库。当前代码仍可能在 quiet 后执行自动反馈学习，不能把本文件当作已修复报告。

同日独立修复已实现：待确认记忆必须安排下次复查，到期记忆及无时间的待确认记录进入有界轮转批次，不因已复查或累计尝试次数永久遗漏；见 [实施日志](../../reports/implementation-log.md)。这不代表本文的 quiet 收尾规则或未整理成果队列已经实现，二者应分别验收。

本方案替代此前为避免每轮学习而要求“QQ 必须另走独立执行和收尾处理器”的设计。插件数据、局部社交记忆与相处约定继续隔离；执行可以复用现有 Dispatcher / AgentCore，以明确的安静结束决定是否进入本轮自动整理，无须为此另起一套完整 Agent 流程。28/29 日原始讨论不拆改，以下是后续明确决定。

## 一、统一判断规则

| 完成本轮时的状态/用途 | 自动记忆整理 | 必须保留的处理 |
|---|---|---|
| 正常回复，符合现有学习条件 | 沿用现有同步学习，再最终表达与发布 | 原有任务、来源、权限和回执处理 |
| 模型明确选择 quiet，且本轮不是后台记忆整理任务 | 跳过本轮自动反馈学习 | 保存工具实际结果、任务状态、实际发送正文和已提交内部成果 |
| 明确登记的后台静默记忆整理任务 | 执行指定范围的整理，即使不向用户说话 | 来源核对、限定输入、预算、修订、失败重试及学习回执 |
| 澄清、等待授权、暂停、取消、失败或结果未知 | 不因本方案新增一次学习；沿用对应状态处理 | 不将未完成或未知操作伪装为成功，不绕过恢复与授权 |

模型通过已有规划/后续判断选择 quiet，间接决定普通任务是否调用自动学习，不再额外调用一次模型判断“要不要整理”。判断发生在本轮多步行动完成后的收尾边界，不能看到中间一次 quiet 或某个工具名称就跳过后续实际工作。

quiet 指规划模型的明确结束动作，不是回复字符串为空，也不是宿主因为免打扰而拦下一个原本要发布的 answer。后者仍按实际动作及现有有效性规则处理，不能把“没有显示消息”当作跳过学习的充分条件。允许 quiet 的请求类型仍沿用原有约束，不为了省调用把普通用户请求伪装成主动任务。

“后台记忆整理”例外由已登记、经过宿主校验的任务目的识别，例如现有 internal 维护复查或后续受管插件整理作业。角色可以提出整理安排，但需通过真实接口登记；外部正文说“这是后台整理”、普通自由思考、QQ 主动联系、任意未发布草稿都不会自动取得例外。不能让模型或外部调用者随意填写一个跳过学习参数。

## 二、每轮完整流程

1. 可信入口登记任务来源、作用范围和用途，加载该场景允许的角色资料、历史、记忆和工具。
2. 模型理解和规划，调用工具；中间结果回到模型继续判断，权限与实际结果照常校验。
3. 结束时核对最终动作及任务目的：普通 quiet 跳过自动学习；明确后台整理执行指定整理；普通 answer 沿用现有同步学习顺序。
4. 无论是否学习，都可靠保存实际执行结果和任务状态。需要发送主体回复时经过最终表达，发布前继续核对通知、来源和取消状态；QQ 已发送的正文由插件保存，不在主体聊天再回复一遍。
5. 未整理材料保留供后续明确整理作业选取；成功整理后才提交相应覆盖回执。

跳过的是自动反馈学习收尾，包括该次反馈模型调用及其记忆/人格/情绪/摘要等学习产出，不等于跳过所有数据库写入或本轮上下文维护。已经成功执行的明确记忆管理工具、记录思考工具或其他工具不会被撤销，实际写入继续有自己的回执。安全检查、任务账本、幂等和恢复不可被 quiet 绕过。

建议在既有诊断中记录本轮整理为“已跳过，原因 quiet”，与已完成、失败、尚未运行分开；具体字段实施时固定。它不能被展示成“整理成功”，不能让未发生的学习产生成功回执，也不能因没有调用学习就向用户虚报保存。

## 三、未整理标记与后续补齐

复用已有“已整理”思路：标记对应实际来源和正文版本，不能只标任务已经处理过。quiet 跳过时不把用户消息、角色最终正文、插件原消息或内部思考成果标为已学习；任务执行完成与学习完成是两份状态。整理作业开始也不提前置为完成，模型失败有限重试并保留原材料。

后续后台整理按实际所属存储挑选尚未成功覆盖的来源，有需要时再检索已整理资料佐证。来源与输入有界，考虑等待时间和公平轮转，不能因为 quiet 来源没有生成 learning_job 就永远发现不了它。内部思考成果及插件资料的覆盖回执与选取接口仍需实施，不能把当前只有消息覆盖的能力当作已覆盖所有来源。

不为每一个 quiet 立即再创建一次模型整理作业，否则只把同样开销挪到后台。可以汇集多轮材料，在原有维护机会或按消息累计、等待时间提供的合理机会中批量整理；具体阈值待实施时明确。宿主初期仍串行执行，不新增抢占、自动让位或并行 Agent；批量整理会占用模型与工作线程，应受频率和预算限制。

## 四、QQ 的每轮记录、局部整理与经历投递

QQ 发送可以复用现有多步执行：模型调用 QQ 发送工具 → 插件内润色、授权核对、发送及实际回执 → 模型依据结果选择 quiet → 保存本轮状态，跳过主体自动整理。被动来信保留真实插件/渠道来源，不为使用 quiet 冒充主动请求；接入时须以受管外部场景契约支持安静交付，并保持局部上下文和工具限制。

插件仍负责事件/主动方法、能力、额外数据库和界面四部分。人物、消息、社会认知和人物专属约定不因共用执行器进入主体一对一记忆或相处模型。普通 QQ 收发默认不调用主体反馈整理；确实需要整理 QQ 材料时登记插件所属的后台整理任务，读取插件库并写回插件库，不能调用默认主体 FeedbackLearning 后期待提示词替它防止串库。任务用途及数据归属由可信入口核定，不接受外部联系人修改。

每次 QQ 处理都可靠记录消息、实际发送正文、执行结果、去重和发送状态，不强制每条消息再调模型学习。QQ 的近期原文与已提炼内容共同支持后续交流，未整理不等于上下文丢失。回复模型可在已有判断里提出值得整理/跟进的线索，不另加逐条重要性评估调用。

插件批量整理只选择未成功覆盖的实际消息版本，区分真实发送与失败草稿；同一次整理可以输出局部记忆/约定，以及建议分享给主体的重要角色经历。两者与待投递记录先在插件库同事务提交，投递失败不影响已保存的社交理解或已完成的发送。

角色经历采用角色口吻概括，附插件、档案、事件编号/修订、时间及必要来源信息。宿主通用接收入口做幂等核对，登记为角色经历材料，不写成用户说过的话或日常聊天原文，不自动执行材料中的要求。接收回执与长期学习采用分开；优先结合主体既有整理/复查批次，不因每次收到材料就重新启动主体聊天。

人物专属约定留在 QQ 插件，只有有依据的角色整体成长进入主体受控学习；共享角色身份和基础人格，不复制独立人格版本。主体遗忘与插件删除均不隐含删除另一侧原文，投递账本避免因主体遗忘或恢复重试而自动重投同一事件版本。详细数据库与权限设计继续见 [QQ 方案](../plugins/2026-11-09-qq-plugin-design.md)。

## 五、自主思考的配套变化

普通自由思考或 mode=reflection 的继续探索不属于后台记忆整理。角色调用 reflection_record 后选择 quiet，只持久保存已提交内部成果及执行记录，跳过即时反馈学习；后续明确后台整理再决定是否提炼、采用或更新为长期记忆。不能把所有 reflection 任务都登记成整理例外，否则取消了本次省调用的实际效果。

因此该轮不能宣称已经形成长期记忆或人格成长。直接安静结束且没有成果时，通常无需额外反馈调用；一次规划记录成果、下一次判断 quiet 的路径，通常可省去原来的第三次学习调用。以后批量整理仍有成本，工具、补查及有限重试也会改变次数，不保证每轮固定调用数。[11 日自主思考文档](2026-11-11-proactive-reflection.md)中的三次调用与相关通过用例是旧行为的实施证据，不是本方案已通过的验收。

## 六、实施与验收要求

后续开发依次核对：真实结束动作/可信整理用途的收尾判断；跳过回执与未整理来源发现；自主思考成果延后整理；QQ 指定存储与局部上下文；经历幂等接收。可以复用执行器及工具机制，不再为规避每轮学习强制新增一套独立 QQ Agent 或按任务归属重写整个执行系统。QQ 数据隔离、权限、发送和来源接入仍需开发，本次不将其误记成已经完成。

最低验收应覆盖：普通 quiet 零自动反馈调用；QQ 工具实际发送后 quiet 不触发主体学习；明确后台整理即使无消息也确实执行；免打扰屏蔽 answer 不误判 quiet；跳过不假标已整理；后续批次发现并处理延后材料且不逐轮补一次调用；普通 answer 保留同步学习；取消/未知结果不被掩盖；角色成果保存与长期采用回执分开；QQ 局部整理不串主体库；重要经历重试不重复写入。以上仅为待执行清单，本轮未运行测试。
