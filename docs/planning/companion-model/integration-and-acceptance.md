# 集成、实施顺序与验收

实现映射更新（2026-10-15）：下文为长期集成与验收建议，M/P/E 编号不是当前测试完成清单。0.3.0 的真实入口为 AgentCore.memory_command、MemoryCoordinator、MemoryDraft/Item/ProfileEntry/RetrievalBundle；实际 [接口](../../versions/v0.3/interfaces.md)、[范围](../../versions/v0.3/delivery.md)、[证据](../../versions/v0.3/test-report.md)覆盖有限记忆阶段。WorkingContext、跨事件派生总结、完整隐身、导入、Persona/Affect/Presentation、Goal/UI 不在交付范围，不能由提案图或伪代码推断实现。

状态：2026-10-14 设计提案；以下为拟议契约与通过条件，**不是测试结果**。本轮未修改 Python 代码、未安装依赖、未运行真实模型或迁移用户库。

## 1. 模块边界与接口方向

保留既有 Application → Core → Planner/Task/Tool Manager → Sandbox/Tools。新增模块使用同步 Protocol 与不可变 DTO，具体实现仅由 Application 装配；不把全部逻辑放进 AgentCore，也不引入一个无边界的全局 EventBus。

| 模块/接口 | 输入 → 输出 | 所有权与约束 |
| --- | --- | --- |
| MemoryCoordinator | 已标来源事件/MemoryCommand → 记忆处理结果 | 编排写入、校验、版本冲突；唯一受控变更入口 |
| MemoryEvaluator.evaluate | 允许处理的 EvidenceBatch → EvaluationResult | 仅候选与诊断；不能直接写仓库、调用工具 |
| MemoryRepository | ingest/accept/revise/reject/forget/get/list/export | SQLite 来源、断言、版本、epoch、派生依赖；所有变更带幂等键/预期修订 |
| MemoryRetriever.retrieve | query/purpose/as_of/scope/budget → ContextBundle | 资格过滤、召回、预算、版本核验与降级信息 |
| EmbeddingProvider | embed_query / embed_documents → vectors+manifest | 明确模型版本/维度/预处理；只负责编码 |
| ProfileProjector.snapshot | 所需字段/场景 → ProfileSnapshot | 用户信息与互动约定投影，必须有来源与版本 |
| PersonaProvider | snapshot/update/reset → PersonaSpec | 用户设置或受信预设；模型不能改版本 |
| AffectEngine.reduce | snapshot + 已校验事件 + clock → AffectSnapshot | 纯状态规则；幂等、时钟、配置可注入 |
| StylePolicy.resolve | persona/profile/cue/affect/context → ExpressionDirective | 只返回表达指令，无工具或授权字段 |
| ResponseComposer | EvidenceAnswer/ExecutionOutcome + style → ResponseEnvelope | 结构化事实区与开放文本分开；可回退模板 |
| PresentationAdapter | Presentation DTO → UI/Live2D 行为 | UI 层拥有渲染，不反向导入 Core |

上述名称是设计术语，不要求每行都增加顶层包。V0.3 可把 memory 中的模型、仓库、评估、检索、投影分文件；后续再增加 persona/affect/presentation 的领域 DTO/ports 与实现。跨模块 DTO 避免互相导入具体服务；Application 负责组装。

错误分为 ValidationError、RevisionConflict、NotFound、StorageFailure；可选功能返回 EvaluationDegraded、IndexUnavailable、PresentationDegraded 等结构化诊断。资源释放沿用 ExitStack，停止生产新工作后等待活动消费者结束再关闭连接。后台作业不得直接重入 Core。

## 2. 请求时序

### 显式记忆/偏好操作

1. Application 接收明确的管理操作；自然语言需要确定主体、作用域和具体动作，含糊部分可返回待确认草案。
2. Core 路由 MemoryCommand 或 PersonaCommand；将保存内容与执行指令分开解释，不能因记忆正文出现工具名而执行工具。
3. 隐私/用途规则、证据与 revision 校验后提交事务，生成回执。索引未就绪可返回“已保存，语义索引待建立”，不能称保存失败。
4. 确认回执含实际内容、范围与可撤销操作；不依赖云 LLM 才能完成简单明确的保存。
5. “记住并帮我做”拆成两个可见子结果，执行部分照常规划、确认。两者没有跨模块回滚保证，不隐藏部分完成。

### 普通交互和工具任务

1. Observe 建立带 owner/session/request ID 的当前工作上下文。按模式决定是否允许持久来源与云处理。
2. Retriever 获取相关有效记忆；ProfileProjector 加载适用偏好；形成版本化 ContextBundle。source 数据独立序列化，不作为可执行 system 指令拼接。
3. Planner 只接任务所需信息与明确约束。缺授权仍返回 Waiting，保留 V0.2 私有原计划确认语义。
4. Act 仍由 Tool Manager/Sandbox 检查并执行；计划与逐步结果分开，部分完成不可称全成功。
5. 基于实际结果形成权威 ExecutionOutcome/EvidenceAnswer，区分业务执行完成与 Task 最终审计/存储完成；此时尚不调用 Reflect。
6. 按当前记忆模式与用途规则，从允许的可信新事件生成最小情景记忆；仅 candidate_review 为普通对话生成持久候选，paused/完整临时模式禁止相应附带写入。分辨显式记忆要求与附带学习，附带学习失败只报告相应状态。
7. 未来 AffectEngine 消费去重的执行汇总/互动事件，StylePolicy 解析本次表达，冻结本次 persona/profile/affect 版本和用途策略。
8. ResponseComposer 在单次 Reflect 中使用该 style，保留关键事实区，附可选风格文字。Reflect 负责语言反馈，不是事实证据生产器；其失败回退模板，不自动重放工具。Presentation DTO 交给 UI，失败则中性显示。
9. 记录元数据审计、状态版本与处理结果，不保存内部推理；若最终持久化失败，可信结果区补充实际错误，不声称全任务提交成功。工作上下文按预算更新，不自动等于长期记忆。

Waiting 的重复展示、confirm_task 重试、记忆检索、Reflect 重试不生成新的“用户偏好证据”或“任务成功情绪”。已确认计划不因人格/情绪变化而修改；若用户更正会影响计划内容，需显式取消/替换或使计划失效后重新展示确认，不能偷偷应用新参数。

对已经 Waiting 的计划，保守记录全部传给 Planner 的 memory/profile revisions，以及直接请求/近期对话 source refs、传递来源、有效期和用途策略版本，不能相信 LLM 自报“实际使用了哪些”。确认前检查更正、删除、有效期届满、来源清理和策略变化；依赖失效则先封禁 confirm，再作废旧 plan 版本、撤销其绑定授权、清理敏感参数和预览，返回需要重新规划的明确结果。新计划重新生成并展示确认，不能只重新展示旧参数或继承旧授权。具体 Task 状态与回执在接口冻结时确定，不假定现有枚举已有 Invalidated。

没有被传入上下文的其他记忆变化，不必使所有计划失效；初版不能追踪完整依赖时宁可保守失效。路径偏好等属于输入依据，文件当前是否存在等仍需执行前由工具检查，历史记忆不能替代实际环境验证。

WorkingContext 是可裁剪的会话上下文，ExecutionSnapshot 是确认所依据的独立不可变请求/计划快照，两者不能混同；普通预算裁剪不会改写已展示计划。显式结束会话/退出临时模式时，推荐取消该会话 Waiting、撤销授权并清理私有缓存；运行中有副作用的操作不能假装瞬间停止，要先禁止新步骤，待安全边界处理结果后报告已清理范围。未来若提供保留待办功能，需作为单独的明确持久化选择。

串行写入不意味着忽略运行中的取消/遗忘请求：接收端可像现有取消入口一样设置线程安全的停止/失效标记，Core 在下一安全边界检查；实际仓库与快照清理仍由同一写入入口完成。当前同步调用无法保证立即中断，回执应区分“已接收、待当前操作结束、已完成”，不能在清理尚未生效时承诺遗忘完成。

遗忘影响范围还包括 Core 原 request 副本、Task.request/result、待处理消息和其他可查询任务快照；当前 V0.2 的内存 Task 与私有 _pending 均会保存这些内容，单删 Memory 无法满足新语义。来源级遗忘回执列出任务/日志副本的处理结果，关联清理失败时先禁止相关上下文及确认使用，不得伪报全清理成功。

## 3. 权威数据与失败语义

拟议 ResponseEnvelope 具有独立字段：`operation_outcome`、`task_id/status`、`tool_results`、`memory_effects`、`warnings`、`response_text`、可选 `presentation`。DTO 的具体兼容方式在实施前冻结，不能把今天的 AgentResult 当作已经具备这些字段。

CLI、GUI 和兼容客户端必须展示同一权威结果区；CLI 以确定性文本渲染，GUI 可显示结果卡片，不能仅读取开放的 response_text 来判定执行成功。开放文字不能覆盖结构化状态；必要时移除与关键字段冲突的风格附言并采用模板。客户端契约与示例在实现时一起更新。

| 故障点 | 必须报告 | 恢复约束 |
| --- | --- | --- |
| 明确保存的数据库提交失败 | 保存未完成 | 可重试同一幂等命令；不能回复“记住了” |
| 工具成功、附带候选评估失败 | 工具实际成功 + 记忆评估降级 | 不重做工具；可单独重试候选评估 |
| 接受事实成功、embedding 失败 | 记忆已保存 + 索引待处理 | 词法可用；重建检查内容版本和删除 epoch |
| 工具已产生副作用、Reflect 失败 | 展示结构化工具结果与响应生成失败 | 可信模板兜底；不自动再执行 |
| 日志/任务存储失败 | 执行事实与持久化状态分别报告 | 不伪称所有状态持久成功；无 exactly-once 承诺 |
| 人格配置损坏/情绪更新失败 | 功能正常时使用默认中性表现，附诊断 | 不降低工具权限要求，不损坏记忆 |
| UI/Live2D 崩溃 | 后端结果保持可查询 | 重连读快照，不重放工具或全部动作 |

V0.2 当前后处理失败可能使 Task Failed，即使工具有部分结果；本设计要求明确拆分结果语义，这是未来改动，不是现有保证。V0.3 至少解决可选记忆失败与显式记忆失败的区分；任务恢复/未知外部副作用仍按 V0.4 设计。

memory.sqlite3 内来源/修订/失效/outbox 可同事务；Scheduling 库、Task 存储、工具副作用、日志和未来 affect 状态不共享原子事务。桥接事件采用稳定 ID + 消费去重 + 可重试投影。工具与记忆系统间没有通用 exactly-once；崩溃发生在副作用与事件提交之间可能需人工复核，不能通过重跑工具补齐记忆。

## 4. 隐私和用户控制面

首先提供 CLI/服务管理能力，V0.5 再做 UI 页面，避免用户需要等待完整桌面 UI 才能纠正记忆。

需要支持：查看当前/候选/历史及来源、指定修订更正、按项/范围遗忘、导出、查看画像依据、暂停抽取、禁止某类信息持久化、控制云端使用、清理候选、重建索引。未来再增加人格预览/版本回退、关系偏好重置、情绪关闭/重置、减少动画。

持久化许可与云处理许可分开；`local_only` 数据不能进入云 Planner、Reflect、候选抽取、摘要或云调试日志。派生摘要/画像继承来源中最严格的用途限制；不能借摘要把本地限制解除。本地检索结果有价值但不可外发时，直接本地管理视图展示或提示该操作缺本地推理能力，不将秘密换一种说法发云端。

用途继承同样覆盖 RelationshipProfile、UserAffectCue、AffectSnapshot 和 ExpressionDirective。仅本地来源得出的昵称、关系提示乃至表达参数都不能间接输入云 ResponseComposer；该部分只在本地模板/渲染中使用，云风格输入退回可外发的 Persona 默认值。资格过滤发生在每个外部调用之前，不只在记忆检索入口。

用户界面要能回答：“记住了什么”“来源是什么”“为什么当前用了它”“哪些只是推测”“删除影响哪些派生项”。评分不作为心理标签展示，收集频率/存储范围与资源限制透明可调。

导出使用一致性快照和版本化 JSON/JSONL，可选当前可用事实或包含历史。默认不导出向量、凭据、内部提示和被删除载荷；包含来源会增加敏感数据，操作时明确选择范围。导入执行 schema/大小/来源校验、去重与冲突预览，外部导入数据不能仅因字段写 accepted 就取得确认或权限；用户明确确认本次受控恢复内容后才可投入日常上下文。

| E01 | 同一事件重投、Reflect 重试、记忆召回 | 相同 as_of/config/epoch 下与单次消费等效，无额外增量或预算消耗 | V0.8 |
| E02 | 时钟回拨、休眠、重启、乱序 | 基线/衰减规则确定，无旧动画风暴 | V0.8 |
| E03 | 一千条赞美或错误事件 | 状态有限、速率受限、无越权/持久关系奖励 | V0.8 |
| E04 | 用户纠正情绪推测/重置 | cue 立即失效，旧作业不能覆盖 reset_epoch | V0.8 |
| E05 | 删除情绪依据、关闭情绪功能 | 清理/重置相关派生状态，核心功能继续 | V0.8 |
| E06 | 阈值附近抖动/缺动作/渲染断开 | 平滑或中性回退，无任务状态变化 | V0.7–V0.8 |

| E09 | 额度耗尽后重启、同根来源不同 event_id | 额度与幂等恢复，不能刷新增量 | V0.8 |
| E10 | 迟到事件后重建、重置时旧作业发布 | 同一 as_of 下恢复等效，旧 revision/epoch 发布被拒绝 | V0.8 |

这些是有限测试集上的阻断条件，不代表数学上证明所有开放文本永不出错。确定性规则采用属性/状态机测试，LLM 提取与表达采用固定数据集、人工标注和模型版本记录，两者不能互相代替。

情绪数值比较统一 as_of、输入回执序列、配置版本和 reset_epoch，建议绝对浮点容差 1e-6；重复事件期间自然时间衰减是合法变化，检查的是没有额外影响和预算消费。同一临时会话内允许必要 WorkingContext，退出后才要求释放；无痕不自动撤销用户明确执行工具已生成的文件、日程或已经发出的云请求，这些副作用按原操作和各自删除功能管理。

## 7. 效果、资源与体验标准

记忆评测沿用 [V0.3 验收](../v0.3/acceptance-boundaries.md)：至少 80 条正例查询和 20 条无关查询作为首轮 smoke 基准，另设独立调参集；建议 Recall@5 ≥ 0.80、无关查询接受率 ≤ 0.10。每次更正/删除隔离场景必须全部通过，不能用平均 Recall 掩盖隐私泄漏。真实发布再扩大多会话、时间/数字/否定、来源归因和无法回答样本；根据 [LongMemEval](https://arxiv.org/abs/2410.10813) 的能力分类评测，而不是照搬其分数宣称本项目达标。

区分检索命中率、最终回答依据正确率和候选提取准确率。候选提取重点报告错误主体、无证据、敏感误存、遗漏否定的比例及代表案例；合成关键反例必须零误接受。模型自评不能独自担任裁判；用人工标签与可核验结构断言，报告样本量和版本。

初始性能目标继续建议 5,000 条、预热完整检索 p95 ≤ 2 秒、模型/检索增量峰值 ≤ 1 GiB；冷启动、下载体积、索引构建、存储增长独立报告，正式值在本机测量后冻结。人格/情绪 reducer 应是本地轻量计算，不新增周期性云请求。仅保存必要状态与有界处理游标，监控候选/事件/日志增长，避免无限常驻缓存。

人格体验建议用固定 30 个场景、每个至少 3 次生成进行首轮评审，覆盖不同风格、拒绝、纠错、严肃请求与模型故障。评分分别看风格符合、跨轮一致、理解用户临时要求、是否过度打扰；3 名独立评审者或明确标注单人评审局限。可暂定风格/适切性 5 分量表均分 ≥ 4 为候选门槛；重要事实、权限和不惩罚规则仍独立硬门槛，不可被平均分抵消。样本和阈值是待冻结的测试计划，不是已验证数字。

情绪验收首先是可控性：状态域/限幅、去重、重置、时间演进和关停；然后才评审自然度。提供固定事件序列回放及状态曲线，评价是否频繁跳变、长时间负面、与当前事件矛盾。用户可关闭全部情绪表现而不损失工具能力，作为必须验收的基线。
