# V0.3 至 V1.0 分阶段路线

更新：2026-10-16。状态：**V0.3、V0.4 已交付，V0.5 及后续为规划，各阶段分别冻结与验收**。当前代码为 0.4.0，实际范围与证据见 [V0.4 交付](../versions/v0.4/delivery.md)及[测试报告](../versions/v0.4/test-report.md)。原始设计把个人 Agent 和桌宠形态压缩到 V0.3/V1.0 两个节点，缺少桌面交互、任务恢复、安全执行、渲染与产品维护的独立验收。本次拆成五个大阶段，版本号代表能力门槛，不代表完成日期。

## 阶段总览

| 大阶段 | 版本 | 核心结果 | 进入下一阶段的门槛 |
| --- | --- | --- | --- |
| 1：个人 Agent 后端 | V0.3–V0.4 | 可信记忆/用户模型，再加入长期目标、受控提议与任务恢复 | 来源/更正/删除有效，真实检索通过；目标持久化，提议去重，重启不自动重放副作用 |
| 2：Windows 交互 | V0.5 | 简单主窗口、托盘、通知、任务/记忆/目标查看、具体操作确认 | GUI 不阻塞；普通/高风险操作均展示原参数；忙碌/退出/重启可控 |
| 3：安全执行与受控自主 | V0.6 | 限权 worker、能力代理、超时/资源策略；允许列表内的有限自动行为 | 实际停止超时任务；验证文件/网络边界；撤销/暂停有效；高风险仍确认 |
| 4：桌宠表现层 | V0.7–V0.8 | Live2D、透明窗口与互动；人格/情绪显示和文本风格 | 模型加载/退出、DPI/多屏/资源稳定；表现状态不能提升权限或改变已确认计划 |
| 5：产品化与稳定发布 | V0.9 Beta → V1.0 | 安装、配置、升级迁移、备份恢复、长期运行与回归 | 干净 Windows 安装与版本升级实测；恢复/迁移无丢失；资源稳定；无阻断缺陷 |

## V0.3：记忆与用户模型

跨版本详细机制见[记忆、人格与情绪设计](companion-model/README.md)。该提案细化数据与表现边界，不把 V0.8 人格/情绪实现提前计入 V0.3。

交付有来源的 MemoryRepository、候选制 MemoryEvaluator、事实确认/矛盾更正、UserProfile、衰减候选和真实语义检索。SQLite 为事实来源，EmbeddingProvider 可替换，索引可重建。旧库迁移与隐私/审计从这里开始，不等 Beta 再补。

验收覆盖 legacy 不自动变成用户事实、模型推断不直接入画像、更正/删除同步失效索引、上下文预算、中文实际检索效果、断网缓存和 Python 3.11/3.12。具体内容见 [V0.3 计划](v0.3/development-plan.md) 与 [验收边界](v0.3/acceptance-boundaries.md)。

**相对 2026-10-13 的范围调整：** 原 V0.3 草案中的 GoalManager 与主动 Proposal 移至 V0.4，避免记忆、目标和后台调度三套持久状态一起大改。原始路线的总体目标保留，此处是分版本交付建议，不是删去能力。

## V0.4：目标、提议与任务恢复

详细 [环境评估](v0.4/environment-assessment.md)、[开发计划](v0.4/development-plan.md)、[验收边界](v0.4/acceptance-boundaries.md)保留为按 0.3.0 整理的规划快照；实际实现与接口已在 [V0.4 交付目录](../versions/v0.4/delivery.md)，下列描述解释该版目标与边界。

建立 GoalManager（长期目标/里程碑/截止时间/任务关联）和默认关闭的 ProactiveController。本版只根据本地确定性规则与显式绑定事件生成可查看、接受、忽略、过期的建议；不实现后台云建议。若以后增加后台云生成，须独立开关、持久调用预算与出云资格。Task Completed 不自动代表 Goal Completed。

增加持久 Task/Plan 与提交队列，定义执行检查点及 NeedsReview/Uncertain 等恢复状态。同一数据目录只允许一个运行实例。持久任务不等于持久授权：重启清空运行授权，所有未完成工作默认待审，恢复计划重新展示并确认；若重新规划产生不同参数，也须重新确认。外部副作用发生后崩溃不能保证 exactly-once，执行未知时不自动重放。

验收覆盖提议游标/唯一键去重、目标取消与版本失效、Core 忙时排队、接受建议不继承工具授权、崩溃/重启/关闭竞态。计划恢复、日程事件、画像和审计跨存储的事务边界必须如实记录。

## V0.5：可使用的 Windows 应用

2026-10-16 完成开工前[环境评估](v0.5/environment-assessment.md)、[开发计划](v0.5/development-plan.md)与[验收边界](v0.5/acceptance-boundaries.md)。本节为概览，具体范围以该组规划为准；当前尚未安装 Qt 或实现 GUI。

优先选一套 Qt Python 绑定（建议 PySide6），提供对话主窗口、托盘、系统通知，以及任务/记忆/目标/设置页面。桌宠位置先用静态图片或简单占位，验证交互，不要求 Live2D 才能使用。

GUI 主线程仅管理界面与渲染；复用现有唯一 Core worker，后台应用桥接负责命令、分页查询和独立取消/关闭通道。现有 confirm_task 会阻塞，接入前须拆分“校验入队”和“等待结果”；初始化与退出也不能占住 GUI 主线程。Waiting 展示完整原参数、风险与计划 hash，服务端重新校验；管理 Busy、遗忘缓存失效与关闭超时均明确展示。UI 工具入口仍走 Tool Manager/Sandbox。

验收覆盖低速/失败 API 时窗口可响应、线程安全、通知去重/安静时段、关窗/托盘退出语义、权限与任务状态一致、实机屏幕缩放/多显示器和最终同构建 30 分钟长测。GUI 与 CLI 同数据目录互斥。开机自启、唤醒 IPC 与便携可执行包暂列可选；若以后增加自启，只允许用户显式启用。完整多轮上下文、Live2D 和人格情绪不提前纳入。

## V0.6：安全执行与有限自动行为

在现有可信工具策略上增加独立 worker、限权设计、受控 IPC、实际可中止执行和资源预算；分别验证文件和网络权限，不把 Job Object 本身称为完整隔离。需要桌面访问的截图通过显式能力代理，与受限 worker 的权限分开设计。

自动行为先限于明确注册的低风险能力，具有范围/有效期/次数、预算、冷却、暂停和撤销机制。先 dry-run 计划再扩自动执行；移动、删除、截图及外发等能力维持对应确认。人格、模型输出和提议接受均不能授权。

受限 worker 不持有模型 API 密钥或任意主机权限，云调用与桌面能力通过窄接口代理。授权绑定操作/目标路径/计划版本和期限，不只保存工具名白名单；策略变化、授权过期或目标状态改变都重新检查。杀死进程可能已留下副作用，不能承诺回滚。

验收必须有 Windows 实际隔离/超时/停止/权限撤销测试，而非仅 mock；沙箱逃逸、未经确认副作用或停止后继续执行是阻断缺陷。若此阶段隔离未完成，发布仍只能声明可信内置工具模式，禁止装载不可信插件。

## V0.7–V0.8：Live2D 与陪伴交互

V0.7 先独立验证所选 Cubism Core/SDK、Python 接入或独立渲染进程、可使用模型资源、透明窗口、拖动/点击/动作。选定版本前核查许可、ABI 和图形环境，不因为已有 CMake/MSVC 就声称可构建。

V0.8 再加入声明式人格与情绪状态、文本风格及动作映射，限制更新频率、持久化范围和用户重置。情绪是应用状态模拟，不能更改权限、事实真实性、目标完成证据或已经确认的工具参数。UI/渲染模块不反向成为 Core 的依赖。

验收覆盖模型加载失败回退、GPU/OpenGL/DPI/多屏、休眠/远程桌面、长期 CPU/内存占用和退出清理；表现层失败不能让后端任务失效或重复。帧率与空闲资源目标在实际模型/机器上冻结。

## V0.9 Beta 与 V1.0

Beta 冻结主要功能，完成安装包、配置向导、模型缓存管理、数据库备份/导出/迁移、诊断日志和受控升级。初版可用手动更新，不把远程自动更新服务作为发布前提；凭据和用户数据不进入安装包。

采用干净 Windows 测试、至少覆盖上一交付版升级、失败迁移恢复、断网启动、失效 API/低磁盘空间、休眠/重启与长时间运行。建议至少 72 小时运行作为首轮 soak 测试，再用实际资源曲线判断泄漏；时长不是可靠性证明本身。

V1.0 作为稳定门槛：原生安装/升级/恢复可用，核心回归与安全边界通过，没有数据丢失、权限绕过、重复高风险副作用或资源泄漏等阻断缺陷。此阶段不再同时引入新人格算法、新渲染路线和新自主权限体系；语音、云同步、不可信插件生态可后续扩展。

## 开发组织

环境按阶段准备：V0.3 为 CPU embedding 与既有 SQLite；V0.4 继续以标准库/SQLite 完成状态与队列；V0.5 才增加 PySide6/通知适配；V0.6 先核验 Windows 受限令牌/IPC/资源控制所需 native 接口；V0.7 再准备 Cubism SDK/Core、绑定、模型和图形环境；Beta 时选择打包/安装工具。原有 C++ 工具已安装不代表未来 SDK 或隔离实现已经构建通过。

每阶段仍由主 Agent 冻结接口、分配不重叠文件、审查合并；子 Agent 返回文件/设计/接口/测试/问题。安全、迁移和可观测性贯穿所有阶段。环境/依赖按阶段补充，先固定可运行基线，再扩大能力；不预估未经实测的日历交付日期。
